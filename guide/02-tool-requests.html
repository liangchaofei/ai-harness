02 让模型提出工具请求 ​

上一章把代码直接放进消息，模型可以据此分析。现在把任务换成：“请审查src/cart.ts，先取得源码，再根据内容指出问题。” 输入里只有路径，没有源码。模型需要表达“我想读取这个文件”，程序才能知道下一步需要什么动作。

本篇实现：应用提供工具说明 → 模型生成结构化请求 → 模型包转换响应 → 应用展示待执行动作。 完成后，程序能区分普通文本和工具请求，并保留每项请求的 ID、名称和参数。它属于第一阶段的动作请求部分；下一篇才真正执行工具并反馈结果，再往后接成自动循环。

这里的src/cart.ts只是任务中的路径字符串，不需要现在创建文件。模型不会因为收到路径就获得磁盘访问能力。

本篇技术方案 ​

实施前，先走完一次具体过程 ​

  1. 应用只给任务路径，同时声明可请求的动作。 任务说要审查 src/cart.ts，工具说明说可以请求 read_file，参数需要一个 path。说明里没有实际读取函数，也没有源码。
  2. 模型包把任务和工具说明发送给服务。 模型根据可见信息返回文字，或者生成工具请求。是否请求、请求哪个名称及参数，由这次模型输出决定，不是应用预先替它填写。
  3. 模型包把服务的动作数据转换成项目数据。
    • 3.1 保留每项请求。 从服务响应取出请求 ID、工具名和参数文本，按顺序组成项目的请求数组；多项请求不会只剩第一项。
    • 3.2 组合成完整模型消息。 将文字、请求数组和停止原因一起返回。动作参数此时仍是 JSON 字符串，不是已经通过校验的本地函数参数。
  4. 应用接住一次返回，区分文本与待执行动作。 普通回答展示文字；工具请求展示 ID、名称与参数；截断则不当作完整动作。此时不读磁盘、不保存工具结果，也不再次调用模型，实际执行接在 03 篇。

因此本篇观察的是“模型提出了什么动作”，不是“文件工具执行出了什么结果”。

实现架构图 ​

从“想读文件”到可识别的请求 ​

如果模型只回复“我需要看一下文件”，程序仍只拿到一段文字。工具调用协议让模型把动作放进专门的字段：哪个工具、给什么参数、用哪个 ID 标识这一次请求。这里说的“工具请求”就是这份动作数据，不是已经执行的函数。

应用先写一份工具说明：名称是read_file，参数中需要字符串path。模型服务收到任务和说明后，可以生成“请求读取这个路径”的动作数据；本地程序再接收并解释它。说明由应用提供，请求由模型生成，是否执行由本地程序决定。

下面用一份教学样本贯穿本章。ID 统一简写为call_01，文本和参数只是可能的值；原始结构按本篇适配代码展示，不是真实抓包记录，也不是需要写入程序的固定响应。

json
{
  "choices": [{
    "finish_reason": "tool_calls",
    "message": {
      "role": "assistant",
      "content": "我先读取该文件的内容。",
      "tool_calls": [{
        "id": "call_01",
        "type": "function",
        "function": {
          "name": "read_file",
          "arguments": "{\"path\":\"src/cart.ts\"}"
        }
      }]
    }
  }]
}

这条响应同时包含文字和动作：content是模型生成的说明，tool_calls是模型提出的请求。function.arguments是字符串，字符串内部才是 JSON 对象的写法；收到它时还没有解析参数，更没有读取文件。模型包把服务字段转换成项目结果：

json
{
  "role": "assistant",
  "content": "我先读取该文件的内容。",
  "stopReason": "toolUse",
  "toolCalls": [{
    "id": "call_01",
    "name": "read_file",
    "arguments": "{\"path\":\"src/cart.ts\"}"
  }]
}

这两份 JSON 是同一次调用在转换前后的形状。服务返回的字段名是tool_calls和finish_reason；项目选择使用toolCalls和stopReason，并把tool_calls停止原因映射为toolUse。字段名的变化发生在本地转换函数，文本、请求 ID、工具名和参数值都来自服务响应。

模型也可能不附带文字，返回content:null；适配会把它转为空字符串，仍保留动作请求。ID 用于以后把执行结果对应到原请求，它不是文件名或整个会话的 ID。无论附带哪种文字，本篇都停在请求阶段。

DeepSeek 的消息接口分别定义了输入tools、输出tool_calls及参数文本，并提醒执行前校验参数。本篇读取这些字段，暂不解析和执行参数。即使参数看起来符合说明，也不能据此认为动作已获授权。

第一步：区分工具说明和工具请求 ​

先辨认输入和输出：ToolDefinition是应用创建的“可请求什么”，ToolCall是模型响应转换出的“这次请求什么”。同一个read_file说明可以对应不同路径、多次请求，它们各自有 ID。

01 已经创建packages/model/src/types/目录，其中有messages.ts、context.ts和options.ts。本篇不移动这些文件，只做下面三项改动：

  1. 新建types/tools.ts：定义ToolDefinition和ToolCall，分别表示应用提供的工具说明和模型返回的动作请求。
  2. 完整替换已有的types/messages.ts：保留Message；为AssistantMessage.stopReason增加toolUse，并增加toolCalls数组。
  3. 完整替换已有的types/context.ts：保留systemPrompt/messages，增加可选的tools字段。

以上路径都位于packages/model/src/下，下面各处会再次给出完整路径和代码。types/options.ts中的CompleteOptions保持 01 的内容，本篇不修改。

先新建packages/model/src/types/tools.ts，写入完整代码：

这份类型区分发送与返回的两类数据：应用创建 ToolDefinition 说明工具用途和参数，模型包发送给服务；服务响应转换为 ToolCall，应用接住后观察模型请求的名称、ID 与参数。声明不会创建读取函数或执行动作。

ts
// 【新增文件】工具说明与工具请求契约。

/** 应用创建并交给模型包的工具说明，不携带执行能力。 */
export interface ToolDefinition {
  /** 模型请求时使用的工具名称。 */
  name: string;

  /** 说明什么时候使用、能取得什么信息。 */
  description: string;

  /** 用 JSON Schema 描述参数；这里的类型不验证 schema 或实际参数。 */
  parameters: Record<string, unknown>;
}

/** 适配层从模型响应转换的单项动作请求，留给本地程序处理。 */
export interface ToolCall {
  /** 服务返回的请求 ID；后续结果要关联它，本篇检查同一列表内不重复。 */
  id: string;

  /** 模型选择的工具名称，收到名称不表示已找到或授权执行。 */
  name: string;

  /** 模型生成的原始 JSON 文本；尚未解析或通过工具参数校验。 */
  arguments: string;
}

ToolDefinition.parameters保存参数的 JSON Schema。JSON Schema 是描述 JSON 数据形状的规则，本篇只用到对象、字段类型、必填字段和额外字段限制。它会作为模型输入，帮助模型生成参数；这个接口里的Record<string, unknown>仅允许保存规则对象，没有替程序验证规则或参数。

这两个接口只是本地类型契约。真正创建工具说明值的是后面的reviewTools数组；实际请求的值由服务生成，再由decodeToolCalls创建符合ToolCall形状的本地对象。写下interface ToolCall不会生成 ID、选择工具或发出请求。

ToolCall.arguments保留服务返回的原始字符串。例如'{"path":"src/cart.ts"}'仍是文本，不是已经交给读取函数的对象。下一篇会在执行前解析、核对字段、查找工具及限制工作范围。参数本身是坏 JSON 时，本篇也不会悄悄改成空对象或假装执行成功。

这份消息契约让一次模型返回可以同时携带文字和全部工具请求。响应转换函数创建 AssistantMessage，应用根据停止原因决定展示文本还是待执行动作；类型不会替应用保存这条响应。

ts
// 模型输入与返回消息。
import type { ToolCall } from './tools';

/**
 * 上下文中的一条文本消息。
 * 应用组织输入时创建，模型包读取它并转换为服务消息。
 */
export interface Message {
  /** user 表示用户侧输入，assistant 表示已有模型回答；本篇输入只有 user 消息。 */
  role: 'user' | 'assistant';

  /** 该角色提供的文本，例如本次审查要求与待审查代码。 */
  content: string;
}

// 【修改】返回消息增加工具请求列表与toolUse停止原因。
/**
 * 模型包检查并转换服务响应后返回的消息，可包含文字与工具请求。
 * 应用接收它，再决定是否展示；取得消息不等于任务完成。
 */
export interface AssistantMessage {
  /** 固定为 assistant，标明这条生成结果来自模型。 */
  role: 'assistant';

  /** 本次生成的文本，可能为空或被截断，由应用决定如何处理。 */
  content: string;

  /** stop 正常停止，length 达到生成上限，toolUse 请求工具；均不证明任务完成。 */
  stopReason: 'stop' | 'length' | 'toolUse';

  /** 全部工具请求，保持返回顺序；纯文本结果为空数组。 */
  toolCalls: readonly ToolCall[];
}

纯文本结果的toolCalls为[]，工具响应则包含一项或多项。toolUse只表示模型提出动作；length表示输出被截断，即使已有部分请求，也不能当完整动作接受。收到文本和收到动作，是两种需要分别处理的结果。

Message本章仍表示输入中的文本对话；它还不能保存和发送带请求的 assistant 历史。本篇只有一次调用，下一篇反馈结果时会一起扩展输入消息契约，不能现在把AssistantMessage直接追加后又丢掉请求字段。

import type { ToolDefinition } from './tools';

/**
 * 应用交给模型包的本次输入：总体要求与对话消息。

应用持有tools列表，模型包读取后转换为服务格式。没有提供列表时，仍能像 01 那样发起纯文本调用。列表中没有本地执行函数；把 JavaScript 函数写进消息也不会让远程服务执行本机代码。

第二步：转换服务返回的动作数据 ​

原来的decodeMessage只认识文本。现在它需要读取动作列表、保存请求身份，并区分“正常文本”“请求工具”“截断”。先实现列表转换，再接回整条消息。

新建packages/model/src/providers/deepseek-response.ts，先写入导入：

ts
// 【新增文件】从DeepSeek响应中取得文本和工具请求，不执行任何工具。
import type { AssistantMessage } from '../types/messages';
import type { ToolCall } from '../types/tools';
import { isRecord } from '../validation';

把每项服务请求转换为 ToolCall ​

在导入之后追加完整的decodeToolCalls函数。输入是服务的message.tool_calls，输出是项目的请求数组，供下一个函数使用：

ts
/** 保留每项请求的身份与原始参数，只检查本篇支持的协议形状。 */
function decodeToolCalls(value: unknown): ToolCall[] {
  if (value === undefined) return [];
  if (!Array.isArray(value)) throw new Error('tool_calls必须是数组。');

  const ids = new Set<string>();
  return value.map((item): ToolCall => {
    if (!isRecord(item) || item.type !== 'function' ||
        typeof item.id !== 'string' || !item.id.trim() || !isRecord(item.function)) {
      throw new Error('工具请求缺少可识别的类型、ID或function对象。');
    }
    const fn = item.function;
    if (typeof fn.name !== 'string' || !fn.name.trim() || typeof fn.arguments !== 'string') {
      throw new Error('工具请求缺少名称或参数文本。');
    }
    if (ids.has(item.id)) throw new Error('同一消息中的工具请求ID重复。');
    ids.add(item.id);

    // 此处保留参数文本，解析、工具查找与执行前校验留给执行层。
    return { id: item.id, name: fn.name, arguments: fn.arguments };
  });
}

对开头的样本，调用方会把message.tool_calls这一个数组传进value，不是把整个 HTTP 响应传进来。map处理第一项时，item.id是call_01，fn接住item.function，其中的名称是read_file，参数仍是'{"path":"src/cart.ts"}'。

回调里的return { id: item.id, name: fn.name, arguments: fn.arguments }创建一项本地请求对象，把服务的嵌套字段放到同一层。map收集各次回调返回的对象，外面的return value.map(...)再把整个数组交回decodeToolCalls的调用方。如果服务给了两项，就生成并返回两项，顺序不变；这两个 return 都没有调用文件读取函数。

ids是本次函数调用里的集合，用来发现同一消息中重复的请求 ID。重复时无法可靠对应结果，所以直接抛错。这不是跨轮去重机制，下一次调用会创建新集合。

没有tool_calls字段时返回空数组。字段存在却不是数组、缺少非空 ID、类型不是function、缺工具名或参数不是字符串时，抛错而不制造请求。这里检查的是协议形状；名称是否已注册、参数是否有效及是否允许读取，都还没有检查。

把文字、动作和停止原因组合为消息 ​

在同一文件末尾追加完整decodeMessage：

这段 decodeMessage 负责把一次服务响应组合成完整项目消息。它接收解析后的响应，检查停止原因、取出文本，再调用上面的请求转换函数取得 toolCalls；返回值交给 complete，再由应用接住。本次仍没有本地工具执行。

ts
/** complete调用它转换响应，返回的请求仍是待处理动作。 */
export function decodeMessage(value: unknown): AssistantMessage {
  if (!isRecord(value) || !Array.isArray(value.choices)) {
    throw new Error('模型响应缺少choices数组。');
  }
  const choice: unknown = value.choices[0];
  if (!isRecord(choice)) throw new Error('模型响应缺少可识别的choice。');
  const reason = choice.finish_reason;
  if (reason !== 'stop' && reason !== 'length' && reason !== 'tool_calls') {
    throw new Error('模型返回了本篇尚不支持的停止原因。');
  }
  const message = choice.message;
  if (!isRecord(message) || message.role !== 'assistant' ||
      (typeof message.content !== 'string' && message.content !== null)) {
    throw new Error('模型没有返回可识别的assistant消息。');
  }

  const toolCalls = decodeToolCalls(message.tool_calls);
  if (reason === 'tool_calls' && toolCalls.length === 0) {
    throw new Error('模型声明请求工具，却没有返回工具请求。');
  }
  if (reason === 'stop' && toolCalls.length > 0) {
    throw new Error('模型停止原因与工具请求不一致。');
  }

  // null表示没有附带文字；截断结果仍保留length，不升级为可用请求。
  return {
    role: 'assistant',
    content: message.content ?? '',
    stopReason: reason === 'tool_calls' ? 'toolUse' : reason,
    toolCalls,
  };
}

继续跟踪开头的完整响应：这里的value来自response.json()，是含choices的整个 JSON 对象。choice接住choices[0]，reason得到tool_calls，局部变量message接住服务中的 assistant 对象，它仍使用tool_calls字段。

const toolCalls = decodeToolCalls(message.tool_calls)把服务的动作数组交给前一个函数，返回的本地数组由toolCalls接住。随后return { ... }创建另一份对象：content保留“我先读取该文件的内容。”，stopReason变为toolUse，toolCalls使用刚得到的数组。这个对象才是项目的AssistantMessage；接口声明没有参与运行时转换。

服务原始位置本地结果位置本次值怎样得到
message.contentcontent复制服务文本；若为null则使用空字符串
choice.finish_reasonstopReasontool_calls在本地映射为toolUse
message.tool_calls[].idtoolCalls[].id保留服务给本次请求的 ID
message.tool_calls[].function.nametoolCalls[].name保留模型返回的名称；应用说明中提供了可用工具名
message.tool_calls[].function.argumentstoolCalls[].arguments保留参数字符串，不解析或改写路径

decodeMessage返回后，结果先交给调用它的complete，尚未直接跳到示例打印。本节的message是解码函数内的服务消息；第四步入口也有一个叫message的变量，接收的是转换后的项目消息，二者不在同一个作用域。

注意两种数组的区别：choices是不同生成结果的列表，本篇仍取第一条；这条结果里的tool_calls才是全部动作请求，不能只取第一项。

如果停止原因声称请求工具，却没有实际请求，函数会失败；若停止原因是stop却附带动作，也明确拒绝这种不一致的结果。length不会改成toolUse：只要协议字段还能识别，就保留已有内容和截断状态，随后由应用拒绝接受；如果截断连协议字段都破坏了，则在检查时抛错。

图中的成功出口仍只产生数据。没有任何一步调用read_file，也没有更新对话历史。

下面的 complete 仍替应用完成一次 HTTP 往返，但发送时多带工具说明，返回时可以取得工具请求。输入是 Context 与调用配置，返回统一的 AssistantMessage；应用后面用它区分普通回答、动作请求和截断。

ts
// 【修改】继续负责请求，将响应转换交给同目录的解码模块。
import type { AssistantMessage } from '../types/messages';
import type { Context } from '../types/context';
import type { CompleteOptions } from '../types/options';
import { decodeMessage } from './deepseek-response';

/** 只取得一次模型结果，不把停止生成等同于任务完成。 */
export async function complete(context: Context, options: CompleteOptions): Promise<AssistantMessage> {
  if (!options.apiKey.trim()) throw new Error('缺少DEEPSEEK_API_KEY。');
  if (!options.model.trim() || context.messages.length === 0) {
    throw new Error('模型名称与消息不能为空。');
  }
  const maxTokens = options.maxTokens ?? 256;
  if (!Number.isSafeInteger(maxTokens) || maxTokens < 1) throw new Error('maxTokens需为正安全整数。');

  // 把项目Context转换成DeepSeek的messages，不修改调用方持有的原数组。
  const messages = context.systemPrompt === undefined
    ? [...context.messages]
    : [{ role: 'system', content: context.systemPrompt }, ...context.messages];
  const response = await fetch('https://api.deepseek.com/chat/completions', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${options.apiKey}`,
    },
    body: JSON.stringify({
      model: options.model,
      messages,
      // 【新增】把应用工具说明转换为服务协议；未提供时不发送tools字段。
      tools: context.tools?.length ? context.tools.map((tool) => ({
        type: 'function',
        function: { name: tool.name, description: tool.description, parameters: tool.parameters },
      })) : undefined,
      stream: false,
      thinking: { type: 'disabled' },
      max_tokens: maxTokens,
    }),
    // 只限制本次HTTP等待；整次Agent的预算由后续Runtime负责。
    signal: AbortSignal.timeout(30_000),
  });

  // 不把服务错误正文或带凭据的请求对象直接打印到终端。
  if (!response.ok) throw new Error(`模型服务请求失败（HTTP ${response.status}）。`);
  const value: unknown = await response.json();
  return decodeMessage(value);
}

下面摘录已包含在上方完整文件中，仅用于对照，不要重复追加：

ts
      tools: context.tools?.length ? context.tools.map((tool) => ({
        type: 'function',
        function: { name: tool.name, description: tool.description, parameters: tool.parameters },
      })) : undefined,

context.tools由应用传入。每份说明转换成{type:'function', function:{name, description, parameters}}，再与model/messages一起序列化。没有工具说明时，tools的值为undefined，JSON.stringify不把这个字段写进正文。

这次请求中的messages包含总体要求和一条路径任务，tools包含工具说明，两者是请求正文的不同字段。JSON.stringify把它们序列化后，fetch才发送 HTTP 请求。没有函数实现或文件内容跟着说明进入服务。

await fetch(...)先让response接住 HTTP 响应对象，它还不是模型消息。接下来这一段已经包含在上面的完整实现中，只用于对照，不重复追加：

ts
  if (!response.ok) throw new Error(`模型服务请求失败（HTTP ${response.status}）。`);
  const value: unknown = await response.json();
  return decodeMessage(value);

HTTP 状态成功后，await response.json()读取、解析正文，完整原始 JSON 由value接住。decodeMessage(value)进行第二步的转换，返回项目对象；return decodeMessage(value)再把该结果作为complete的成功结果交给外部调用方。不是只打印转换结果，也不是由 DeepSeek 服务直接返回我们定义的stopReason/toolCalls。

如果 HTTP、JSON 解析或解码检查失败，就不会得到这个成功结果，入口的await会转入catch。成功路径仍没有修改context.messages；把结果返回和把结果写入历史是不同动作。

本篇继续使用非流式、非思考模式，不设置强制工具选择。是否提出动作仍取决于实际模型输出；提供工具说明不保证每次都会调用，也不保证生成的名称和参数正确。30 秒仍只约束这次 HTTP 等待，输出上限仍由调用方传入。

// 【新增文件】从DeepSeek响应中取得文本和工具请求，不执行任何工具。
import type { AssistantMessage } from '../types/messages';
import type { ToolCall } from '../types/tools';
import { isRecord } from '../validation';

/** 保留每项请求的身份与原始参数，只检查本篇支持的协议形状。 */
function decodeToolCalls(value: unknown): ToolCall[] {
  if (value === undefined) return [];
  if (!Array.isArray(value)) throw new Error('tool_calls必须是数组。');

  const ids = new Set<string>();
  return value.map((item): ToolCall => {
    if (!isRecord(item) || item.type !== 'function' ||
        typeof item.id !== 'string' || !item.id.trim() || !isRecord(item.function)) {
      throw new Error('工具请求缺少可识别的类型、ID或function对象。');
    }
    const fn = item.function;
    if (typeof fn.name !== 'string' || !fn.name.trim() || typeof fn.arguments !== 'string') {
      throw new Error('工具请求缺少名称或参数文本。');
    }
    if (ids.has(item.id)) throw new Error('同一消息中的工具请求ID重复。');
    ids.add(item.id);

    // 此处保留参数文本，解析、工具查找与执行前校验留给执行层。
    return { id: item.id, name: fn.name, arguments: fn.arguments };
  });
}

/** complete调用它转换响应，返回的请求仍是待处理动作。 */
export function decodeMessage(value: unknown): AssistantMessage {
  if (!isRecord(value) || !Array.isArray(value.choices)) {
    throw new Error('模型响应缺少choices数组。');
  }
  const choice: unknown = value.choices[0];
  if (!isRecord(choice)) throw new Error('模型响应缺少可识别的choice。');
  const reason = choice.finish_reason;
  if (reason !== 'stop' && reason !== 'length' && reason !== 'tool_calls') {
    throw new Error('模型返回了本篇尚不支持的停止原因。');
  }
  const message = choice.message;
  if (!isRecord(message) || message.role !== 'assistant' ||
      (typeof message.content !== 'string' && message.content !== null)) {
    throw new Error('模型没有返回可识别的assistant消息。');
  }

  const toolCalls = decodeToolCalls(message.tool_calls);
  if (reason === 'tool_calls' && toolCalls.length === 0) {
    throw new Error('模型声明请求工具，却没有返回工具请求。');
  }
  if (reason === 'stop' && toolCalls.length > 0) {
    throw new Error('模型停止原因与工具请求不一致。');
  }

  // null表示没有附带文字；截断结果仍保留length，不升级为可用请求。
  return {
    role: 'assistant',
    content: message.content ?? '',
    stopReason: reason === 'tool_calls' ? 'toolUse' : reason,
    toolCalls,
  };
}

// 【修改】继续负责请求，将响应转换交给同目录的解码模块。
import type { AssistantMessage } from '../types/messages';
import type { Context } from '../types/context';
import type { CompleteOptions } from '../types/options';
import { decodeMessage } from './deepseek-response';

/** 只取得一次模型结果，不把停止生成等同于任务完成。 */
export async function complete(context: Context, options: CompleteOptions): Promise<AssistantMessage> {
  if (!options.apiKey.trim()) throw new Error('缺少DEEPSEEK_API_KEY。');
  if (!options.model.trim() || context.messages.length === 0) {
    throw new Error('模型名称与消息不能为空。');
  }
  const maxTokens = options.maxTokens ?? 256;
  if (!Number.isSafeInteger(maxTokens) || maxTokens < 1) throw new Error('maxTokens需为正安全整数。');

  // 把项目Context转换成DeepSeek的messages，不修改调用方持有的原数组。
  const messages = context.systemPrompt === undefined
    ? [...context.messages]
    : [{ role: 'system', content: context.systemPrompt }, ...context.messages];
  const response = await fetch('https://api.deepseek.com/chat/completions', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${options.apiKey}`,
    },
    body: JSON.stringify({
      model: options.model,
      messages,
      // 【新增】把应用工具说明转换为服务协议；未提供时不发送tools字段。
      tools: context.tools?.length ? context.tools.map((tool) => ({
        type: 'function',
        function: { name: tool.name, description: tool.description, parameters: tool.parameters },
      })) : undefined,
      stream: false,
      thinking: { type: 'disabled' },
      max_tokens: maxTokens,
    }),
    // 只限制本次HTTP等待；整次Agent的预算由后续Runtime负责。
    signal: AbortSignal.timeout(30_000),
  });

  // 不把服务错误正文或带凭据的请求对象直接打印到终端。
  if (!response.ok) throw new Error(`模型服务请求失败（HTTP ${response.status}）。`);
  const value: unknown = await response.json();
  return decodeMessage(value);
}

// 【修改】应用提供工具说明，区分待执行请求与可以显示的文本。
import { complete, type Context } from '@ai-harness/model';
import { reviewTools } from './tools';

const model = process.env.DEEPSEEK_MODEL?.trim() || 'deepseek-flash';
const prompt = process.argv[2] ?? '请审查src/cart.ts，先取得源码，再根据内容指出问题。';
const context: Context = {
  systemPrompt: '你是代码审查助手。缺少源码时请求read_file，不编造文件内容或执行结果。',
  messages: [{ role: 'user', content: prompt }],
  // 【新增】只发送动作说明，没有执行函数或文件内容。
  tools: reviewTools,
};

try {
  console.log('请求模型（model）：', model);
  console.log('应用上下文（context）：', JSON.stringify(context, null, 2));
  const message = await complete(context, {
    apiKey: process.env.DEEPSEEK_API_KEY?.trim() ?? '',
    model,
    maxTokens: 256,
  });
  console.log('模型消息（message）：', JSON.stringify(message));

  // 【修改】先拦截截断，避免把不完整的工具参数当作可用请求。
  if (message.stopReason === 'length') throw new Error('输出已截断，本次不接受文本或工具请求。');
  if (message.stopReason === 'toolUse') {
    for (const call of message.toolCalls) {
      console.log('待执行工具请求：', JSON.stringify(call));
    }
    console.log('本篇停在请求阶段，工具执行次数：0；尚未取得源码。');
  } else {
    if (!message.content.trim()) throw new Error('没有可显示的文本，本次不交付回答。');
    console.log('模型文本（text）：', message.content);
  }
} catch (error) {
  console.error('本次调用未交付：', error instanceof Error ? error.message : String(error));
  process.exitCode = 1;
}

//模型包内部的数据判断，不依赖具体提供商或Agent状态。

/**
 * 判断未知值是否为非空、非数组的对象，供响应检查读取字段。
 * 返回true只收窄对象形状，不保证字段存在或类型正确。
 */
export function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null && !Array.isArray(value);
}
