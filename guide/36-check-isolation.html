第 36 篇：限制验收进程写文件和使用网络 ​

Coding Agent 修复发票计算后，会执行一份可信验收脚本。脚本还会导入工作副本里刚被修改的代码。即使模型只能请求 run_check({})，被导入的代码也会真的在 Node 进程里执行。这个进程能否写文件、打开网络监听，是另一层需要验证的权限。

本篇在 macOS 给验收子进程加上只读、离线策略。模型仍通过原工具编辑获准的计算文件。进入验收后，同一份修改可被读取和执行，此时写入和网络操作会受到系统约束。

如果已经检出了本篇代码，先运行 node --import tsx examples/check-isolation/main.ts compare。在带 sandbox-exec 的 macOS 上，观察两行结果里哪两项从 allowed 变成 EPERM。阅读时先跟技术方案，再看第一步的固定策略和最终参数数组。图解可以点击放大。

本篇技术方案 ​

同一次运行有两道不同的问题。第一道由应用决定模型提出的 run_check 是否获准。第二道由操作系统决定验收进程启动后可以访问哪些资源。用同一份脚本做对照，才能判断第二道限制究竟拦住了什么。

实施前，先走完一次具体过程 ​

  1. 操作者选择 invoice-isolated.json。CLI 解析显式的 checkIsolation，然后准备发票工作副本、精确的可写路径和可信验收脚本。
  2. CLI 装配验收时，把固定 Node 命令交给 macOS 的 sandbox-exec 启动，并传入应用定义的策略。模型收到的工具说明仍只允许提交空对象。
  3. 模型用 replace_text 调整重复折扣，再请求 run_check({})。运行器启动验收。脚本能够读取并导入计算文件，五个业务用例照常运行。若进程尝试写文件或监听端口，对照实验能观察到系统拒绝。
  4. Runtime 保存工具反馈，CLI 判断实际验收是否匹配当前的修改。若这次任务经检查点稍后恢复，CLI 会先校验任务指纹，再以相同执行策略打开副本。

核心代码在 apps/coding-cli/src/session/check-command.ts 的 createCheckCommand。 一个无配置任务得到原本的 Node 命令，显式选择隔离的任务得到带固定策略的启动命令。openTaskWorkspace 是新运行与已保存任务恢复的共用入口。

这是针对可信本地练习材料的 macOS 实验。系统策略允许一般文件读取，代码仍能访问当前用户有权读取的宿主机内容。权限也只作用于验收进程，模型调用、MCP 服务和 CLI 主进程都有自己的边界。sandbox-exec 已被 macOS 的本机手册标记为弃用。本章用它直接观察系统拒绝，生产部署仍需为文件读取、进程树与资源消耗分别设计和验证。 Apple 的 macOS 权限说明

Pi 的工具可以在应用组装时注入具体执行操作，例如 bash.ts 的 BashOperations 和 options.operations。这里借鉴保持工具接口稳定、由应用选择后端的做法，具体系统限制来自 macOS。 Pi 固定版本的执行后端

第一步：把固定策略变成验收命令 ​

新建 apps/coding-cli/src/session/check-command.ts。它接收已校验的任务配置与副本路径，返回现有 coding-tools 接口要求的 CheckCommand。具体启动、限时与有界输出仍由原验收运行器处理。

ts
// 【新增文件】把可信任务的执行策略翻译成固定验收命令。
import type { CheckCommand } from '@ai-harness/coding-tools';
import type { TaskConfig } from '../types/task';

const MACOS_PROFILE = [
  '(version 1)',
  '(allow default)',
  '(deny file-write*)',
  '(deny network*)',
].join('\n');

/** 新任务与检查点恢复均使用相同策略，模型仍只提交 run_check({})。 */
export function createCheckCommand(task: TaskConfig, root: string): CheckCommand {
  const nodeArgs = ['--import', import.meta.resolve('tsx'), task.checkScript, root];

  if (task.checkIsolation === undefined) {
    return { executable: process.execPath, args: nodeArgs };
  }

  if (process.platform !== 'darwin') {
    throw new Error('macos-offline-readonly 只支持带 sandbox-exec 的 macOS。');
  }

  return {
    executable: '/usr/bin/sandbox-exec',
    args: ['-p', MACOS_PROFILE, process.execPath, ...nodeArgs],
  };
}

在同文件顶部，MACOS_PROFILE 定义了这章要观察的系统策略。

ts
const MACOS_PROFILE = [
  '(version 1)',
  '(allow default)',
  '(deny file-write*)',
  '(deny network*)',
].join('\n');

allow default 保留大多数默认权限，让 Node 还能读取脚本、源码和依赖。两个 deny 分别禁止文件写入与网络操作。运行探测脚本时，前者会拦住在副本中新建临时标记文件，后者会拦住监听本机回环地址。

接着看同文件 createCheckCommand 的两条返回路径。

ts
export function createCheckCommand(task: TaskConfig, root: string): CheckCommand {

    args: ['-p', MACOS_PROFILE, process.execPath, ...nodeArgs],

例如任务脚本是 check-invoice.mjs，root 就是 CLI 刚创建的副本。普通配置将 nodeArgs 原样交给当前 Node。启用隔离时，-p 后面是完整策略，后面才是同一个 Node 和参数数组。底层启动函数仍用 shell: false，所以两层参数在不同位置解析，配置也没有提供任意命令的入口。

如果系统不是 macOS，配置了该策略的任务会在准备时失败。在 macOS 缺少启动程序或策略应用失败时，验收会失败，程序不会自动改走直接执行。

// 把操作者的可信任务配置转换为准备副本所需数据。
import { readFile, realpath, stat } from 'node:fs/promises';
import { dirname, isAbsolute, relative, resolve } from 'node:path';
import { loadTaskMemory } from '../context/task-memory';
import type { MemoryCapture, TaskConfig } from '../types/task';

function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null && !Array.isArray(value);
}

/** CLI路径按cwd解析；配置内source/checkScript按配置文件目录解析。 */
export async function loadTask(taskFile: string, signal?: AbortSignal): Promise<TaskConfig> {
  signal?.throwIfAborted();
  const configPath = await realpath(resolve(taskFile));
  const info = await stat(configPath);
  if (!info.isFile() || info.size > 16 * 1024) throw new Error('任务配置应为小型JSON文件。');
  const value: unknown = JSON.parse(await readFile(configPath, { encoding: 'utf8', signal }));
  const keys = ['source', 'prompt', 'writablePaths', 'checkScript'];
  // 【修改】可选项只允许指定的字段，仍保持四个必填字段。
  const optionalKeys = ['memory', 'extension', 'checkIsolation'];
  if (
    !isRecord(value) ||
    keys.some((key) => !Object.hasOwn(value, key)) ||
    Object.keys(value).some((key) => !keys.includes(key) && !optionalKeys.includes(key))
  ) {
    throw new Error('任务字段不匹配。');
  }
  const { source, prompt, writablePaths, checkScript, extension, checkIsolation } = value;
  // 【新增】任务只选择已知策略名，策略正文由 CLI 持有。
  if (checkIsolation !== undefined && checkIsolation !== 'macos-offline-readonly') {
    throw new Error('任务指定了未知验收隔离策略。');
  }
  // 只接受两个已知扩展名。
  if (extension !== undefined && extension !== 'source-pair' && extension !== 'invoice-policy-mcp') {
    throw new Error('任务指定了未知扩展。');
  }
  if (typeof source !== 'string' || !source.trim() || typeof checkScript !== 'string' || !checkScript.trim()
    || typeof prompt !== 'string' || !prompt.trim() || prompt.length > 4000
    || !Array.isArray(writablePaths) || writablePaths.length < 1 || writablePaths.length > 16
    || writablePaths.some((path) => typeof path !== 'string' || !path.trim())
    || new Set(writablePaths).size !== writablePaths.length) throw new Error('任务字段无效。');

  const base = dirname(configPath);
  const sourcePath = await realpath(resolve(base, source));
  const scriptPath = await realpath(resolve(base, checkScript));
  if (!(await stat(sourcePath)).isDirectory() || !(await stat(scriptPath)).isFile()
    || !scriptPath.endsWith('.mjs')) throw new Error('材料或验收文件无效。');
  const scriptRelative = relative(sourcePath, scriptPath);
  // 验收在来源之外，避免把它复制到模型处理的材料中；这不是OS隔离。
  if (scriptRelative === '' || (!isAbsolute(scriptRelative)
    && scriptRelative !== '..' && !scriptRelative.startsWith('../'))) throw new Error('验收应在材料目录之外。');
  // 只在加载任务时读取；模型调用期间复用选中的一条记录。
  const memory = await loadTaskMemory(value.memory, base, signal);
  // 读取笔记和授权写入是两项独立的配置决定。
  let memoryCapture: MemoryCapture | undefined;
  if (isRecord(value.memory) && Object.hasOwn(value.memory, 'captureCase')) {
    const { file, topic, captureCase } = value.memory;
    if (
      typeof file !== 'string' ||
      typeof topic !== 'string' ||
      typeof captureCase !== 'string' ||
      captureCase.length === 0 ||
      captureCase.length > 64
    ) {
      throw new Error('记忆写入需要指定可核对的验收用例。');
    }
    memoryCapture = {
      path: await realpath(resolve(base, file)),
      topic: topic.trim(),
      caseInput: captureCase,
    };
  }

  signal?.throwIfAborted();
  return {
    source: sourcePath,
    prompt: prompt.trim(),
    writablePaths: [...writablePaths],
    checkScript: scriptPath,
    ...(checkIsolation ? { checkIsolation } : {}),
    ...(extension ? { extension } : {}),
    ...(memory ? { memory } : {}),
    ...(memoryCapture ? { memoryCapture } : {}),
  };
}

// 从可信材料建立一次独立代码任务，不依赖示例目录。
import { cp, mkdtemp, rm, writeFile } from 'node:fs/promises';
import { tmpdir } from 'node:os';
import { join } from 'node:path';
import { createCodeTaskSession } from '@ai-harness/coding-tools';
import { createPlanSession } from '@ai-harness/runtime';
import type { TaskConfig } from '../types/task';
import type { CliSession } from '../types/session';
import { createCheckCommand } from './check-command';

/** main传入解析后配置；准备失败清理半成品，成功后由main保留副本。 */
export async function prepareSession(
  task: TaskConfig,
  planning: boolean,
  signal?: AbortSignal,
): Promise<CliSession> {
  signal?.throwIfAborted();
  const root = await mkdtemp(join(tmpdir(), 'ai-harness-cli-'));
  try {
    await cp(task.source, root, {
      recursive: true,
      dereference: false,
    });
    // 本篇只接独立、无依赖的小型ESM教学材料，不覆盖来源中的包配置。
    await writeFile(join(root, 'package.json'), '{"type":"module"}\n', { flag: 'wx' });
    signal?.throwIfAborted();
    const codeTask = await openTaskWorkspace(task, root, signal)
    return {
      root,
      codeTask,
      plan: planning ? createPlanSession() : undefined,
    };
  } catch (error) {
    await rm(root, {
      recursive: true,
      force: true,
    });
    throw error;
  }
}
/** 从指定副本重新建立工具会话，供新任务与检查点恢复共用。 */
export function openTaskWorkspace(task: TaskConfig, root: string, signal?: AbortSignal) {
  return createCodeTaskSession(
    {
      root,
      extensions: ['.ts', '.json', '.md'],
      writablePaths: task.writablePaths,
      // 【修改】为新任务与恢复任务应用同一个验收执行策略。
      check: createCheckCommand(task, root),
    },
    signal,
  );
}

ts
//保存并接续一个明确等待验收的工作副本。
import { createHash } from 'node:crypto';
import { readFile, realpath, stat, writeFile } from 'node:fs/promises';
import { isAbsolute, resolve } from 'node:path';
import type { RunResult } from '@ai-harness/runtime';
import type { CliSession } from '../types/session';
import type { CheckDecision, TaskConfig } from '../types/task';
import { readCheckApproval, saveCheckApproval } from './check-approval';
import { claimCheck, inspectCheckReceipt, saveCheckReceipt } from './check-receipt';
import { openTaskWorkspace } from './prepare';

/** 写入方创建，恢复方校验。记录一次待执行的验收及其适用内容。 */
interface PendingCheck {
  /** 检查点的磁盘格式版本。 */
  version: 1;
  /** 下一步固定为验收，恢复入口据此选择动作。 */
  next: 'check';
  /** 创建时确认的旧副本绝对路径。 */
  workspace: string;
  /** 写入检查点时，副本受跟踪文本范围的内容指纹。 */
  revision: string;
  /** 任务来源、可写路径、验收脚本位置、正文与显式执行策略的指纹。 */
  taskKey: string;
  /** 写入 true 才需要人工决定。旧检查点没有该字段。 */
  requiresApproval?: true;
}

function isPendingCheck(value: unknown): value is PendingCheck {
  if (typeof value !== 'object' || value === null) return false;
  const item = value as Record<string, unknown>;
  return item.version === 1 && item.next === 'check' &&
    typeof item.workspace === 'string' && isAbsolute(item.workspace) &&
    typeof item.revision === 'string' && /^[a-f0-9]{64}$/.test(item.revision) &&
    typeof item.taskKey === 'string' && /^[a-f0-9]{64}$/.test(item.taskKey) &&
    (item.requiresApproval === undefined || item.requiresApproval === true);
}

async function taskKey(task: TaskConfig, signal?: AbortSignal): Promise<string> {
  const script = await readFile(task.checkScript, { encoding: 'utf8', signal });
  return createHash('sha256').update(JSON.stringify([
    task.source,
    task.writablePaths,
    task.checkScript,
    script,
    // 【新增】只为启用隔离的新任务追加策略，旧检查点的摘要仍可用。
    ...(task.checkIsolation ? [task.checkIsolation] : []),
  ])).digest('hex');
}

/** 只在正常返回、已有允许改动且未请求验收时写下待验收检查点。 */
export async function savePendingCheck(
  path: string,
  task: TaskConfig,
  session: CliSession,
  result: RunResult,
  signal?: AbortSignal,
  requiresApproval = false,
): Promise<void> {
  const requestedCheck = result.messages.some((message) =>
    message.role === 'assistant' && message.toolCalls.some((call) => call.name === 'run_check'),
  );
  const review = await session.codeTask.inspect(signal);
  if (result.status !== 'answered' || requestedCheck || review.lastCheck ||
      review.changes.length === 0 ||
      review.changes.some((change) => !task.writablePaths.includes(change.path))) {
    throw new Error('只能保存已修改且尚未尝试验收的受控交接。');
  }

  const entry: PendingCheck = {
    version: 1,
    next: 'check',
    workspace: await realpath(session.root),
    revision: review.currentRevision,
    taskKey: await taskKey(task, signal),
    ...(requiresApproval ? { requiresApproval: true } : {}),
  };
  signal?.throwIfAborted();
  await writeFile(path, JSON.stringify(entry) + '\n', { flag: 'wx', mode: 0o600 });
}

async function openPendingCheck(path: string, task: TaskConfig, signal?: AbortSignal) {
  const checkpointPath = await realpath(resolve(path));
  const info = await stat(checkpointPath);
  if (!info.isFile() || info.size > 8 * 1024) {
    throw new Error('检查点文件无效或超限。');
  }
  const text = await readFile(checkpointPath, { encoding: 'utf8', signal });
  const entry: unknown = JSON.parse(text);
  if (Buffer.byteLength(text) > 8 * 1024 || !isPendingCheck(entry) ||
      entry.taskKey !== await taskKey(task, signal) ||
      await realpath(entry.workspace) !== entry.workspace) {
    throw new Error('检查点与当前任务不匹配。');
  }

  const session = await openTaskWorkspace(task, entry.workspace, signal);
  const before = await session.inspect(signal);
  if (before.currentRevision !== entry.revision) {
    throw new Error('副本内容与检查点不一致。');
  }
  const checkpointKey = createHash('sha256').update(text).digest('hex');
  return { checkpointPath, checkpointKey, entry, session };
}

/** 先核对任务和副本，再写入操作者对这一个待验收动作的决定。 */
export async function decidePendingCheck(
  path: string,
  task: TaskConfig,
  decision: CheckDecision,
  signal?: AbortSignal,
) {
  const { checkpointPath, checkpointKey, entry } = await openPendingCheck(path, task, signal);
  if (!entry.requiresApproval || (await inspectCheckReceipt(checkpointPath, checkpointKey)).status !== 'pending') {
    throw new Error('当前检查点没有可批准的待验收动作。');
  }
  await saveCheckApproval(checkpointPath, checkpointKey, decision, signal);
  return { workspace: entry.workspace, approval: decision === 'approve' ? 'approved' : 'denied' };
}

/** 操作者查看检查点的批准与执行证据。 */
export async function inspectPendingCheck(path: string, task: TaskConfig, signal?: AbortSignal) {
  const { checkpointPath, checkpointKey, entry } = await openPendingCheck(path, task, signal);
  const state = await inspectCheckReceipt(checkpointPath, checkpointKey);
  const approval = entry.requiresApproval
    ? await readCheckApproval(checkpointPath, checkpointKey, signal)
    : 'notRequired';
  return {
    workspace: entry.workspace,
    approval,
    status: state.status,
    ...(state.status === 'completed' ? { historicalPassed: state.receipt.passed } : {}),
  };
}

/** 先确认副本和任务，再占用检查点并执行一次原有验收。 */
export async function resumePendingCheck(path: string, task: TaskConfig, signal?: AbortSignal) {
  const { checkpointPath, checkpointKey, entry, session } = await openPendingCheck(path, task, signal);
  // 等待或拒绝时，在创建 .started 前退出。
  if (entry.requiresApproval) {
    const approval = await readCheckApproval(checkpointPath, checkpointKey, signal);
    if (approval !== 'approved') {
      return { workspace: entry.workspace, approval };
    }
  }
  const check = session.tools.find((tool) => tool.name === 'run_check');
  if (!check) throw new Error('当前任务缺少验收工具。');

  // 已有匹配回执时复用结果；已占用且无回执时由 claimCheck 拒绝继续。
  signal?.throwIfAborted();
  const receipt = await claimCheck(checkpointPath, checkpointKey);
  if (receipt) {
    return { workspace: entry.workspace, passed: receipt.passed, feedback: receipt.feedback, reused: true };
  }
  const feedback = await check.execute({}, signal);
  const after = await session.inspect(signal);
  const report: unknown = JSON.parse(after.lastCheck?.stdout ?? 'null');
  const passed = after.checkMatchesCurrent && after.currentRevision === entry.revision &&
    after.lastCheck?.status === 'passed' && after.lastCheck.exitCode === 0 &&
    typeof report === 'object' && report !== null && 'passed' in report && report.passed === true;
  // 先写回执，再向调用方返回结果。
  await saveCheckReceipt(checkpointPath, { checkpointKey, passed, feedback });
  return { workspace: entry.workspace, passed, feedback, reused: false };
}

repair 则由第一轮固定响应构造 replace_text，第二轮构造 run_check，第三轮停止。Runtime 完整执行这些请求，最后的 accepted 由原来的交付报告计算。CLI 会保留交付副本供审阅。
