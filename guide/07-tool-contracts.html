07 工具准入与可判断的失败 ​

本篇给 Agent 增加一项执行能力：模型提出动作后，Runtime 先统一检查参数；能处理的错误交回模型继续决定，无法确定的异常则停止并保留已完成事实。 重点是动作怎样被检查、执行和反馈，错误类型用来表达这些判断的结果。

继续使用代码审查任务，不增加新业务。模型请求读取 src/cart.ts，本地真正执行读取的仍是 read_file。变化发生在它们之间：Runtime 不再只解析 JSON 后就交给工具，而是先按照工具声明的参数规则检查数据，再决定能否调用工具。

这是第二阶段的第二个单元，建设的是 Agent 的执行机制：模型负责提出动作，Runtime 负责检查与组织执行，工具负责实际操作，结果再成为下一轮模型可见的信息。原来的发布调查和两种模型接入继续复用。

为什么已有参数检查，还要做这一篇 ​

03 的读取工具和 05 的查询工具已经各自检查参数，因此旧示例并非接受任意输入。但只靠每个工具自己写检查，接入一个新工具时，仍可能出现“发给模型的规则写了，本地执行前却漏查了”的缺口。

本篇把同一份参数规则接到执行入口：它既用于向模型说明怎样传参，也用于本地判断实际参数是否符合规则。这里的 schema 就是描述参数形状的数据，例如“必须有字符串 path，不能有额外字段”；仅仅写出这份数据不会自动产生检查。

要判断的事情本篇之前本篇之后
应用提供的工具是否重名、参数规则能否用于检查重名主要在执行批次时检查；规则尚未统一编译启动前统一准备，有问题就不请求模型
模型的参数是否符合工具声明各工具内部自行检查Runtime 先按 schema 检查，合格后才进入工具
出现已知失败或未知异常后怎样继续已有反馈和停止；未知批次异常前的结果未统一带回反馈与停止明确分开，停止时保留此前完成的结果

所以正常读取的答案可能没有变化，新增的是每个经 Runtime 执行的工具都要经过相同的检查步骤。原工具的文件清单、记录是否存在等检查仍然保留，因为参数形状正确不代表动作被允许。

本篇技术方案 ​

实施前，先走完一次具体过程 ​

继续使用原来的 read_file。它的工具说明要求 path 是字符串，且不能有额外字段；这份说明既发送给模型，也会成为本地检查的依据。

整篇实现先准备工具，再逐项决定能否执行，最后把结果交回循环：

  1. 启动时准备应用提供的工具清单。 检查名称与说明，复制本次使用的数据，再将每个工具的 schema 编译成校验函数。后面多轮复用这份准备结果，不在每轮重新编译。
  2. 模型提出请求后，执行器先检查批次身份。 核对工具请求的类型、名称字段和批内 ID，再按响应中列出的请求逐项处理；这不是把全部注册工具都执行一次。
  3. 每项请求经过两层门禁。
    • 3.1 Runtime 检查普通数据。 查工具名、解析参数 JSON，再按已编译的 schema 检查字段和类型。不通过就产生原请求 ID 对应的已知失败反馈，不进入工具 execute。
    • 3.2 工具检查具体动作。 数据形状通过后，读取工具还要检查路径清单、文件条件并真正读取。schema 不能替代这层许可与执行检查。
  4. 能解释的失败反馈给模型，未知异常停止。 已知错误成为 toolResult，Runtime 保存后允许下一轮修正；未知异常终止后续动作，同时保留本批已经完成的反馈。模型等待的故障也用明确类别报告，不混同工具参数错误。
  5. 应用观察为什么停止。 运行结果带阶段与受控失败标识，报告展示原因；即使最后 answered，仍要检查实际读取和结论。本地固定入口用坏参数复现门禁，真实模型不必先犯这个错误。

下面是一种可能轨迹，不是要求真实模型固定调用三次：

模型调用决定或结果Runtime 的动作
1请求 read_1 / read_file / {path:123}解析 JSON 后检查结构，拒绝进入 execute；保存 invalid_arguments 反馈
2看见反馈，提出 read_2 / read_file / {path:'src/cart.ts'}结构通过，再由原工具检查路径清单并实际读取；保存源码结果
3根据源码回答返回 answered，应用仍需核对读取证据与审查结论

两次工具请求的 ID 不同。第一项失败仍属于 read_1，第二项成功属于 read_2；不能为了看起来成功就把旧失败改写成新结果。

这里要区分两件事：schema 检查数据形状，工具检查这次动作是否允许、是否做得成。{path:'src/missing.ts'} 的形状正确，但路径不在允许清单中，原工具仍会拒绝。schema 通过不等于授权通过，更不等于操作系统隔离。

Pi 固定版本的 prepareToolCall会先查工具、调用参数验证，再进入执行路径。它的 validateToolArguments还包含类型转换和可选值处理。本篇借鉴“执行前统一验证、复用校验器”，采用 Ajv 验证已经使用的普通 JSON Schema，暂不自动把数值改成字符串或补上缺失字段。

第一步：为模型调用准备明确的停止原因 ​

先接好工具主线所需的一个停止出口：如果请求模型时连接失败，或响应无法转换为工具请求，就没有可执行动作；这种失败应返回应用，而不是生成一条假的工具结果再交给模型。本步给这些出口命名，后面的第二至五步再完成工具准备、请求检查、执行与反馈。

定义错误，而不是匹配错误字符串 ​

新建 packages/model/src/types/failures.ts：

ModelFailureKind 约定模型等待失败的稳定类别，供后面的错误对象和 Runtime 分支使用。它只是类别名称，不会通过错误文字自动识别连接、HTTP 或协议问题。

ts
// 【新增文件】模型包可识别的调用失败类别。
/** complete 创建错误时使用；Runtime 据此归类，不靠解析异常正文。 */
export type ModelFailureKind = 'configuration' | 'http' | 'transport' | 'protocol';

再新建 packages/model/src/errors/model-call-error.ts：

ModelCallError 将一项受控失败类别与允许展示的说明组合成错误对象。HTTP 层和模型入口在实际失败处创建它，Runtime 接住后生成运行失败信息；原始原因仅保留供本地检查。

ts
// 【新增文件】把可公开的失败分类与本地原始异常分开。
import type { ModelFailureKind } from '../types/failures';

/** 模型包创建，Runtime 读取 kind；cause 只供本地调试，不进入消息。 */
export class ModelCallError extends Error {
  constructor(
    readonly kind: ModelFailureKind,
    message: string,
    options?: ErrorOptions,
    readonly httpStatus?: number,
  ) {
    super(message, options);
    this.name = 'ModelCallError';
  }
}

模型包抛出的 ModelCallError 有四种 kind：调用配置不符、服务返回非成功 HTTP、连接或响应体等待失败、消息格式不支持。httpStatus 只在 HTTP 失败时使用。cause 保存原始异常，供本地断点查看，不进入模型消息或默认日志。

类型定义不会自动识别错误；下面在实际动作发生处创建这个错误对象。可信应用若自己创建它，也应只把允许展示的说明放进 message。

共用 HTTP 等待 ​

新建 packages/model/src/providers/shared/request-json.ts。它替两家请求函数完成同一段工作：等待 HTTP，检查状态，读取 JSON。输入是已经编码好的请求，输出仍是未知数据，之后由对应服务解码器判断消息字段。

ts
// 【新增文件】两家适配器共用 HTTP 等待和 JSON 读取，不处理消息协议。
import { ModelCallError } from '../../errors/model-call-error';

/** 适配器传入已编码请求；返回未知 JSON，再由各自解码器检查。 */
export async function requestJson(
  url: string, init: RequestInit, fetcher: typeof globalThis.fetch,
): Promise<unknown> {
  let response: Response;
  try {
    response = await fetcher(url, init);
  } catch (cause) {
    throw new ModelCallError('transport', '模型服务连接或等待失败。', { cause });
  }
  if (!response.ok) {
    throw new ModelCallError('http', `模型服务请求失败（HTTP ${response.status}）。`, undefined, response.status);
  }
  try {
    return await response.json();
  } catch (cause) {
    // 语法错误与响应体读取中断分开；都不输出原始响应正文。
    if (cause instanceof SyntaxError) {
      throw new ModelCallError('protocol', '模型响应不是合法 JSON。', { cause });
    }
    throw new ModelCallError('transport', '模型响应体读取失败。', { cause });
  }
}

例如服务返回 HTTP 429，函数直接抛出 kind: 'http'、httpStatus: 429，不读取并打印服务错误正文。如果状态成功却返回非 JSON，归为 protocol；如果读取响应体时连接中断，则归为 transport。返回未知 JSON 并不代表模型消息已经合法，仍要经过原解码器。

/** 只取得一次模型结果，不把停止生成等同于任务完成。 */
export async function completeDeepSeek(context: Context, options: ResolvedCompleteOptions): Promise<AssistantMessage> {
  // 把项目Context转换成DeepSeek的messages，不修改调用方持有的原数组。
  // 先转换历史，再附加总体要求；不直接展开项目内部消息。
  const history = encodeMessages(context.messages);
  const messages = context.systemPrompt === undefined
    ? history
    : [{ role: 'system', content: context.systemPrompt }, ...history];
  const value = await requestJson('https://api.deepseek.com/chat/completions', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${options.apiKey}`,
    },
    body: JSON.stringify({
      model: options.model,
      messages,
      // 把应用工具说明转换为服务协议；未提供时不发送tools字段。
      tools: context.tools?.length ? context.tools.map((tool) => ({
        type: 'function',
        function: { name: tool.name, description: tool.description, parameters: tool.parameters },
      })) : undefined,
      stream: false,
      thinking: { type: 'disabled' },
      max_tokens: options.maxTokens,
    }),
    // 只限制本次HTTP等待；整次Agent的预算由后续Runtime负责。
    signal: AbortSignal.timeout(30_000),
  }, options.fetch ?? globalThis.fetch);

  return decodeMessage(value);
}

// 【修改】配置、HTTP和消息转换分别归类，原始异常只作为 cause 保留。
import type { Context } from './types/context';
import type { AssistantMessage } from './types/messages';
import type { CompleteOptions, ResolvedCompleteOptions } from './types/options';
import { resolveOptions } from './request-options';
import { completeDeepSeek } from './providers/deepseek';
import { completeAnthropic } from './providers/anthropic';
import { ModelCallError } from './errors/model-call-error';

/** 仍只返回一次模型消息，不保存历史，也不在失败时自动重试。 */
export async function complete(context: Context, options: CompleteOptions): Promise<AssistantMessage> {
  let resolved: ResolvedCompleteOptions;
  try {
    resolved = resolveOptions(context, options);
  } catch (cause) {
    throw new ModelCallError('configuration', '模型调用配置无效，请检查所选服务和生成参数。', { cause });
  }
  try {
    return await (resolved.provider === 'deepseek'
      ? completeDeepSeek(context, resolved)
      : completeAnthropic(context, resolved));
  } catch (cause) {
    if (cause instanceof ModelCallError) throw cause;
    throw new ModelCallError('protocol', '模型消息编码或解码失败。', { cause });
  }
}

这里 return await (...) 有具体作用：等待适配器的 Promise 在当前 try 内成功或失败，才能被当前 catch 归类。只写 return promise 会直接把尚未完成的 Promise 交出去，它之后的拒绝不会进入这一层 catch。

第三步：启动前检查并准备工具清单 ​

这一步把上一节的两种工具表达真正接起来。应用传入原 reviewTools，其中的 read_file 还只有规则和执行函数；Runtime 需要一份能按名称查找、又能直接检查参数的准备结果。

新建 packages/runtime/src/tools/registry.ts。createToolRegistry 返回“名称 → 已准备工具”的 Map，代码中叫 registry。这里的“注册”就是检查工具后放入这张表，不是执行所有工具。runAgent 每次启动调用一次，之后的请求复用它。

ts
// 【新增文件】启动前检查工具清单、快照说明并编译 schema。
import Ajv from 'ajv';
import type { ExecutableTool } from '../types/tools';
import type { RegisteredTool } from '../types/tool-registry';
import { ToolBatchError } from '../errors/tool-batch-error';

/** runAgent 每次启动调用一次；配置失败发生在任何模型或工具动作之前。 */
export function createToolRegistry(tools: readonly ExecutableTool[]): ReadonlyMap<string, RegisteredTool> {
  const registry = new Map<string, RegisteredTool>();
  const ajv = new Ajv({ strict: true, addUsedSchema: false });
  try {
    for (const tool of tools) {
      if (typeof tool.name !== 'string' || !/^[a-zA-Z0-9_-]{1,64}$/.test(tool.name) || registry.has(tool.name) ||
          typeof tool.description !== 'string' || !tool.description.trim() || typeof tool.execute !== 'function') {
        throw new Error('工具名称、说明或执行函数无效。');
      }
      const parameters = structuredClone(tool.parameters);
      if (parameters.type !== 'object') throw new Error('工具参数 schema 根类型必须为 object。');
      const validate = ajv.compile(parameters);
      if ('$async' in validate && validate.$async) throw new Error('当前只接收同步参数 schema。');
      registry.set(tool.name, {
        name: tool.name, description: tool.description, parameters,
        execute: tool.execute.bind(tool), validate,
      });
    }
    return registry;
  } catch (cause) {
    // 不把 Ajv 的原始错误、schema 或应用配置直接发送给模型。
    throw new ToolBatchError({ code: 'tool_configuration', message: '本地工具配置无效，尚未开始模型调用。' }, [], { cause });
  }
}

以 read_file 为例，正常准备过程是：先复制它的 schema，再用 ajv.compile(parameters) 取得检查函数。随后 registry.set(...) 才真正创建并存入带有 validate 的工具对象；这就是上一节 RegisteredTool 类型描述的对象。

返回以后，runAgent 用 registry 中的说明构造模型可见的工具列表，执行器则在模型提出请求后，按名称取出同一项。它拿到 {path:123} 时调用 validate，得到不合格；拿到 {path:'src/cart.ts'} 时结构合格，才有机会调用原 execute。准备阶段本身没有读取文件。

这里的名称限制为 1 至 64 位字母、数字、下划线或连字符，是本项目当前的工具命名范围。重名会造成动作分发歧义，所以在第一次模型调用前拒绝；schema 拼错或不支持时也在这里停止，不把应用配置缺陷交给模型“修参数”。

structuredClone 使调用前已准备的 schema 不随应用原对象的后续修改而变化。它没有隔离工具闭包或冻结所有对象；应用提供的模型回调和工具仍是可信代码。bind(tool) 保留工具方法原来依赖的 this，不把函数拿出来后悄悄改变其调用对象。

Ajv 使用 strict: true 拒绝有歧义或不支持的 schema；未开启的类型转换、默认值填充和额外字段删除保持关闭，依据见官方选项说明。因此 123 不会变成 '123'，多余参数也不会被静默删掉后执行。addUsedSchema: false 不把每个已编译 schema 自动登记成一份全局 $id 清单；本篇通过工具名持有各自的检查函数，没有动态远程 schema 服务。

第四步：执行前校验，已知失败返回，未知异常停止 ​

执行哪些请求：看本次响应，不是遍历所有可用工具 ​

一个批次指同一条模型响应中的 toolCalls 请求列表。03 就已支持它，本篇是在原有路径中增加统一校验，不是新建一种“把所有工具各跑一次”的机制。

比如 05 的应用提供 lookup_release 和 lookup_service 两个工具。模型某次响应包含两项 lookup_service 请求，分别查询 checkout-api、inventory-api，执行器就只做这两项，不会顺便再查一次发布。这里是同一个工具使用不同参数；批次也可以包含不同工具，数量还可以只有一项。

对象表示什么是否会逐项执行
应用传入的 tools本次允许模型选择的工具清单不会因出现在这里就执行
准备后的 registry可按名称查到工具与检查函数的表用于查找，不是待执行列表
本次响应的 message.toolCalls模型这次明确提出的动作执行器按这里的顺序处理

为什么正常情况下处理完整批次再请求模型？模型这一条消息已经请求了两份资料，程序应先取得两项对应结果，再让它根据新信息继续判断。若刚执行第一项就再次请求，第二项还没有结果，工具往返也没有完成。未知异常是停止出口，不会硬凑完整批次再继续。

同批动作的参数在模型返回时就已确定。即使列表中先读后写，后面的写入参数也不会自动根据读取结果重新生成；需要读完再决定怎样修改时，应先反馈读取结果，由下一次模型调用提出修改。本项目本篇没有新增写工具。

用准备好的工具处理本批请求 ​

在新位置创建 packages/runtime/src/tools/execute.ts。它承接原 execute-tools.ts 的执行。保留两个调用入口，是因为它们接收的工具准备状态不同：

函数谁调用、传入什么替调用方完成什么
公开 executeTools(message, tools)独立执行一批的调用方，提供原始工具清单先准备清单，再处理本批请求
内部 executeToolBatch(message, registry)runAgent，提供本次运行已准备的表直接检查并执行本批，避免每轮重新编译

这两个入口最后进入同一段执行逻辑，不会各执行一遍。下面代码中的 for (const call of message.toolCalls) 明确了真正被遍历的是请求列表。

ts
// 【新增文件】承接原 execute-tools.ts；增加 schema 门禁和可保留的失败信息。
import type { AssistantMessage, ToolResultMessage } from '@ai-harness/model';
import type { ExecutableTool } from '../types/tools';
import type { RegisteredTool } from '../types/tool-registry';
import { ToolExecutionError } from '../errors/tool-execution-error';
import { ToolBatchError } from '../errors/tool-batch-error';
import { createToolRegistry } from './registry';

/** 保留原公开接口；直接执行一批时，也先准备并检查清单。 */
export async function executeTools(message: AssistantMessage, tools: readonly ExecutableTool[]): Promise<ToolResultMessage[]> {
  return executeToolBatch(message, createToolRegistry(tools));
}

/** runAgent 使用已准备清单；顺序执行，整批完成后才继续请求模型。 */
export async function executeToolBatch(
  message: AssistantMessage, registry: ReadonlyMap<string, RegisteredTool>,
): Promise<ToolResultMessage[]> {
  const ids = message.toolCalls.map((call) => call.id);
  if (message.stopReason !== 'toolUse' || ids.length === 0 ||
      ids.some((id) => typeof id !== 'string' || !id.trim()) || new Set(ids).size !== ids.length) {
    throw new ToolBatchError({ code: 'tool_protocol', message: '工具批次缺少完整请求或唯一 ID。' }, []);
  }
  const results: ToolResultMessage[] = [];
  for (const call of message.toolCalls) {
    let content: string;
    let isError = false;
    try {
      const tool = registry.get(call.name);
      if (!tool) throw new ToolExecutionError('没有注册该工具，请从工具说明中选择。', 'unknown_tool');
      let value: unknown;
      try {
        value = JSON.parse(call.arguments);
      } catch {
        throw new ToolExecutionError('参数不是合法 JSON，请重新生成。', 'invalid_json');
      }
      if (!tool.validate(value)) {
        // 指出结构不符，但不把参数值、schema 或库内部错误拼入反馈。
        throw new ToolExecutionError('参数不符合工具说明，请检查字段类型、必填项与额外字段。', 'invalid_arguments');
      }
      content = await tool.execute(value);
      if (typeof content !== 'string') throw new Error('工具没有返回文本。');
    } catch (cause) {
      if (!(cause instanceof ToolExecutionError)) {
        throw new ToolBatchError({
          code: 'tool_execution', message: '工具执行发生未知异常，已停止剩余动作。', toolCallId: call.id,
        }, [...results], { cause });
      }
      content = JSON.stringify({ code: cause.code, message: cause.message });
      isError = true;
    }
    results.push({ role: 'toolResult', toolCallId: call.id, toolName: call.name, content, isError });
  }
  return results;
}

沿 read_1 走一次：先查到 read_file，JSON.parse 把参数文本转成 {path:123}；tool.validate(value) 返回假，于是抛出已知的 invalid_arguments。tool.execute(value) 没有被调用，文件读取也就没有开始。执行器接住这类已知错误，生成 code/message 文本，创建与 read_1 关联的结果，继续处理同批其余请求。

下一次请求使用 {path:'src/cart.ts'} 时，校验通过才进入原工具；工具仍从应用清单找真实文件。返回的源码放入成功结果，执行器整批返回后，Runtime 才统一保存并继续调用模型。

结果返回给谁，谁把它变成下一次输入 ​

03 已有 ToolExecutionError，用来表示可以公开反馈的已知工具失败。本篇保留它，并给反馈增加代码。比如参数不符时，执行器返回的项目消息形如下面这样；这是观察示意，不要追加到源码：

json
{
  "role": "toolResult",
  "toolCallId": "read_1",
  "toolName": "read_file",
  "content": "{\"code\":\"invalid_arguments\",\"message\":\"参数不符合工具说明，请检查字段类型、必填项与额外字段。\"}",
  "isError": true
}

content 仍是文本，只是现在承载一段有 code/message 的 JSON。ToolResultMessage 的结构没有修改，06 的两家适配器仍能编码它。代码用于稳定识别类别，中文说明帮助模型或操作者理解；它们都由本地程序创建，不是模型返回的字段。

executeToolBatch 返回的 results 交给 runAgent 接住，随后才由 messages.push(...results) 保存。如果第一项请求失败，下一次传给模型的项目记录就是：原用户任务、包含 read_1 的 assistant、关联 read_1 的失败结果。模型能够利用反馈，是因为这条结果进入了下一次输入，不是因为程序抛出过异常。

ID 为空或重复属于整批无法可靠关联，在任何一项动作之前停止。参数校验则逐项发生：第一项成功、第二项参数失败时，第一项不会回滚，第二项得到反馈，同批其他项仍可继续。这不是原子事务。

06 的服务解码器也会检查响应 ID；若在解码时已拒绝，得到的是 model_protocol。这里的 tool_protocol 是执行器对项目批次的保护，也覆盖自定义 ModelCall 或直接调用 executeTools 的情况。分类取决于实际在哪一步发现问题。

如果 execute 抛出了未知异常，当前 results 中已有的结果复制进 ToolBatchError，并附上出错项的 ID。执行器立即退出，不执行后面的工具。它没有把任意异常的正文放进反馈，避免把内部信息交回模型。

ts
// 【修改】准备工具清单，并把受控失败信息返回应用。
// Runtime 持有本次历史，自动衔接模型决定与工具反馈。
import type { AssistantMessage } from '@ai-harness/model';
import type { RunAgentOptions, RunResult } from './types/run';
// 【修改】每次运行先准备工具，后续批次复用。
import { executeToolBatch } from './tools/execute';
import { createToolRegistry } from './tools/registry';
import { ToolBatchError } from './errors/tool-batch-error';
import { ModelCallError } from '@ai-harness/model';
import type { RegisteredTool } from './types/tool-registry';

/** 应用调用一次；返回明确的停止结果，不把模型停止等同于任务验收通过。 */
export async function runAgent(options: RunAgentOptions): Promise<RunResult> {
  if (!Number.isSafeInteger(options.maxModelCalls) || options.maxModelCalls < 1) {
    throw new Error('maxModelCalls 必须为正安全整数。');
  }
  if (options.messages.length === 0) throw new Error('初始消息不能为空。');

  // 复制数组，由 Runtime 独占本次追加权；不深拷贝或冻结消息对象。
  const messages = [...options.messages];
  let modelCalls = 0;
  let registry: ReadonlyMap<string, RegisteredTool>;
  try {
    registry = createToolRegistry(options.tools);
  } catch (error) {
    if (!(error instanceof ToolBatchError)) throw error;
    return { status: 'failed', phase: 'tools', failure: error.failure, error, messages, modelCalls };
  }
  const definitions = [...registry.values()].map(({ name, description, parameters }) => ({
    name, description, parameters,
  }));

  while (modelCalls < options.maxModelCalls) {
    modelCalls += 1;
    let message: AssistantMessage;
    try {
      // 每次使用最新记录；给调用方单独的数组，不暴露工具执行函数。
      message = await options.callModel({
        systemPrompt: options.systemPrompt,
        messages: [...messages],
        tools: definitions,
      });
    } catch (error) {
      // 【修改】稳定类别与原始异常分开，不以异常文本决定是否继续。
      const failure = error instanceof ModelCallError
        ? { code: `model_${error.kind}` as const, message: error.message, httpStatus: error.httpStatus }
        : { code: 'model_unknown' as const, message: '模型调用函数发生未分类异常。' };
      return { status: 'failed', phase: 'model', failure, error, messages, modelCalls };
    }
    messages.push(message);

    // 截断的动作参数不能执行；空文本也不能当作有效回答。
    if (message.stopReason === 'length') {
      return { status: 'truncated', messages, modelCalls };
    }
    if (message.stopReason === 'stop') {
      if (!message.content.trim()) return { status: 'emptyAnswer', messages, modelCalls };
      return { status: 'answered', answer: message, messages, modelCalls };
    }

    // 最后一次仍请求动作：记录请求，但不执行无法再反馈给模型的批次。
    if (modelCalls === options.maxModelCalls) {
      return { status: 'callLimit', messages, modelCalls };
    }
    try {
      const results = await executeToolBatch(message, registry);
      messages.push(...results);
    } catch (error) {
      // 【修改】保留未知异常前已完成的结果；停止后不再请求模型。
      if (error instanceof ToolBatchError) {
        messages.push(...error.completedResults);
        return { status: 'failed', phase: 'tools', failure: error.failure, error, messages, modelCalls };
      }
      return { status: 'failed', phase: 'tools', error, messages, modelCalls,
        failure: { code: 'tool_execution', message: '工具调度发生未知异常。' } };
    }
    // 不需要手写第二次调用；回到循环顶部，再带着完整反馈请求模型。
  }
  throw new Error('运行计数异常。');
}

正常路径仍是：message = await options.callModel(...) 接住决定，messages.push(message) 保存，执行器返回 results 后再 messages.push(...results)。区别是模型看到的说明与执行器检查用的 schema 都来自本次准备结果。

模型侧捕获到 ModelCallError 时，kind: 'protocol' 变成 failure.code: 'model_protocol'。应用自己注入的回调若抛出未分类异常，则是 model_unknown，Runtime 不根据错误文字猜它是网络还是协议问题。消息转换失败没有返回 assistant，所以也不会执行这次响应里看似存在的工具。

工具侧若接住 ToolBatchError，先执行 messages.push(...error.completedResults)，再返回失败。保存已完成事实之后停止，不会再进入下一次模型调用。 例如一条 assistant 提了三项请求，第一项成功、第二项未知异常，返回记录是：初始用户消息、含三项请求的 assistant、第一项成功结果；第三项未执行，第二项的结果不确定。

这份失败记录可能包含尚未完成的工具请求，不能直接当作完整工具往返重新发给服务。本篇没有恢复协议，也无法证明出错的第二项没有产生外部副作用；需要后续检查点与副作用专题处理。

ts
import type { RunResult } from '@ai-harness/runtime';

/** 只展示允许的异常标识；原异常留在 result.error 中供本地断点查看。 */
function describeFailure(error: unknown): string {
  if (!(error instanceof Error)) return '未识别的异常';
  if (/^模型服务请求失败（HTTP \d{3}）。$/.test(error.message)) return error.message;
  const names = new Set(['Error', 'TypeError', 'SyntaxError', 'TimeoutError', 'AbortError']);
  const name = names.has(error.name) ? error.name : 'Error';
  const cause = error.cause;
  const code = cause instanceof Error && 'code' in cause ? cause.code : undefined;
  const codes = new Set(['ECONNRESET', 'ECONNREFUSED', 'ENOTFOUND', 'ETIMEDOUT', 'UND_ERR_CONNECT_TIMEOUT', 'UND_ERR_SOCKET']);
  return typeof code === 'string' && codes.has(code) ? `${name} / ${code}` : name;
}

/** 应用在运行停止后调用；只打印已有记录和受控诊断，不执行模型或工具。 */
export function printRun(result: RunResult): void {
  let responseNumber = 0;
  for (const message of result.messages) {
    if (message.role === 'assistant') {
      responseNumber += 1;
      console.log(`模型响应 ${responseNumber}：`, JSON.stringify(message));
    } else if (message.role === 'toolResult') {
      console.log('本地工具结果：', JSON.stringify(message));
    }
  }
  console.log('运行停止：', result.status, '模型调用次数：', result.modelCalls);
  if (result.status === 'failed') {
    // 【新增】展示框架生成的稳定代码和说明，不打印 result.error 或 cause。
    console.error('失败代码：', result.failure.code, '失败说明：', result.failure.message);
    console.error('异常阶段：', result.phase, '异常标识：', describeFailure(result.error));
  }
}

模型服务 HTTP 失败可能看到 model_http，并从 failure.httpStatus 取得状态码；工具执行异常看到 tool_execution。原始 result.error 与嵌套 cause 不整体打印。ToolExecutionError 的说明本身仍由工具作者负责选择，只能放允许反馈的内容。

本篇形成的边界 ​

读完并运行后，应能沿一次请求指出三个变化：

  1. 调用前有共同检查：path 为数值时，在 Runtime 的 validate 处拒绝，尚未进入读取工具。
  2. 拒绝后有下一轮可用的信息：失败结果关联原 ID，由 Runtime 保存，下一次模型才能据此改选动作或修正参数。
  3. 无法继续时仍保留事实：未知异常使运行停止，已完成项由 Runtime 保存，应用拿到原因；剩余项不执行。

RegisteredTool 支持第一件事，已知失败反馈支持第二件事，批次错误与运行失败结果支持第三件事。类型和错误类只有接进这些实际动作后才产生作用。

现在工具清单先准备，模型参数再逐项检查，工具守住具体执行范围。已知失败作为观察进入后续决策；未知异常明确停止，应用按稳定代码识别，已经完成的结果仍能从记录找到。

这不等于自动恢复、事务回滚或安全沙箱，也没有证明真实模型一定会根据失败修正。schema 的计算成本与可信度仍由接入方约束；不能把任意外部 schema 当作安全输入。后续沿阶段大纲接入事件、流式和运行控制。

/** 应用提供固定文件位置；返回 ID 到非空文本的映射，不向模型开放文件路径。 */
export async function loadRecords(file: URL): Promise<ReadonlyMap<string, string>> {
  const value: unknown = JSON.parse(await readFile(file, 'utf8'));
  if (!isRecord(value)) {
    throw new Error('记录材料必须是 ID 到文本的对象。');
  }
  const records = new Map<string, string>();
  for (const [id, record] of Object.entries(value)) {
    if (!id.trim() || typeof record !== 'string' || !record.trim()) {
      throw new Error('记录 ID 和内容必须是非空文本。');
    }
    records.set(id, record);
  }
  if (records.size === 0) throw new Error('记录材料不能为空。');
  return records;
}

/** 在实际成功结果中查找指定查询，不把模型自述或失败结果当作证据。 */
function hasQuery(messages: readonly Message[], toolName: string, id: string): boolean {
  return messages.some((message) => {
    if (message.role !== 'toolResult' || message.toolName !== toolName || message.isError) return false;
    try {
      const value: unknown = JSON.parse(message.content);
      return isRecord(value) && value.id === id
        && typeof value.record === 'string' && value.record.trim().length > 0;
    } catch {
      return false;
    }
  });
}

/** 只展示允许的异常标识；原异常留在 result.error 中供本地断点查看。 */
function describeFailure(error: unknown): string {
  if (!(error instanceof Error)) return '未识别的异常';
  if (/^模型服务请求失败（HTTP \d{3}）。$/.test(error.message)) return error.message;
  const names = new Set(['Error', 'TypeError', 'SyntaxError', 'TimeoutError', 'AbortError']);
  const name = names.has(error.name) ? error.name : 'Error';
  const cause = error.cause;
  const code = cause instanceof Error && 'code' in cause ? cause.code : undefined;
  const codes = new Set(['ECONNRESET', 'ECONNREFUSED', 'ENOTFOUND', 'ETIMEDOUT', 'UND_ERR_CONNECT_TIMEOUT', 'UND_ERR_SOCKET']);
  return typeof code === 'string' && codes.has(code) ? `${name} / ${code}` : name;
}

/** 应用在运行停止后调用；只打印已有记录和受控诊断，不执行模型或工具。 */
export function printRun(result: RunResult): void {
  let responseNumber = 0;
  for (const message of result.messages) {
    if (message.role === 'assistant') {
      responseNumber += 1;
      console.log(`模型响应 ${responseNumber}：`, JSON.stringify(message));
    } else if (message.role === 'toolResult') {
      console.log('本地工具结果：', JSON.stringify(message));
    }
  }
  console.log('运行停止：', result.status, '模型调用次数：', result.modelCalls);
  if (result.status === 'failed') {
    // 【新增】展示框架生成的稳定代码和说明，不打印 result.error 或 cause。
    console.error('失败代码：', result.failure.code, '失败说明：', result.failure.message);
    console.error('异常阶段：', result.phase, '异常标识：', describeFailure(result.error));
  }
}

// 受配置清单限制的实际文件读取工具。
import { open } from 'node:fs/promises';
import { ToolExecutionError, type ExecutableTool } from '@ai-harness/runtime';
import type { ReadFileOptions } from './types/read-file';

const MAX_BYTES = 16 * 1024;
const KNOWN_IO_ERRORS = new Set(['ENOENT', 'EACCES', 'EPERM', 'ENOTDIR', 'EISDIR']);

/** 工具内部读取普通文件，最多接收 16 KiB，始终关闭文件句柄。 */
async function readAllowedFile(target: string): Promise<string> {
  try {
    const file = await open(target, 'r');
    try {
      if (!(await file.stat()).isFile()) throw new ToolExecutionError('只允许读取普通文件。');
      const buffer = Buffer.alloc(MAX_BYTES + 1);
      let total = 0;
      while (total < buffer.length) {
        const { bytesRead } = await file.read(buffer, total, buffer.length - total, null);
        if (bytesRead === 0) break;
        total += bytesRead;
      }
      if (total > MAX_BYTES) throw new ToolExecutionError('文件超过 16 KiB，本次未返回内容。');
      return buffer.subarray(0, total).toString('utf8');
    } finally {
      await file.close();
    }
  } catch (error) {
    const code = error instanceof Error && 'code' in error ? error.code : undefined;

// 【修改】准备工具清单，并把受控失败信息返回应用。
// Runtime 持有本次历史，自动衔接模型决定与工具反馈。
import type { AssistantMessage } from '@ai-harness/model';
import type { RunAgentOptions, RunResult } from './types/run';
// 【修改】每次运行先准备工具，后续批次复用。
import { executeToolBatch } from './tools/execute';
import { createToolRegistry } from './tools/registry';
import { ToolBatchError } from './errors/tool-batch-error';
import { ModelCallError } from '@ai-harness/model';
import type { RegisteredTool } from './types/tool-registry';

/** 应用调用一次；返回明确的停止结果，不把模型停止等同于任务验收通过。 */
export async function runAgent(options: RunAgentOptions): Promise<RunResult> {
  if (!Number.isSafeInteger(options.maxModelCalls) || options.maxModelCalls < 1) {
    throw new Error('maxModelCalls 必须为正安全整数。');
  }
  if (options.messages.length === 0) throw new Error('初始消息不能为空。');

  // 复制数组，由 Runtime 独占本次追加权；不深拷贝或冻结消息对象。
  const messages = [...options.messages];
  let modelCalls = 0;
  let registry: ReadonlyMap<string, RegisteredTool>;
  try {
    registry = createToolRegistry(options.tools);
  } catch (error) {
    if (!(error instanceof ToolBatchError)) throw error;
    return { status: 'failed', phase: 'tools', failure: error.failure, error, messages, modelCalls };
  }
  const definitions = [...registry.values()].map(({ name, description, parameters }) => ({
    name, description, parameters,
  }));

  while (modelCalls < options.maxModelCalls) {
    modelCalls += 1;
    let message: AssistantMessage;
    try {
      // 每次使用最新记录；给调用方单独的数组，不暴露工具执行函数。
      message = await options.callModel({
        systemPrompt: options.systemPrompt,
        messages: [...messages],
        tools: definitions,
      });
    } catch (error) {
      // 【修改】稳定类别与原始异常分开，不以异常文本决定是否继续。
      const failure = error instanceof ModelCallError
        ? { code: `model_${error.kind}` as const, message: error.message, httpStatus: error.httpStatus }
        : { code: 'model_unknown' as const, message: '模型调用函数发生未分类异常。' };
      return { status: 'failed', phase: 'model', failure, error, messages, modelCalls };
    }
    messages.push(message);

    // 截断的动作参数不能执行；空文本也不能当作有效回答。
    if (message.stopReason === 'length') {
      return { status: 'truncated', messages, modelCalls };
    }
    if (message.stopReason === 'stop') {
      if (!message.content.trim()) return { status: 'emptyAnswer', messages, modelCalls };
      return { status: 'answered', answer: message, messages, modelCalls };
    }

    // 最后一次仍请求动作：记录请求，但不执行无法再反馈给模型的批次。
    if (modelCalls === options.maxModelCalls) {
      return { status: 'callLimit', messages, modelCalls };
    }
    try {
      const results = await executeToolBatch(message, registry);
      messages.push(...results);
    } catch (error) {
      // 【修改】保留未知异常前已完成的结果；停止后不再请求模型。
      if (error instanceof ToolBatchError) {
        messages.push(...error.completedResults);
        return { status: 'failed', phase: 'tools', failure: error.failure, error, messages, modelCalls };
      }
      return { status: 'failed', phase: 'tools', error, messages, modelCalls,
        failure: { code: 'tool_execution', message: '工具调度发生未知异常。' } };
    }
    // 不需要手写第二次调用；回到循环顶部，再带着完整反馈请求模型。
  }
  throw new Error('运行计数异常。');
}

import type { ExecutableTool } from '../types/tools';

import { createToolRegistry } from './registry';

/** 保留原公开接口；直接执行一批时，也先准备并检查清单。 */
export async function executeTools(message: AssistantMessage, tools: readonly ExecutableTool[]): Promise<ToolResultMessage[]> {
  return executeToolBatch(message, createToolRegistry(tools));
}

/** runAgent 使用已准备清单；顺序执行，整批完成后才继续请求模型。 */
export async function executeToolBatch(
  message: AssistantMessage, registry: ReadonlyMap<string, RegisteredTool>,
): Promise<ToolResultMessage[]> {
  const ids = message.toolCalls.map((call) => call.id);
  if (message.stopReason !== 'toolUse' || ids.length === 0 ||
      ids.some((id) => typeof id !== 'string' || !id.trim()) || new Set(ids).size !== ids.length) {
    throw new ToolBatchError({ code: 'tool_protocol', message: '工具批次缺少完整请求或唯一 ID。' }, []);
  }
  const results: ToolResultMessage[] = [];
  for (const call of message.toolCalls) {
    let content: string;
    let isError = false;
    try {
      const tool = registry.get(call.name);
      if (!tool) throw new ToolExecutionError('没有注册该工具，请从工具说明中选择。', 'unknown_tool');
      let value: unknown;
      try {
        value = JSON.parse(call.arguments);
      } catch {
        throw new ToolExecutionError('参数不是合法 JSON，请重新生成。', 'invalid_json');
      }
      if (!tool.validate(value)) {
        // 指出结构不符，但不把参数值、schema 或库内部错误拼入反馈。
        throw new ToolExecutionError('参数不符合工具说明，请检查字段类型、必填项与额外字段。', 'invalid_arguments');
      }
      content = await tool.execute(value);
      if (typeof content !== 'string') throw new Error('工具没有返回文本。');
    } catch (cause) {
      if (!(cause instanceof ToolExecutionError)) {
        throw new ToolBatchError({
          code: 'tool_execution', message: '工具执行发生未知异常，已停止剩余动作。', toolCallId: call.id,
        }, [...results], { cause });
      }
      content = JSON.stringify({ code: cause.code, message: cause.message });
      isError = true;
    }
    results.push({ role: 'toolResult', toolCallId: call.id, toolName: call.name, content, isError });
  }
  return results;
}

// 【新增文件】启动前检查工具清单、快照说明并编译 schema。
import Ajv from 'ajv';
import type { ExecutableTool } from '../types/tools';
import type { RegisteredTool } from '../types/tool-registry';
import { ToolBatchError } from '../errors/tool-batch-error';

/** runAgent 每次启动调用一次；配置失败发生在任何模型或工具动作之前。 */
export function createToolRegistry(tools: readonly ExecutableTool[]): ReadonlyMap<string, RegisteredTool> {
  const registry = new Map<string, RegisteredTool>();
  const ajv = new Ajv({ strict: true, addUsedSchema: false });
  try {
    for (const tool of tools) {
      if (typeof tool.name !== 'string' || !/^[a-zA-Z0-9_-]{1,64}$/.test(tool.name) || registry.has(tool.name) ||
          typeof tool.description !== 'string' || !tool.description.trim() || typeof tool.execute !== 'function') {
        throw new Error('工具名称、说明或执行函数无效。');
      }
      const parameters = structuredClone(tool.parameters);
      if (parameters.type !== 'object') throw new Error('工具参数 schema 根类型必须为 object。');
      const validate = ajv.compile(parameters);
      if ('$async' in validate && validate.$async) throw new Error('当前只接收同步参数 schema。');
      registry.set(tool.name, {
        name: tool.name, description: tool.description, parameters,
        execute: tool.execute.bind(tool), validate,
      });
    }
    return registry;
  } catch (cause) {
    // 不把 Ajv 的原始错误、schema 或应用配置直接发送给模型。
    throw new ToolBatchError({ code: 'tool_configuration', message: '本地工具配置无效，尚未开始模型调用。' }, [], { cause });
  }
}
