26 退出后继续追问上一场任务 ​

第 25 篇能在退出后查到日志。本篇让 Coding CLI 在新进程里读回这份历史，回答「修正后最后一次验收是什么结果？」。

本篇在 Agent 的什么位置 ​

第五阶段「可靠执行与恢复」。这一步接在新进程启动、第一次调用模型之前。旧工具反馈作为历史消息进入新请求，执行工具的工作副本和验收状态仍属于原来的进程。

本篇技术方案 ​

实施前，先走完一次具体过程 ​

  1. 第一个 CLI 进程修复路径，保存会话头、首段 11 条消息和追问段 2 条新增消息。
  2. 退出后，第二个 CLI 进程收到日志路径和新问题。它验证文件版本、运行段边界和工具请求与反馈的配对，再按顺序拼出 13 条历史。
  3. CLI 把新问题放在第 14 条，调用一次模型。模型能引用旧的 check_complete。本次工具列表为空，回答描述的是历史验收结果。

实现架构图 ​

验收标准。 两个进程分别运行，第二个进程能依据磁盘记录回答。日志截断或工具反馈缺失时，读入失败，模型工厂也不会被调用。

第一步：把每段新增消息拼回历史 ​

新建 apps/coding-cli/src/session/read-session-log.ts。调用方给它日志路径，等它交回一份能传给模型的历史消息。这里沿用开头生成的那份三行日志。先展开完整实现，一次写入新文件。后面的几个小节用同源摘录解释这份代码。

完整实现 session/read-session-log.ts
ts
// 【新增文件】将可信的本地会话日志还原为可接续的消息。
import { readFile, stat } from 'node:fs/promises';
import type { Message, ToolCall } from '@ai-harness/model';

function record(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null && !Array.isArray(value);
}

function toolCall(value: unknown): value is ToolCall {
  return record(value) && typeof value.id === 'string' && value.id.length > 0 &&
    typeof value.name === 'string' && typeof value.arguments === 'string';
}

function message(value: unknown): value is Message {
  if (!record(value) || typeof value.content !== 'string') {
    return false;
  }
  if (value.role === 'user') {
    return true;
  }
  if (value.role === 'assistant') {
    return (value.stopReason === 'stop' || value.stopReason === 'toolUse' ||
      value.stopReason === 'length') && Array.isArray(value.toolCalls) &&
      value.toolCalls.every(toolCall);
  }
  return value.role === 'toolResult' && typeof value.toolCallId === 'string' &&
    typeof value.toolName === 'string' && typeof value.isError === 'boolean';
}

/** 每段必须从用户消息起步，以完成回答收尾，工具请求与反馈逐一配对。 */
function completeSegment(messages: readonly Message[]): boolean {
  const last = messages.at(-1);
  if (messages[0]?.role !== 'user' || last?.role !== 'assistant' ||
      last.stopReason !== 'stop' || last.toolCalls.length !== 0 || !last.content.trim()) {
    return false;
  }

  const pending = new Map<string, string>();
  for (const item of messages) {
    if (item.role === 'toolResult') {
      if (pending.get(item.toolCallId) !== item.toolName) {
        return false;
      }
      pending.delete(item.toolCallId);
    } else {
      if (pending.size > 0) {
        return false;
      }
      if (item.role === 'assistant') {
        for (const call of item.toolCalls) {
          if (pending.has(call.id)) {
            return false;
          }
          pending.set(call.id, call.name);
        }
      }
    }
  }
  return pending.size === 0;
}

/** 只接受第 25 篇写出的版本 1 日志，按行还原各段新增消息。 */
export async function readSessionHistory(path: string, signal?: AbortSignal): Promise<Message[]> {
  const info = await stat(path);
  const limit = 64 * 1024;
  if (!info.isFile() || info.size > limit) {
    throw new Error('会话日志应为不超过 64 KiB 的文件。');
  }

  const text = await readFile(path, { encoding: 'utf8', signal });
  if (Buffer.byteLength(text, 'utf8') > limit || !text.endsWith('\n')) {
    throw new Error('日志超限或最后一行未写完。');
  }

  const [first, ...lines] = text.slice(0, -1).split('\n');
  const header: unknown = JSON.parse(first!);
  if (!record(header) || header.type !== 'session' || header.version !== 1 ||
      typeof header.workspace !== 'string' || lines.length === 0) {
    throw new Error('缺少可接续的版本 1 会话记录。');
  }

  const history: Message[] = [];
  for (const line of lines) {
    const entry: unknown = JSON.parse(line);
    if (!record(entry) || entry.type !== 'run' || entry.status !== 'answered' ||
        !Array.isArray(entry.messages) || !entry.messages.every(message) ||
        !completeSegment(entry.messages)) {
      throw new Error('运行段未正常回答或工具反馈不完整。');
    }
    history.push(...entry.messages);
  }
  return history;
}

1.1 先分清会话头和运行段 ​

在 readSessionHistory 中，找到读取文件之后的这几行。

ts
  const [first, ...lines] = text.slice(0, -1).split('\n');
  const header: unknown = JSON.parse(first!);
  if (!record(header) || header.type !== 'session' || header.version !== 1 ||
      typeof header.workspace !== 'string' || lines.length === 0) {
    throw new Error('缺少可接续的版本 1 会话记录。');
  }

上一条检查已确认文件以换行结尾，所以 slice(0, -1) 先去掉最后一个换行，再按行切开。此时 first 是会话头的文本，lines 是两条运行记录的文本。头部必须是版本 1，而且至少有一条运行记录。只有会话头的文件还没有一段结束的运行可供接续。

1.2 确认一行里装的是可以接续的消息 ​

继续看 readSessionHistory 的循环。每轮只解析一行。下面是进入 history 之前的检查。

ts
    const entry: unknown = JSON.parse(line);
    if (!record(entry) || entry.type !== 'run' || entry.status !== 'answered' ||
        !Array.isArray(entry.messages) || !entry.messages.every(message) ||
        !completeSegment(entry.messages)) {
      throw new Error('运行段未正常回答或工具反馈不完整。');
    }

JSON.parse 只能告诉我们它是合法 JSON。因此先把结果当 unknown，再逐项确认。对于本例，首段的 entry.status 是 answered，entry.messages 有 11 条。every(message) 检查单条结构。比如 toolResult 必须有字符串内容、工具请求 ID 和工具名，以及布尔值 isError。completeSegment 则检查这些消息连在一起是否完整。

1.3 用 check_complete 走一遍请求与反馈 ​

在同一个文件里找到 completeSegment。开头要求这段从用户消息开始，最后是有文字、没有待执行请求的正常回答。循环内部有一张 pending 表，键是请求 ID，值是工具名。读到 assistant 消息里的工具请求时，下面这段把每个请求登记进去，同一批重复 ID 会失败。

ts
        for (const call of item.toolCalls) {
          if (pending.has(call.id)) {
            return false;
          }
          pending.set(call.id, call.name);
        }

例如读到请求 { id: "check_complete", name: "run_check", … } 后，表里有 "check_complete" → "run_check"。下一条实际工具反馈到来时，循环走到同一函数的 toolResult 分支：

ts
      if (pending.get(item.toolCallId) !== item.toolName) {
        return false;
      }
      pending.delete(item.toolCallId);

ID 和工具名都匹配，才把这条待配对请求删掉。假如删掉该反馈，pending 里仍有 check_complete，循环读到下一条模型回答时会返回 false，外层随即拒绝整个日志。验收业务通过或失败则仍由反馈正文表达，配对检查只确认这条反馈对应哪个请求。

1.4 拼回完整历史 ​

回到 readSessionHistory。这一行在所有检查通过后执行：

ts
    history.push(...entry.messages);

第一条运行记录把 history 从 0 条变成 11 条，第二条再追加追问与回答，变成 13 条。这样最后一轮留下的两条消息不会把首段的原始验收覆盖掉。

可以先停在这里。 试着说出 13 条来自哪两行，以及删掉一条反馈时为什么不能继续组装。

第二步：把新问题交给模型 ​

新建 apps/coding-cli/src/session/resume-conversation.ts。它接住日志路径和新问题，等校验通过再向模型发一次请求。先展开下面的完整实现写入新文件。

完整实现 session/resume-conversation.ts
ts
// 【新增文件】只根据已记录的历史回答一条新问题。
import { runAgent, type ModelCall } from '@ai-harness/runtime';
import { readSessionHistory } from './read-session-log';

/** 日志验证通过后才创建模型连接。本段没有工作副本和可执行工具。 */
export async function resumeConversation(
  path: string,
  question: string,
  createCallModel: () => ModelCall,
  signal: AbortSignal,
) {
  const history = await readSessionHistory(path, signal);
  signal.throwIfAborted();
  return runAgent({
    messages: [...history, { role: 'user', content: question }],
    systemPrompt: '根据保存的会话回答最新问题。历史反馈只说明当时的事实；没有依据时明确说明。',
    tools: [],
    callModel: createCallModel(),
    maxModelCalls: 1,
    maxToolCalls: 0,
    timeoutMs: 60_000,
    signal,
  });
}

等待日志校验通过 ​

回到同一文件中 resumeConversation 的开头，下面是完整实现里的摘录。

ts
  const history = await readSessionHistory(path, signal);
  signal.throwIfAborted();

如果第一步抛错，执行停在 await，因此下面的 createCallModel() 不会执行。正常时 history 有 13 条，函数把它们交给 runAgent：

ts
  return runAgent({
    messages: [...history, { role: 'user', content: question }],
    systemPrompt: '根据保存的会话回答最新问题。历史反馈只说明当时的事实；没有依据时明确说明。',
    tools: [],
    callModel: createCallModel(),
    maxModelCalls: 1,
    maxToolCalls: 0,

数组展开保留旧 check_complete，再把这次问题放在第 14 条。模型可以用保存的反馈说明当时的结果。tools: [] 与 maxToolCalls: 0 让这段只回答问题，maxModelCalls: 1 限制为一次调用。Runtime 返回的停止状态和回答会交回 CLI，由第三步的接续分支打印。

// 只处理终端参数，不读取环境或启动任务。
import type { CliOptions } from '../types/task';

export const helpText = `用法：ai-harness --task <任务.json> [--plan] [--follow-up <问题>] [--session-log <文件>]
ai-harness --resume-log <文件> --follow-up <问题>
任务路径相对当前终端目录；配置内路径相对任务文件目录。
--plan 开启实验性计划；--follow-up 在首次回答后追加一条问题。
--help 只显示帮助。
退出码：0已接受，1未接受，2参数/准备/报告失败，130主动取消。`;

/** main传入argv，不接受未知、重复或缺值选项。 */
export function parseArgs(args: readonly string[]): CliOptions {
  if (args.length === 1 && args[0] === '--help') {
    return { help: true };
  }
  let taskFile: string | undefined;
  let planning = false;
  let followUp: string | undefined;
  let sessionLog: string | undefined;
  let resumeLog: string | undefined;
  for (let i = 0; i < args.length; i += 1) {
    const arg = args[i];
    if (arg === '--plan' && !planning) {
      planning = true;
    } else if (arg === '--follow-up' && followUp === undefined) {
      // 【新增】读取一条用户追问。引号由终端处理。
      const value = args[++i]?.trim();
      if (!value || value.startsWith('--')) {
        throw new Error('追问内容缺失。');
      }
      followUp = value;
    } else if (arg === '--session-log' && sessionLog === undefined) {
      // 【新增】文件路径相对启动 CLI 时的工作目录。
      const value = args[++i];
      if (!value?.trim() || value.startsWith('--')) {
        throw new Error('会话记录路径缺失。');
      }
      sessionLog = value;
    } else if (arg === '--resume-log' && resumeLog === undefined) {
      const value = args[++i];
      if (!value?.trim() || value.startsWith('--')) {
        throw new Error('会话日志路径缺失。');
      }
      resumeLog = value;
    } else if (arg === '--task' && taskFile === undefined) {
      const value = args[++i];
      if (!value?.trim() || value.startsWith('--')) {
        throw new Error('任务路径缺失。');
      }
      taskFile = value;
    } else {
      throw new Error('参数无效。');
    }
  }
  if (resumeLog) {
    if (taskFile || sessionLog || planning || !followUp) {
      throw new Error('只读接续需要且仅接受日志路径和一条追问。');
    }
    return { help: false, resumeLog, question: followUp };
  }
  if (!taskFile) {
    throw new Error('需要任务配置。');
  }
  return {
    help: false,
    taskFile,
    planning,
    ...(followUp ? { followUp } : {}),
    ...(sessionLog ? { sessionLog } : {}),
  };
}

// 应用生命周期：参数→配置→副本→运行→报告→释放监听。
import type { RunInputOptions } from './types/task';
import type { ModelCall, RunEventListener } from '@ai-harness/runtime';
import { parseArgs, helpText } from './config/args';
import { loadTask } from './config/task';
import { createModelCall } from './model';
import { prepareSession } from './session/prepare';
import { appendRun, createSessionLog } from './session/session-log';
import { resumeConversation } from './session/resume-conversation';
import { runSession } from './session/run';
import { reportSession } from './report/report';
import { printProgress, printBlock } from './report/terminal';
import type { CliSession } from './types/session';

/** CLI 接收退出码。观察入口可注入模型，并开启全量历史对照。 */
export async function runCli(
  args: readonly string[],
  createCallModel: () => ModelCall = createModelCall,
  fullHistory = false,
): Promise<number> {
  const controller = new AbortController();
  const onInterrupt = () => {
    if (!controller.signal.aborted) {
      console.log('请求取消，等待当前协作操作退出。');
      controller.abort();
    }
  };
  let session: CliSession | undefined;
  let phase = '参数';
  process.on('SIGINT', onInterrupt);

  try {
    const options = parseArgs(args);
    if (options.help) {
      console.log(helpText);
      return 0;
    }

    // 【新增】只读接续先于任务配置和副本准备分流。
    if ('resumeLog' in options) {
      phase = '会话接续';
      const result = await resumeConversation(
        options.resumeLog,
        options.question,
        createCallModel,
        controller.signal,
      );
      printBlock('接续停止', { status: result.status });
      if (result.status === 'answered') {
        printBlock('接续回答', result.answer.content);
        return 0;
      }
      return result.status === 'cancelled' ? 130 : 1;
    }

    phase = '任务配置';
    const task = await loadTask(options.taskFile, controller.signal);

    phase = '模型配置';
    const callModel = createCallModel();

    phase = '副本准备';
    session = await prepareSession(task, options.planning, controller.signal);
    printBlock('工作副本', session.root);

    // 【新增】先独占创建文件，防止两次 CLI 运行混写。
    let logPath: string | undefined;
    if (options.sessionLog) {
      phase = '会话记录';
      logPath = await createSessionLog(options.sessionLog, session.root);
    }

    phase = '运行与报告';
    const onEvent: RunEventListener = (event) => {
      printProgress(event);
      if (
        event.type === 'tool_end' &&
        event.toolName === 'update_plan' &&
        !event.isError &&
        session?.plan
      ) {
        printBlock('任务计划（模型声明）', session.plan.read());
      }
    };

    const first = await runSession(task, session, callModel, controller.signal, onEvent, { fullHistory });
    // 【新增】首段落盘之后才启动追问。
    if (logPath) {
      phase = '会话记录';
      await appendRun(logPath, first, 0);
      phase = '运行与报告';
    }
    let result = first;

    // 沿用已经准备的副本和工具，只给 Runtime 一个新的历史起点。
    if (options.followUp && first.status === 'answered' && !controller.signal.aborted) {
      printBlock('首段停止', {
        status: first.status,
        modelCalls: first.modelCalls,
        toolCalls: first.toolCalls,
        runId: first.runId,
      });
      const nextInput: RunInputOptions = {
        messages: [...first.messages, { role: 'user', content: options.followUp }],
        fullHistory,
      };
      result = await runSession(task, session, callModel, controller.signal, onEvent, nextInput);
      if (logPath) {
        phase = '会话记录';
        await appendRun(logPath, result, first.messages.length);
        phase = '运行与报告';
      }
    }

    return await reportSession(task, session, result);
  } catch {
    if (controller.signal.aborted) {
      return 130;
    }

    // 原异常留在调试器，不打印凭据、响应正文或整个请求。
    console.error(`${phase}失败；请检查配置或在对应函数断点查看原异常。`);
    return 2;
  } finally {
    process.off('SIGINT', onInterrupt);
    if (session) {
      console.log('工作副本保留在：', session.root);
    }
  }
}

// 【新增文件】固定模型只根据上一进程写入的验收反馈回答。
import { runCli } from '../../apps/coding-cli/src/main';

const file = process.argv[2];
if (!file) {
  throw new Error('请指定第 25 篇生成的日志。');
}
const question = '修正后最后一次验收的结果是什么？';

process.exitCode = await runCli(['--resume-log', file, '--follow-up', question], () =>
  async (context) => {
    const check = context.messages.find((message) =>
      message.role === 'toolResult' && message.toolCallId === 'check_complete',
    );
    if (!check || JSON.parse(check.content).status !== 'passed' ||
        context.tools?.length || context.messages.at(-1)?.content !== question) {
      throw new Error('缺少历史验收证据，或只读接续的输入不符合预期。');
    }
    return {
      role: 'assistant',
      content: '日志中最后一次验收通过，依据是 check_complete。',
      stopReason: 'stop',
      toolCalls: [],
    };
  },
);
