04 让 Runtime 自动继续与停止 ​

03 中，应用先调用一次模型，执行工具，再手写第二次调用。如果第二次模型还需要文件，程序就停下了。本篇把这段衔接交给 Runtime：模型请求工具就执行并反馈，再请求模型；模型返回文本或触发运行限制时，返回明确的停止结果。 应用只调用一次运行入口，不再写 first/second。

这是第一阶段的自动循环部分。仍使用 03 的文件读取工具和审查材料，不增加业务功能。完成后，程序可以根据实际响应走不同次数：一次回答、读取后回答，或者根据工具失败调整请求后再回答。每条路径都受调用上限约束。

这里的自动循环不是不断重复同一请求。每次调用模型前，Runtime 都把上一次模型响应和已完成的工具结果保存进去，让下一次决定基于更新的信息。 反馈改变的是模型可见的证据；下一步动作仍由模型产生，本地程序检查并执行。

本篇技术方案 ​

实施前，先走完一次具体过程 ​

先确认沿用的材料。03 创建的 fixtures/code-review/src/cart.ts 完整内容如下，本篇无需修改：

ts
// 审查材料；不会被导入并执行。
export interface CartItem {
  price: number;
  quantity: number;
}

export function total(items: CartItem[]): number {
  return items.reduce((sum, item) => sum + item.price, 0);
}

任务仍是审查 src/cart.ts。应用把这个模型可见名称映射到上面的实际文件；工具读取文本，不导入执行 total。可以用单价 10、数量 3 应得 30 这一输入检查回答是否指出遗漏数量的问题。

本篇把应用手写的衔接交给 Runtime，整体按下面的顺序运行：

  1. 应用准备一次运行。 提供初始任务、工具、调用上限和一个会请求模型的函数；服务配置留在应用与模型包，循环不用认识密钥或服务地址。
  2. Runtime 建立自己持有的历史。 从初始消息开始，每次把当前历史交给模型函数，等待一条完整模型消息，再保存这条响应。
  3. 根据响应继续或停止。 有工具请求，就调用原执行器；执行器返回真实结果后，由 Runtime 追加到历史，再带着更新后的内容进入下一轮。只有文字时，按停止原因和内容选取返回分支。
  4. 限制和异常同样有明确出口。 达到模型调用上限，不再请求；未知异常返回失败。已经发生的工具动作不会因停止自动回滚。
  5. 应用只接住一次最终结果。 结果带历史、调用次数和停止状态；应用展示记录、检查成功读取证据，再人工核对具体结论。循环返回文本不等于任务质量已通过。

这些步骤不预先规定模型第二次就回答。例如下面是一种可能轨迹：

模型调用输入中的记录数模型响应本地下一步
11请求 cart.ts，ID 为 bad_01路径不在清单内，保存失败结果
23根据反馈改为 src/cart.ts，ID 为 read_02读取成功，保存源码结果
35根据源码给出审查文字保存响应，结束运行

这是说明机制的样本，不要求真实模型先犯错，也不保证它会这样修正。第一种路径错误并没有打开文件；第二次请求是模型生成的新动作，不是程序偷偷把错误路径改掉。

正常的“读一次就回答”只需要两次模型调用。支持这两种情况的是同一个循环，而不是分别写两套流程。

第一步：定义 Runtime 使用的调用与结果 ​

给 Runtime 一个会调用模型的函数 ​

Runtime 需要“传入本次上下文，得到一条模型响应”，不需要知道服务地址和密钥。新建 packages/runtime/src/types/model-call.ts：

ts
// 【新增文件】Runtime 使用的单次模型调用契约。
import type { AssistantMessage, Context } from '@ai-harness/model';

/** 应用提供实现；Runtime 传入本次上下文，等待一条已转换的模型消息。 */
export type ModelCall = (context: Context) => Promise<AssistantMessage>;

ModelCall 是函数类型，不是模型对象，也不会自己发请求。后面应用会创建一个符合这个类型的函数，内部调用现有 complete。Runtime 每次把最新的 Context 交给该函数，await 后得到已经转换过的 AssistantMessage。

它只规定本阶段需要的调用形状。不同提供商的协议转换仍在模型包，第二阶段再接入第二家服务；本篇不提前加入提供商注册系统。

配置和停止结果 ​

新建 packages/runtime/src/types/run.ts。配置由应用提供，实际运行结果由 Runtime 创建；不是在这个类型文件中执行循环。

这些类型约定一次运行的输入和停止后的输出：应用创建选项，Runtime 创建带历史和调用次数的结果，报告按 status 选择展示分支。它们描述运行数据，不会自行执行循环或判断审查结论。

ts
// 【新增文件】一次运行的配置与停止结果。
import type { AssistantMessage, Message } from '@ai-harness/model';
import type { ModelCall } from './model-call';
import type { ExecutableTool } from './tools';

/** 应用创建运行配置；任务与模型连接不写入通用循环。 */
export interface RunAgentOptions {
  /** 初始记录；Runtime 复制数组后追加，不向此数组 push。 */
  messages: readonly Message[];
  /** 可省略的总体要求，每次模型调用沿用。 */
  systemPrompt?: string;
  /** 本次允许使用的本地工具；Runtime 仅把说明交给 callModel。 */
  tools: readonly ExecutableTool[];
  /** 应用绑定服务配置和凭据的函数，Runtime 不选择提供商。 */
  callModel: ModelCall;
  /** 整次运行最多发起的模型调用数，正安全整数；包括最终回答和失败的调用。 */
  maxModelCalls: number;
}

/** 各种停止结果共用的运行记录，由 Runtime 创建并交给应用读取。 */
interface RunRecord {
  /** 已保存的初始消息、模型响应与完整批次结果；只在内存中。 */
  messages: readonly Message[];
  /** 实际发起的模型调用次数，不是工具次数或消息条数。 */
  modelCalls: number;
}

/** Runtime 返回的停止原因；answered 也不保证任务结论正确。 */
export type RunResult = RunRecord & (
  | { status: 'answered'; answer: AssistantMessage }
  // callLimit 最后一次仍请求工具；truncated 输出截断；emptyAnswer 正常停止但无文本。
  | { status: 'callLimit' | 'truncated' | 'emptyAnswer' }
  // 未知异常不作为工具反馈；保留原异常仅供本地调试，不能直接打印整个结果。
  | { status: 'failed'; phase: 'model' | 'tools'; error: unknown }
);

本次应用会提供一条用户消息、文件读取工具、总体要求和 maxModelCalls: 6。callModel 负责模型接入，配置里没有 DeepSeek 专属字段。

结果由共同记录加不同停止分支组成。RunRecord 保存所有分支都需要的消息与计数；RunResult 根据 status 区分：只有 answered 分支有 answer，只有 failed 分支有异常阶段和原异常。应用先检查状态，再读取相应字段，不靠猜测可选字段是否存在。

modelCalls 统计 Runtime 调用 callModel 函数的尝试次数，包括返回最终回答的调用，以及抛异常的调用。它不是工具数、消息数，也不等于真正发出的 HTTP 请求数或计费次数：例如模型函数可能在检查配置时就抛出异常。

需要先理解的几个停止结果：

status表示什么能证明任务完成吗
answered模型正常停止且有非空文字不能，还要按任务检查证据和结论
callLimit最后一次允许调用仍请求工具不能，保留了尚未执行的请求
truncated本次模型输出达到生成上限而截断不能，截断的请求不执行
emptyAnswer模型正常停止却没有有效文字不能
failed模型调用或工具批次抛出未知异常不能，原异常只供本地调试

第二步：循环推进，并在明确位置停止 ​

新建 packages/runtime/src/run-agent.ts。它替应用完成整次推进：接收初始消息和工具，反复调用传入的模型函数、执行工具、保存反馈，最终返回一份 RunResult。

以开头的三次调用样本为例，输入只有一条用户消息；目标输出是 status: 'answered'、modelCalls: 3 和六条记录，其中包含一次路径失败、一次成功读取和最终回答。若中途达到上限，就返回上限分支，不把已有工具动作包装成任务成功。

ts
// 【新增文件】Runtime 持有本次历史，自动衔接模型决定与工具反馈。
import type { AssistantMessage } from '@ai-harness/model';
import type { RunAgentOptions, RunResult } from './types/run';
import { executeTools } from './execute-tools';

/** 应用调用一次；返回明确的停止结果，不把模型停止等同于任务验收通过。 */
export async function runAgent(options: RunAgentOptions): Promise<RunResult> {
  if (!Number.isSafeInteger(options.maxModelCalls) || options.maxModelCalls < 1) {
    throw new Error('maxModelCalls 必须为正安全整数。');
  }
  if (options.messages.length === 0) throw new Error('初始消息不能为空。');

  // 复制数组，由 Runtime 独占本次追加权；不深拷贝或冻结消息对象。
  const messages = [...options.messages];
  const definitions = options.tools.map(({ name, description, parameters }) => ({
    name, description, parameters,
  }));
  let modelCalls = 0;

  while (modelCalls < options.maxModelCalls) {
    modelCalls += 1;
    let message: AssistantMessage;
    try {
      // 每次使用最新记录；给调用方单独的数组，不暴露工具执行函数。
      message = await options.callModel({
        systemPrompt: options.systemPrompt,
        messages: [...messages],
        tools: definitions,
      });
    } catch (error) {
      return { status: 'failed', phase: 'model', error, messages, modelCalls };
    }
    messages.push(message);

    // 截断的动作参数不能执行；空文本也不能当作有效回答。
    if (message.stopReason === 'length') {
      return { status: 'truncated', messages, modelCalls };
    }
    if (message.stopReason === 'stop') {
      if (!message.content.trim()) return { status: 'emptyAnswer', messages, modelCalls };
      return { status: 'answered', answer: message, messages, modelCalls };
    }

    // 最后一次仍请求动作：记录请求，但不执行无法再反馈给模型的批次。
    if (modelCalls === options.maxModelCalls) {
      return { status: 'callLimit', messages, modelCalls };
    }
    try {
      const results = await executeTools(message, options.tools);
      messages.push(...results);
    } catch (error) {
      return { status: 'failed', phase: 'tools', error, messages, modelCalls };
    }
    // 不需要手写第二次调用；回到循环顶部，再带着完整反馈请求模型。
  }
  throw new Error('运行计数异常。');
}

一次正常推进怎样发生 ​

先看记录的建立。const messages = [...options.messages] 创建新的数组，03 应用里的初始数组不再承担追加任务。工具对象通过 map 提取成 definitions，这里只保留名称、描述和参数说明，不把本地 execute 交给模型函数。

第一次进入循环，modelCalls 从 0 变成 1。Runtime 调用 options.callModel，给它的 messages 是当前记录的另一份数组浅拷贝。此时只有用户任务。返回的 AssistantMessage 由循环局部变量 message 接住，messages.push(message) 保存整条响应。

若它请求工具，程序调用已有的 executeTools(message, options.tools)。这个函数执行完整批次并返回结果数组，由循环的 results 接住，再执行：

ts
messages.push(...results);

这行已包含在上方完整函数中，仅用于对照，不要再次追加。单项工具执行后，本次记录从两条变成三条：用户、模型请求、工具结果。执行器没有自行改历史；实际写回发生在循环这里。

控制流随后回到 while。第二次不是把最初那一条用户消息再发一次，而是重新从更新后的 messages 创建输入。模型能看到刚才的成功或失败结果，决定继续请求什么，或者回答。

具体跟踪一次失败后的修正 ​

开头样本中，第一次的 message.toolCalls[0] 请求 cart.ts。工具清单只允许 src/cart.ts，所以工具返回已知失败，执行器创建 isError: true 的结果。

第二次传入模型函数的记录已有三条。假设模型返回新的 read_02 请求，路径改为 src/cart.ts，循环保存这条新消息，再执行工具。这次 results[0].content 包含实际源码，写回后记录长度变成 5。

第三次调用得到正常文字，循环保存响应，进入 stop 分支，创建 answered 结果并返回。改变路径的是模型产生的新请求；让模型看到错误并有机会改变动作的是 Runtime 的反馈写回。 如果模型一直请求错误路径，它也可能用完调用次数，本篇没有保证自动修复成功。

这里的数组复制只复制数组，不深拷贝、冻结消息或参数对象。注入的模型函数属于可信应用代码，应读取上下文而不修改消息对象；这不是对不可信插件的隔离机制。本次记录只在内存中，进程退出后不会自动恢复。

为什么先保存，再检查停止原因 ​

messages.push(message) 在分支判断前执行，因此截断或最后一次尚未执行的请求也保留在结果里，便于应用解释停在哪里。保存不等于接受，更不等于执行：length 分支直接返回，不把可能截断的参数交给工具。

stop 分支先检查文字是否为空。有内容才返回 answered，这里判断的是“模型给出了可以进一步检查的回答”，并没有检查审查内容是否正确。

最后一次请求工具怎么办 ​

例如 maxModelCalls: 2：第一次请求并执行读取，第二次仍请求其他内容。这时已经没有第三次模型调用来消费新结果，所以返回 callLimit，第二次提出的那批工具不会执行。最后一条记录会是待执行的 assistant 请求，没有对应结果；这是一份停止记录，不是已经可以直接续跑的完整历史。

如果第二次返回正常文字，则可以在上限内得到 answered。因此上限不是“到了这个次数就一律失败”，而是最多允许调用多少次模型函数。该策略用于本篇，之后涉及可持久化动作和恢复时还需重新审视，不能理解为所有框架的唯一做法。

已知工具失败仍由 03 的执行器转换为结果，循环保存后可以继续。未知异常则返回 failed，phase 区分模型函数和工具执行；不再开始后续批次或下一次模型调用。工具批次中已经发生的动作不回滚，也没有部分结果恢复机制。

ts
// 【新增文件】示例展示运行记录，并检查当前审查任务的读取证据。
import type { RunResult } from '@ai-harness/runtime';

/** 只展示允许的异常标识；原异常留在 result.error 中供本地断点查看。 */
function describeFailure(error: unknown): string {
  if (!(error instanceof Error)) return '未识别的异常';
  if (/^模型服务请求失败（HTTP \d{3}）。$/.test(error.message)) return error.message;
  const names = new Set(['Error', 'TypeError', 'SyntaxError', 'TimeoutError', 'AbortError']);
  const name = names.has(error.name) ? error.name : 'Error';
  const cause = error.cause;
  const code = cause instanceof Error && 'code' in cause ? cause.code : undefined;
  const codes = new Set(['ECONNRESET', 'ECONNREFUSED', 'ENOTFOUND', 'ETIMEDOUT', 'UND_ERR_CONNECT_TIMEOUT', 'UND_ERR_SOCKET']);
  return typeof code === 'string' && codes.has(code) ? `${name} / ${code}` : name;
}

/** 应用使用；返回是否满足本示例基本展示条件，不验证代码结论一定正确。 */
export function reportRun(result: RunResult, requiredPath: string): boolean {
  let responseNumber = 0;
  for (const message of result.messages) {
    if (message.role === 'assistant') {
      responseNumber += 1;
      console.log(`模型响应 ${responseNumber}：`, JSON.stringify(message));
    } else if (message.role === 'toolResult') {
      console.log('本地工具结果：', JSON.stringify(message));
    }
  }
  console.log('运行停止：', result.status, '模型调用次数：', result.modelCalls);
  if (result.status === 'failed') {
    console.error('异常阶段：', result.phase, '异常标识：', describeFailure(result.error));
    return false;
  }
  if (result.status !== 'answered') return false;

  const hasSource = result.messages.some((message) => message.role === 'toolResult'
    && message.toolName === 'read_file' && !message.isError
    && message.content.startsWith(`${requiredPath}\n`));
  if (!hasSource) {
    console.error('缺少目标文件的成功读取证据，本次审查未交付。');
    return false;
  }
  console.log('模型文本（text）：', result.answer.content);
  return true;
}

先展示已经发生的过程 ​

for (const message of result.messages) 遍历的是 Runtime 已经收集好的记录。遇到 assistant 就打印模型消息，遇到 toolResult 就打印本地执行结果；用户任务在这个展示循环里跳过，因为应用已经知道自己发起的任务。

沿上面的四条记录看：用户任务不打印；第一条 assistant 打印为“模型响应 1”，其中仍有读取请求；工具结果打印为“本地工具结果”；最后一条 assistant 打印为“模型响应 2”。这只是回看过程，不会把原请求再次执行。最后的 模型文本（text） 还会单独展示最终回答的文字，与“模型响应 2”来自同一条消息，不是第三次模型调用。

responseNumber 只是这里展示时增加的响应编号。result.modelCalls 来自 Runtime，统计模型函数的调用尝试数。如果第二次调用抛异常，记录里可能只有第一条模型响应，此时展示编号到 1，调用次数却是 2：第二次尝试没有产生可保存的响应。

最后决定展示什么、返回什么 ​

如果 hasSource 为 true，函数打印 result.answer.content，然后返回 true。正常样本因此会展示源码读取、两条模型响应、answered 状态和最终文字；下一步的入口据此保持正常退出。

再看两种不同情况：

  • 先读取失败，模型随后修正路径并成功读取，再给出回答：历史里虽然有失败，但也有成功的目标读取，hasSource 可以是 true。
  • 读取一直失败，模型最后回答“缺少源码，无法审查”：Runtime 可以是 answered，但没有成功读取，当前审查仍返回 false。

这个检查是当前示例的最低接受条件，不是完整的答案评估器。它不检查源码版本，不验证模型是否真正使用了内容，也不能防止不可信工具伪造文本；本阶段工具由可信应用注入。是否指出遗漏数量的问题，仍要对照材料与具体计算检查。

辅助函数怎样缩小异常范围 ​

describeFailure(error) 只在 result.status === 'failed' 时使用。它接收 Runtime 留下的原异常，返回可以展示的一小段字符串，不修改异常，也不修复运行。

正常的源码审查不会走到这里。出现失败时，它按以下方式处理：

  1. 抛出的值不是 Error 对象，返回“未识别的异常”。JavaScript 可以抛任意值，不能假定一定有 message。
  2. error.message 完整匹配模型包生成的固定 HTTP 状态格式，例如“模型服务请求失败（HTTP 401）。”，只展示这段已控制的说明，不展示服务响应正文。
  3. 其他异常先取允许的标准名称。名称不在清单中时统一用 Error，避免任意自定义名称直接进入日志。
  4. 再查看 error.cause。它可能保存底层网络异常；只有确实是 Error、具有 code，且代码在允许清单内，才把代码附到名称后面。例如得到 TypeError / ECONNREFUSED。缺少这些条件时只返回名称。

因此，reportRun 的失败日志可能是“异常阶段：model，异常标识：TypeError / ECONNREFUSED”。阶段说明停在模型调用，代码帮助定位连接问题；它们不能直接证明是密钥错误或某个确定的网络原因。

原异常仍在 result.error 中，可以在本地断点查看。不要直接打印整个 result、完整异常或请求对象，它们可能包含本地路径、请求信息或其他不应进入共享日志的内容。配置校验发生在运行开始前；配置无效时由入口的 catch 处理，不会先创建一个正常运行结果。

// 受配置清单限制的实际文件读取工具。
import { open } from 'node:fs/promises';
import { ToolExecutionError, type ExecutableTool } from '@ai-harness/runtime';
import type { ReadFileOptions } from './types/read-file';

const MAX_BYTES = 16 * 1024;
const KNOWN_IO_ERRORS = new Set(['ENOENT', 'EACCES', 'EPERM', 'ENOTDIR', 'EISDIR']);

/** 工具内部读取普通文件，最多接收 16 KiB，始终关闭文件句柄。 */
async function readAllowedFile(target: string): Promise<string> {
  try {
    const file = await open(target, 'r');
    try {
      if (!(await file.stat()).isFile()) throw new ToolExecutionError('只允许读取普通文件。');
      const buffer = Buffer.alloc(MAX_BYTES + 1);
      let total = 0;
      while (total < buffer.length) {
        const { bytesRead } = await file.read(buffer, total, buffer.length - total, null);
        if (bytesRead === 0) break;
        total += bytesRead;
      }
      if (total > MAX_BYTES) throw new ToolExecutionError('文件超过 16 KiB，本次未返回内容。');
      return buffer.subarray(0, total).toString('utf8');
    } finally {
      await file.close();
    }
  } catch (error) {
    const code = error instanceof Error && 'code' in error ? error.code : undefined;
    if (typeof code === 'string' && KNOWN_IO_ERRORS.has(code)) {
      throw new ToolExecutionError(`无法读取已配置文件（${code}）。`);
    }
    throw error;
  }
}

/** 应用创建工具；模型只收到说明，Runtime 才能调用 execute。 */
export function createReadFileTool(options: ReadFileOptions): ExecutableTool {
  const files = new Map(Object.entries(options.files));
  return {
    name: 'read_file',
    description: `读取一个已允许的 UTF-8 源码文件。可用路径：${[...files.keys()].join('、')}。`,
    parameters: {
      type: 'object',
      properties: { path: { type: 'string', description: '从可用路径中选择一项。' } },
      required: ['path'],
      additionalProperties: false,
    },
    async execute(value: unknown): Promise<string> {
      if (typeof value !== 'object' || value === null || Array.isArray(value)
        || !('path' in value) || typeof value.path !== 'string'
        || Object.keys(value).length !== 1) {
        throw new ToolExecutionError('参数必须是只包含字符串 path 的对象。');
      }
      const target = files.get(value.path);
      if (target === undefined) throw new ToolExecutionError('该路径不在应用允许的文件清单中。');
      const source = await readAllowedFile(target);
      return `${value.path}\n${source}`;
    },
  };
}

/** complete 调用它创建发送用数组；不改变应用保存的记录。 */
export function encodeMessages(messages: readonly Message[]) {
  return messages.map((message) => {
    if (message.role === 'user') {
      return { role: 'user' as const, content: message.content };
    }
    if (message.role === 'toolResult') {
      return {
        role: 'tool' as const,
        tool_call_id: message.toolCallId,

    return {
      role: 'assistant' as const,
      content: message.content || null,
      tool_calls: message.toolCalls.length ? message.toolCalls.map((call) => ({
        id: call.id,
        type: 'function' as const,
        function: { name: call.name, arguments: call.arguments },
      })) : undefined,
    };
  });

// 从DeepSeek响应中取得文本和工具请求，不执行任何工具。
import type { AssistantMessage } from '../types/messages';
import type { ToolCall } from '../types/tools';
import { isRecord } from '../validation';

/** 保留每项请求的身份与原始参数，只检查本篇支持的协议形状。 */
function decodeToolCalls(value: unknown): ToolCall[] {
  if (value === undefined) return [];
  if (!Array.isArray(value)) throw new Error('tool_calls必须是数组。');

  const ids = new Set<string>();
  return value.map((item): ToolCall => {
    if (!isRecord(item) || item.type !== 'function' ||
        typeof item.id !== 'string' || !item.id.trim() || !isRecord(item.function)) {
      throw new Error('工具请求缺少可识别的类型、ID或function对象。');
    }
    const fn = item.function;
    if (typeof fn.name !== 'string' || !fn.name.trim() || typeof fn.arguments !== 'string') {
      throw new Error('工具请求缺少名称或参数文本。');
    }
    if (ids.has(item.id)) throw new Error('同一消息中的工具请求ID重复。');
    ids.add(item.id);

    // 此处保留参数文本，解析、工具查找与执行前校验留给执行层。
    return { id: item.id, name: fn.name, arguments: fn.arguments };
  });
}

/** complete调用它转换响应，返回的请求仍是待处理动作。 */
export function decodeMessage(value: unknown): AssistantMessage {
  if (!isRecord(value) || !Array.isArray(value.choices)) {
    throw new Error('模型响应缺少choices数组。');
  }
  const choice: unknown = value.choices[0];
  if (!isRecord(choice)) throw new Error('模型响应缺少可识别的choice。');
  const reason = choice.finish_reason;
  if (reason !== 'stop' && reason !== 'length' && reason !== 'tool_calls') {
    throw new Error('模型返回了本篇尚不支持的停止原因。');
  }
  const message = choice.message;
  if (!isRecord(message) || message.role !== 'assistant' ||
      (typeof message.content !== 'string' && message.content !== null)) {
    throw new Error('模型没有返回可识别的assistant消息。');
  }

  const toolCalls = decodeToolCalls(message.tool_calls);
  if (reason === 'tool_calls' && toolCalls.length === 0) {
    throw new Error('模型声明请求工具，却没有返回工具请求。');
  }
  if (reason === 'stop' && toolCalls.length > 0) {
    throw new Error('模型停止原因与工具请求不一致。');
  }

  // null表示没有附带文字；截断结果仍保留length，不升级为可用请求。
  return {
    role: 'assistant',
    content: message.content ?? '',
    stopReason: reason === 'tool_calls' ? 'toolUse' : reason,
    toolCalls,
  };
}

// 继续负责请求，将响应转换交给同目录的解码模块。
import type { AssistantMessage } from '../types/messages';
import type { Context } from '../types/context';
import type { CompleteOptions } from '../types/options';
import { decodeMessage } from './deepseek-response';
// 请求也要转换历史中的动作与结果。
import { encodeMessages } from './deepseek-messages';

/** 只取得一次模型结果，不把停止生成等同于任务完成。 */
export async function complete(context: Context, options: CompleteOptions): Promise<AssistantMessage> {
  if (!options.apiKey.trim()) throw new Error('缺少DEEPSEEK_API_KEY。');
  if (!options.model.trim() || context.messages.length === 0) {
    throw new Error('模型名称与消息不能为空。');
  }
  const maxTokens = options.maxTokens ?? 256;
  if (!Number.isSafeInteger(maxTokens) || maxTokens < 1) throw new Error('maxTokens需为正安全整数。');

  // 把项目Context转换成DeepSeek的messages，不修改调用方持有的原数组。
  // 先转换历史，再附加总体要求；不直接展开项目内部消息。
  const history = encodeMessages(context.messages);
  const messages = context.systemPrompt === undefined
    ? history
    : [{ role: 'system', content: context.systemPrompt }, ...history];
  const response = await fetch('https://api.deepseek.com/chat/completions', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${options.apiKey}`,
    },
    body: JSON.stringify({
      model: options.model,
      messages,
      // 把应用工具说明转换为服务协议；未提供时不发送tools字段。
      tools: context.tools?.length ? context.tools.map((tool) => ({
        type: 'function',
        function: { name: tool.name, description: tool.description, parameters: tool.parameters },
      })) : undefined,
      stream: false,
      thinking: { type: 'disabled' },
      max_tokens: maxTokens,
    }),
    // 只限制本次HTTP等待；整次Agent的预算由后续Runtime负责。
    signal: AbortSignal.timeout(30_000),
  });

  // 不把服务错误正文或带凭据的请求对象直接打印到终端。
  if (!response.ok) throw new Error(`模型服务请求失败（HTTP ${response.status}）。`);
  const value: unknown = await response.json();
  return decodeMessage(value);
}

// 执行一条模型消息内的工具请求，不请求模型、不修改历史。
import type { AssistantMessage, ToolResultMessage } from '@ai-harness/model';
import type { ExecutableTool } from './types/tools';
import { ToolExecutionError } from './tool-error';

/** 应用调用；整批按顺序完成后返回结果，应用再保存并请求模型。 */
export async function executeTools(
  message: AssistantMessage,
  tools: readonly ExecutableTool[],
): Promise<ToolResultMessage[]> {
  if (message.stopReason !== 'toolUse' || message.toolCalls.length === 0) {
    throw new Error('只执行完整的 toolUse 消息。');
  }

  // 在任何执行之前检查歧义；不会执行前几项才发现后面 ID 重复。
  const registry = new Map(tools.map((tool) => [tool.name, tool]));
  if (registry.size !== tools.length) throw new Error('本地工具名称不能重复。');
  const ids = message.toolCalls.map((call) => call.id);
  if (ids.some((id) => !id.trim()) || new Set(ids).size !== ids.length) {
    throw new Error('本批请求 ID 为空或重复。');
  }

  const results: ToolResultMessage[] = [];
  for (const call of message.toolCalls) {
    let content: string;
    let isError = false;
    try {
      const tool = registry.get(call.name);
      if (!tool) throw new ToolExecutionError('没有注册该工具。');

      let argumentsValue: unknown;
      try {
        argumentsValue = JSON.parse(call.arguments);
      } catch {
        throw new ToolExecutionError('工具参数不是合法 JSON，请重新生成。');
      }
      content = await tool.execute(argumentsValue);
      if (typeof content !== 'string') throw new Error('工具没有返回文本。');
    } catch (error) {
      // 只反馈明确归类的失败，避免把程序缺陷或敏感异常正文发送给模型。
      if (!(error instanceof ToolExecutionError)) throw error;
      content = error.message;
      isError = true;
    }
    results.push({
      role: 'toolResult', toolCallId: call.id, toolName: call.name, content, isError,
    });
  }
  return results;
}

// 【新增文件】Runtime 持有本次历史，自动衔接模型决定与工具反馈。
import type { AssistantMessage } from '@ai-harness/model';
import type { RunAgentOptions, RunResult } from './types/run';
import { executeTools } from './execute-tools';

/** 应用调用一次；返回明确的停止结果，不把模型停止等同于任务验收通过。 */
export async function runAgent(options: RunAgentOptions): Promise<RunResult> {
  if (!Number.isSafeInteger(options.maxModelCalls) || options.maxModelCalls < 1) {
    throw new Error('maxModelCalls 必须为正安全整数。');
  }
  if (options.messages.length === 0) throw new Error('初始消息不能为空。');

  // 复制数组，由 Runtime 独占本次追加权；不深拷贝或冻结消息对象。
  const messages = [...options.messages];
  const definitions = options.tools.map(({ name, description, parameters }) => ({
    name, description, parameters,
  }));
  let modelCalls = 0;

  while (modelCalls < options.maxModelCalls) {
    modelCalls += 1;
    let message: AssistantMessage;
    try {
      // 每次使用最新记录；给调用方单独的数组，不暴露工具执行函数。
      message = await options.callModel({
        systemPrompt: options.systemPrompt,
        messages: [...messages],
        tools: definitions,
      });
    } catch (error) {
      return { status: 'failed', phase: 'model', error, messages, modelCalls };
    }
    messages.push(message);

    // 截断的动作参数不能执行；空文本也不能当作有效回答。
    if (message.stopReason === 'length') {
      return { status: 'truncated', messages, modelCalls };
    }
    if (message.stopReason === 'stop') {
      if (!message.content.trim()) return { status: 'emptyAnswer', messages, modelCalls };
      return { status: 'answered', answer: message, messages, modelCalls };
    }

    // 最后一次仍请求动作：记录请求，但不执行无法再反馈给模型的批次。
    if (modelCalls === options.maxModelCalls) {
      return { status: 'callLimit', messages, modelCalls };
    }
    try {
      const results = await executeTools(message, options.tools);
      messages.push(...results);
    } catch (error) {
      return { status: 'failed', phase: 'tools', error, messages, modelCalls };
    }
    // 不需要手写第二次调用；回到循环顶部，再带着完整反馈请求模型。
  }
  throw new Error('运行计数异常。');
}

// 【新增文件】示例展示运行记录，并检查当前审查任务的读取证据。
import type { RunResult } from '@ai-harness/runtime';

/** 只展示允许的异常标识；原异常留在 result.error 中供本地断点查看。 */
function describeFailure(error: unknown): string {
  if (!(error instanceof Error)) return '未识别的异常';
  if (/^模型服务请求失败（HTTP \d{3}）。$/.test(error.message)) return error.message;
  const names = new Set(['Error', 'TypeError', 'SyntaxError', 'TimeoutError', 'AbortError']);
  const name = names.has(error.name) ? error.name : 'Error';
  const cause = error.cause;
  const code = cause instanceof Error && 'code' in cause ? cause.code : undefined;
  const codes = new Set(['ECONNRESET', 'ECONNREFUSED', 'ENOTFOUND', 'ETIMEDOUT', 'UND_ERR_CONNECT_TIMEOUT', 'UND_ERR_SOCKET']);
  return typeof code === 'string' && codes.has(code) ? `${name} / ${code}` : name;
}

/** 应用使用；返回是否满足本示例基本展示条件，不验证代码结论一定正确。 */
export function reportRun(result: RunResult, requiredPath: string): boolean {
  let responseNumber = 0;
  for (const message of result.messages) {
    if (message.role === 'assistant') {
      responseNumber += 1;
      console.log(`模型响应 ${responseNumber}：`, JSON.stringify(message));
    } else if (message.role === 'toolResult') {
      console.log('本地工具结果：', JSON.stringify(message));
    }
  }
  console.log('运行停止：', result.status, '模型调用次数：', result.modelCalls);
  if (result.status === 'failed') {
    console.error('异常阶段：', result.phase, '异常标识：', describeFailure(result.error));
    return false;
  }
  if (result.status !== 'answered') return false;

  const hasSource = result.messages.some((message) => message.role === 'toolResult'
    && message.toolName === 'read_file' && !message.isError
    && message.content.startsWith(`${requiredPath}\n`));
  if (!hasSource) {
    console.error('缺少目标文件的成功读取证据，本次审查未交付。');
    return false;
  }
  console.log('模型文本（text）：', result.answer.content);
  return true;
}
