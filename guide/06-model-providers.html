06 模型适配：换服务，保留同一个 Runtime ​

05 已让代码审查和发布调查共用同一个 Runtime。但两者最终都调用 DeepSeek：如果换成另一家服务，需要改循环吗？工具请求、工具结果还能继续流转吗？

本篇在模型包中接入 Anthropic Messages API。应用选择服务，模型包负责转换各自的请求与响应，Runtime 继续使用原来的消息结构、工具执行器和停止规则。完成后，两种任务都能选择接入；没有第二家 API Key，也能用本地固定响应观察完整的协议往返。

这是第二阶段的第一篇，建设的是 Agent 的模型接入能力：无论服务怎样表达动作，运行内核都能接住项目消息、执行工具、保存反馈，再继续决策。它不改变模型本身的能力，也不保证两家服务的答案相同。接下来的单元继续建设工具契约、事件、流式输出、取消和预算。

本篇技术方案 ​

实施前，先走完一次具体过程 ​

  1. 应用选择提供商，保留原任务。 代码审查还是请求文件，发布调查还是查询记录；变化的是模型配置增加服务选择。密钥仍由应用提供，不放进任务消息。
  2. 统一入口解析配置，再选择适配器。 模型包接收项目上下文和配置，检查模型名、输出上限等选项，将同一次调用交给对应服务实现，Runtime 不增加厂商分支。
  3. 适配器完成两个方向的转换。
    • 3.1 发送时转换。 把项目的用户消息、模型工具请求与本地结果，组织成所选服务认识的消息格式；两家格式不同，不能直接把一家的正文换个地址发送。
    • 3.2 返回时转换。 从服务原生响应取得文字、工具请求与停止原因，统一返回项目的模型消息。Runtime 接到的仍是原契约，可以继续执行工具和保存反馈。
  4. 用同一循环继续任务。 工具结果进入下一轮上下文，再由适配器编码发送。应用仍按各自任务规则展示和检查最终结果，不要求两家回答措辞相同。
  5. 没有第二家 Key，也能先观察协议。 本地入口用预写的两种原生 HTTP 响应替代网络，但调用实际编码、解码、Runtime 和文件工具，检查整个往返。它证明接线可运行，不等于第二家真实服务已验证。

后面先接配置与适配，再把两种入口连到同一套任务，不重新实现执行循环。

换服务时，什么应该变化 ​

继续使用代码审查任务：读取 src/cart.ts，指出总价计算的问题。工具和材料沿用 03 至 05；实际文件仍是 fixtures/code-review/src/cart.ts，由应用配置的清单映射为模型看到的 src/cart.ts。

先只看两家服务怎样表达“读取同一个文件”。下面是协议结构示意，保留本章使用的字段，不是真实调用日志：

json
// DeepSeek 响应中的工具请求
{"id":"call_read_01","type":"function","function":{"name":"read_file","arguments":"{\"path\":\"src/cart.ts\"}"}}

// Anthropic 响应中的工具请求内容块
{"type":"tool_use","id":"toolu_read_01","name":"read_file","input":{"path":"src/cart.ts"}}

DeepSeek 的参数是 JSON 文本，Anthropic 的 input 已经是对象。两者都要求保留请求 ID，但它们的字段位置不同。不能只换 HTTP 地址，再把另一种响应当成 choices[0].message 读取。

本项目已定义 ToolCall：id/name/arguments，其中 arguments 是字符串。新适配器把 Anthropic 的 input 用 JSON.stringify 转成这种结构，再返回 AssistantMessage。Runtime 仍在执行前解析参数、查找工具，工具仍负责检查具体路径并实际读取。

读取后，Runtime 保存的仍是 ToolResultMessage。第二次调用时，DeepSeek 需要 role: 'tool' 和 tool_call_id；Anthropic 需要 role: 'user' 中的 tool_result 内容块。内部结果没有变，发送给服务的表达变了。 对应规则见两家的 Chat Completions 协议和 工具调用反馈说明。

“适配”就是把项目认识的输入输出，与服务要求的格式互相转换。应用负责选服务、提供对应密钥；模型包负责这种转换；Runtime 负责什么时候调用、执行哪些工具、保存什么以及何时停止。工具不会因为换模型服务而搬到模型包。

Pi 固定版本的 Models.stream / complete也在模型层选择接入，complete 等待流的最终结果。本篇借鉴职责边界，先保留非流式 HTTP；不引入它的完整模型目录、认证和流式实现。

第一步：给调用配置加上选择 ​

完整替换 packages/model/src/types/options.ts。原有 apiKey/model/maxTokens 保留；新增 provider，不传时仍选 DeepSeek；新增可选 fetch，正常调用不传，本地观察时传入一个只返回样本的函数。

ModelProvider 是提供商名称的类型。ResolvedCompleteOptions 表示已经补全默认值的配置，仅供模型包内部使用；定义它不会自动完成校验，下一步的函数才实际检查并创建对象。

ts
// 【修改】公共调用配置增加提供商选择和可注入的 HTTP 传输。
/** 模型包当前接入的两种服务；不等于任意兼容服务都已经支持。 */
export type ModelProvider = 'deepseek' | 'anthropic';

/** 应用传给 complete；不进入对话消息。 */
export interface CompleteOptions {
  /** 省略时保留 DeepSeek；一次运行应固定同一个提供商。 */
  provider?: ModelProvider;
  /** 所选服务自己的密钥；模型包只放入请求头。 */
  apiKey: string;
  /** 服务模型 ID；应用负责选择支持当前文本与工具模式的模型。 */
  model: string;
  /** 输出 token 上限，省略时为 256；不是整次任务预算。 */
  maxTokens?: number;
  /** 默认使用全局 fetch；本地协议检查传入固定响应函数，不访问网络。
   * 此函数会接触含凭据的请求，只能由可信应用配置。
   */
  fetch?: typeof globalThis.fetch;
}

/** complete 校验后创建，两个适配器读取；不从包入口公开。 */
export interface ResolvedCompleteOptions extends CompleteOptions {
  /** 已确定的服务，不再依赖缺省规则。 */
  provider: ModelProvider;
  /** 已检查为正安全整数。 */
  maxTokens: number;
}

这里的两个函数入口用途不同：Runtime 的 ModelCall 接收项目 Context、返回项目消息；fetch 接收 HTTP 请求、返回 HTTP Response。本地替换后者，仍会经过真实的消息编码和响应解码。自定义传输能接触请求头，只能由可信应用提供；不要把模型生成的代码作为这个函数执行。

第二步：共用检查，保留 DeepSeek 的协议 ​

一次检查，再选择接入 ​

新建 packages/model/src/request-options.ts。它替公开 complete 检查两家共同需要的配置：服务名称可识别、密钥和模型非空、至少有一条消息、输出上限有效。例如传入未指定服务和上限的配置，返回对象就会带 provider: 'deepseek' 与 maxTokens: 256。

ts
// 【新增文件】两家服务共用的调用前检查。
import type { Context } from './types/context';
import type { CompleteOptions, ResolvedCompleteOptions } from './types/options';

/** complete 在编码和发送前调用；返回新配置，不修改应用传入的对象。 */
export function resolveOptions(context: Context, options: CompleteOptions): ResolvedCompleteOptions {
  const provider = options.provider ?? 'deepseek';
  if (provider !== 'deepseek' && provider !== 'anthropic') {
    throw new Error('不支持的模型提供商。');
  }
  if (!options.apiKey.trim()) throw new Error('缺少所选模型服务的 API Key。');
  if (!options.model.trim() || context.messages.length === 0) {
    throw new Error('模型名称与消息不能为空。');
  }
  const maxTokens = options.maxTokens ?? 256;
  if (!Number.isSafeInteger(maxTokens) || maxTokens < 1) {
    throw new Error('maxTokens 需为正安全整数。');
  }
  return { ...options, provider, maxTokens };
}

返回值是新对象，原 options 不变。它不验证远程账户、模型是否可用，也不验证工具参数的业务含义；这些不能靠检查字符串非空得知。失败会在 HTTP 发送之前抛出，后面不再调用适配器。

调整原请求函数 ​

完整替换 packages/model/src/providers/deepseek.ts：原 complete 改名为 completeDeepSeek，参数改为内部 ResolvedCompleteOptions；删除原来重复的密钥、模型、消息与上限检查。原 encodeMessages、decodeMessage、工具 schema 转换和服务选项保留。maxTokens 现在从检查后的配置取得。

这个适配入口接收项目上下文和已经检查的配置，按 DeepSeek 协议发送、解码并返回项目消息。公开 complete 会按服务选择调用它，Runtime 仍然不接触原生响应字段。

ts
// 【修改】共用检查移入公开调用入口；这里保留 DeepSeek 协议。
// 继续负责请求，将响应转换交给同目录的解码模块。
import type { AssistantMessage } from '../types/messages';
import type { Context } from '../types/context';
import type { ResolvedCompleteOptions } from '../types/options';
import { decodeMessage } from './deepseek-response';
// 请求也要转换历史中的动作与结果。
import { encodeMessages } from './deepseek-messages';

/** 只取得一次模型结果，不把停止生成等同于任务完成。 */
export async function completeDeepSeek(context: Context, options: ResolvedCompleteOptions): Promise<AssistantMessage> {
  // 把项目Context转换成DeepSeek的messages，不修改调用方持有的原数组。
  // 先转换历史，再附加总体要求；不直接展开项目内部消息。
  const history = encodeMessages(context.messages);
  const messages = context.systemPrompt === undefined
    ? history
    : [{ role: 'system', content: context.systemPrompt }, ...history];
  const response = await (options.fetch ?? globalThis.fetch)('https://api.deepseek.com/chat/completions', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${options.apiKey}`,
    },
    body: JSON.stringify({
      model: options.model,
      messages,
      // 把应用工具说明转换为服务协议；未提供时不发送tools字段。
      tools: context.tools?.length ? context.tools.map((tool) => ({
        type: 'function',
        function: { name: tool.name, description: tool.description, parameters: tool.parameters },
      })) : undefined,
      stream: false,
      thinking: { type: 'disabled' },
      max_tokens: options.maxTokens,
    }),
    // 只限制本次HTTP等待；整次Agent的预算由后续Runtime负责。
    signal: AbortSignal.timeout(30_000),
  });

  // 不把服务错误正文或带凭据的请求对象直接打印到终端。
  if (!response.ok) throw new Error(`模型服务请求失败（HTTP ${response.status}）。`);
  const value: unknown = await response.json();
  return decodeMessage(value);
}

关键变化是 (options.fetch ?? globalThis.fetch)(...)：有本地传输就调用它，没有就调用正常网络传输。两种情况下，后面仍等待 Response、读取未知 JSON，再交给原 decodeMessage。更换传输没有绕过协议转换，也没有直接给 Runtime 塞一条最终消息。

公开包入口还会在第五步更新，先把新服务的转换接齐，不要在此时运行不完整的工程。

第三步：把项目记录编码成新服务消息 ​

先看输入与目标输出。Runtime 中一轮批次可能保存以下四条记录，只用于观察，不写入源码：

text
用户任务
assistant：toolCalls = [请求 one，请求 two]
toolResult：toolCallId = one，content = 第一份结果，isError = false
toolResult：toolCallId = two，content = 第二份结果，isError = true

Anthropic 需要三条发送消息：用户任务；带两个 tool_use 块的 assistant；带两个 tool_result 块的 user。两项结果合并发送，但 Runtime 内部仍分别保存。isError: true 映射到块上的 is_error: true，原 ID 复制到 tool_use_id。

先定义发送结构 ​

新建 packages/model/src/types/anthropic.ts。这些类型只描述该服务编码器创建的对象，不从包入口导出，也不替换项目公共 Message。工具说明使用服务的 input_schema 字段，稍后由请求函数转换，字段定义见工具说明协议。

这份内部类型约定项目消息编码成 Anthropic 请求时使用的文本块、工具请求块和工具结果块。编码器创建这些对象，请求函数放进正文；本地类型声明不验证服务返回，也不替代项目公共消息。

ts
// 【新增文件】仅供 Anthropic 编码器使用，不从包入口公开。
/** 编码器把项目文本转换为服务的文本块。 */
export interface AnthropicTextBlock {
  type: 'text';
  text: string;
}

/** 编码器重建历史中的工具请求；服务要求 input 是对象。 */
export interface AnthropicToolUseBlock {
  type: 'tool_use';
  /** 复制原 ToolCall.id，供下一条结果关联。 */
  id: string;
  name: string;
  input: Record<string, unknown>;
}

/** 编码器把 Runtime 已保存的结果转换为用户消息中的反馈块。 */
export interface AnthropicToolResultBlock {
  type: 'tool_result';
  /** 复制 ToolResultMessage.toolCallId，不创建新身份。 */
  tool_use_id: string;
  content: string;
  is_error: boolean;
}

/** 发送用消息；不替换 Runtime 内部 Message。 */
export type AnthropicMessage =
  | { role: 'user'; content: (AnthropicTextBlock | AnthropicToolResultBlock)[] }
  | { role: 'assistant'; content: (AnthropicTextBlock | AnthropicToolUseBlock)[] };

创建发送用数组 ​

新建 packages/model/src/providers/anthropic-messages.ts。encodeAnthropicMessages 接收 Runtime 交给本次调用的记录，返回新的服务消息数组。调用它的是后面的请求函数，使用返回值的是 HTTP 请求正文。

ts
// 【新增文件】把项目历史转换为 Anthropic 的消息块。
import type { Message } from '../types/messages';
import type { AnthropicMessage, AnthropicTextBlock, AnthropicToolUseBlock } from '../types/anthropic';
import { isRecord } from '../validation';

/** completeAnthropic 调用；创建发送用数组，原记录仍由 Runtime 保存。 */
export function encodeAnthropicMessages(messages: readonly Message[]): AnthropicMessage[] {
  const encoded: AnthropicMessage[] = [];
  let previousRole: Message['role'] | undefined;
  for (const message of messages) {
    const followsResult = previousRole === 'toolResult';
    previousRole = message.role;
    if (message.role === 'user') {
      encoded.push({ role: 'user', content: [{ type: 'text', text: message.content }] });
      continue;
    }
    if (message.role === 'toolResult') {
      const block = {
        type: 'tool_result' as const,
        tool_use_id: message.toolCallId,
        content: message.content,
        is_error: message.isError,
      };
      const previous = encoded.at(-1);

      // 同一批连续结果合并到一个 user 消息，紧接原 assistant 请求。
      if (previous?.role === 'user' && followsResult) {
        previous.content.push(block);
      } else {
        encoded.push({ role: 'user', content: [block] });
      }
      continue;
    }
    const content: (AnthropicTextBlock | AnthropicToolUseBlock)[] = [];
    if (message.content) content.push({ type: 'text', text: message.content });
    for (const call of message.toolCalls) {
      const input: unknown = JSON.parse(call.arguments);
      if (!isRecord(input)) throw new Error('Anthropic 历史工具参数必须是 JSON 对象。');
      content.push({ type: 'tool_use', id: call.id, name: call.name, input });
    }
    encoded.push({ role: 'assistant', content });
  }
  return encoded;
}

沿前面的四条记录看一遍：第一条用户文本变成一个 text 块；第二条 assistant 的 toolCalls 逐项变成 tool_use，参数文本解析成服务要求的 input 对象。到第三条结果时，创建一个装有 tool_result 的 user 消息；到第四条时，followsResult 为真，把第二个结果加入刚才新建的 user 内容数组。

previousRole 记的是上一条项目记录的角色，不是已经编码了多少条消息。因为四条项目记录可以编码成三条服务消息，不能拿两个数组的下标互相代替。previous.content.push(block) 修改的是本函数创建的发送对象，没有改 Runtime 持有的原结果。

这是发送历史时的 JSON 解析；真正执行工具前的解析与参数检查仍在原执行层。正常记录里的参数来自已保存的工具请求。若手工拼出非法历史参数，新服务无法接收，本次调用会失败，不能悄悄改成空对象发送。编码器也没有负责补齐任意缺失结果；输入应来自已完成整批反馈的正常循环。

第四步：把新服务响应还原为项目消息 ​

先转换返回值 ​

假设服务返回一个 tool_use 块，ID 为 toolu_read_01，名称为 read_file，input 为 {path: 'src/cart.ts'}。解码后应得到：

json
{"role":"assistant","content":"","stopReason":"toolUse","toolCalls":[{"id":"toolu_read_01","name":"read_file","arguments":"{\"path\":\"src/cart.ts\"}"}]}

新建 packages/model/src/providers/anthropic-response.ts。参数 value 来自 HTTP 的 response.json()，它在检查前是未知数据，不能因为写了接口就相信内容正确。

decodeAnthropicMessage 接收未知的服务 JSON，将文本块、工具请求块和停止原因转换成一条项目 AssistantMessage，返回给 Anthropic 请求函数。这样上层循环只处理原来的消息形状，而不解析服务专有的 content 块。

ts
// 【新增文件】把服务响应转换为 Runtime 已认识的 AssistantMessage。
import type { AssistantMessage } from '../types/messages';
import type { ToolCall } from '../types/tools';
import { isRecord } from '../validation';

/** completeAnthropic 传入 response.json() 的未知值；不执行或保存请求。 */
export function decodeAnthropicMessage(value: unknown): AssistantMessage {
  if (!isRecord(value) || value.role !== 'assistant' || !Array.isArray(value.content)) {
    throw new Error('Anthropic 响应缺少可识别的 assistant 内容。');
  }
  const reason = value.stop_reason;
  if (reason !== 'end_turn' && reason !== 'max_tokens' && reason !== 'tool_use') {
    throw new Error('Anthropic 返回了尚不支持的停止原因。');
  }
  const texts: string[] = [];
  const toolCalls: ToolCall[] = [];
  const ids = new Set<string>();
  for (const block of value.content) {
    if (!isRecord(block)) throw new Error('Anthropic 内容块格式错误。');
    if (block.type === 'text' && typeof block.text === 'string') {
      texts.push(block.text);
    } else if (block.type === 'tool_use' && typeof block.id === 'string' && block.id.trim() &&
               typeof block.name === 'string' && block.name.trim() && isRecord(block.input)) {
      if (ids.has(block.id)) throw new Error('同一消息中的工具请求 ID 重复。');
      ids.add(block.id);
      toolCalls.push({ id: block.id, name: block.name, arguments: JSON.stringify(block.input) });
    } else {
      // 不把无法保存、无法正确反馈的内容悄悄丢掉。
      throw new Error('Anthropic 内容块不在当前文本与工具支持范围内。');
    }
  }
  if ((reason === 'tool_use' && toolCalls.length === 0) ||
      (reason === 'end_turn' && toolCalls.length > 0)) {
    throw new Error('Anthropic 停止原因与工具请求不一致。');
  }
  return {
    role: 'assistant',
    content: texts.join('\n'),
    stopReason: reason === 'tool_use' ? 'toolUse' : reason === 'max_tokens' ? 'length' : 'stop',
    toolCalls,
  };
}

value.content 是服务的内容块数组。函数把文本收集到 texts，把工具块收集到 toolCalls；复制服务给出的 id/name，将对象参数重新序列化成项目要求的字符串。最后创建一条项目 AssistantMessage 返回，不保存记录，也不读取文件。

stop_reason 的字段名和取值由服务定义，stopReason 和 toolUse 是项目内部约定。转换后，Runtime 不需要认识 end_turn 或 tool_use。截断仍保留为 length；如果截断内容连当前支持的块形状都不满足，则属于解码失败，不把残缺动作升级为可执行请求。

重复 ID、停止原因与请求矛盾、未知块或未知停止值都会抛出异常。比如只把思考块删掉再返回其余工具，可能丢掉服务要求后续带回的信息；当前选择明确停止。已有 Runtime 会返回 failed / model，不会执行这次没有成功返回的动作。更细的失败分类在下一篇建设。

连接一次 HTTP 请求 ​

新建 packages/model/src/providers/anthropic.ts。它替应用完成一次服务调用：取得项目上下文，生成发送结构，等待响应，返回刚才解码后的消息。

ts
// 【新增文件】Anthropic Messages API 的非流式文本与工具接入。
import type { Context } from '../types/context';
import type { AssistantMessage } from '../types/messages';
import type { ResolvedCompleteOptions } from '../types/options';
import { encodeAnthropicMessages } from './anthropic-messages';
import { decodeAnthropicMessage } from './anthropic-response';

/** 公开 complete 分发到这里；只取得一次服务响应，循环仍由 Runtime 驱动。 */
export async function completeAnthropic(
  context: Context, options: ResolvedCompleteOptions,
): Promise<AssistantMessage> {
  const response = await (options.fetch ?? globalThis.fetch)('https://api.anthropic.com/v1/messages', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${options.apiKey}`,
      'anthropic-version': '2026-10-21',
    },
    body: JSON.stringify({
      model: options.model,
      system: context.systemPrompt,
      messages: encodeAnthropicMessages(context.messages),
      tools: context.tools?.length ? context.tools.map((tool) => ({
        name: tool.name, description: tool.description, input_schema: tool.parameters,
      })) : undefined,
      stream: false,
      // 当前公共消息没有思考块；选用支持关闭思考的模型，例如 claude-haiku-5-5。
      thinking: { type: 'disabled' },
      max_tokens: options.maxTokens,
    }),
    signal: AbortSignal.timeout(30_000),
  });

  // 不输出请求头和服务错误正文，沿用应用已有的受控异常展示。
  if (!response.ok) throw new Error(`模型服务请求失败（HTTP ${response.status}）。`);
  const value: unknown = await response.json();
  return decodeAnthropicMessage(value);
}

输入仍是同一个 Context。这里 system 是请求的独立字段；messages 使用第三步的编码器；tools 将公共说明中的 parameters 放到 input_schema。工具的 execute 从来没有发送给服务。

按本章采用的 API 版本，密钥放在 Bearer 请求头，版本固定在 anthropic-version；请求结构依据 Messages API。配置示例关闭思考，避免生成当前公共消息无法保存的块。选择不支持此模式的型号可能被服务拒绝，不会自动换型号或换服务。

await 得到的 response 是 HTTP 对象；value 才是读取出的原始 JSON；decodeAnthropicMessage(value) 返回项目消息。30 秒仍只限制这次 HTTP 等待，输出上限仍由 maxTokens 映射为 max_tokens。没有在本篇暗中加入重试或整次任务超时。

图中的服务响应是结构示意。真实调用时服务生成请求值；本地观察时样本文件提供这些值，程序职责相同，证据含义不同。

ts
// 【新增文件】仅供本地协议观察；所有响应从 fixtures 读取，不调用网络。
import { readFile } from 'node:fs/promises';
import type { ModelProvider } from '@ai-harness/model';

/** 检查入口创建并传给 complete；样本耗尽就失败，不回退到真实 fetch。 */
export async function createProtocolFetch(provider: ModelProvider): Promise<typeof globalThis.fetch> {
  const fixture = provider === 'deepseek' ? 'deepseek.json' : 'anthropic.json';
  const samples: unknown = JSON.parse(await readFile(
    new URL(`../../../fixtures/model-protocol/${fixture}`, import.meta.url), 'utf8',
  ));
  if (!Array.isArray(samples)) throw new Error('本地响应材料必须是数组。');
  const endpoint = provider === 'deepseek'
    ? 'https://api.deepseek.com/chat/completions'
    : 'https://api.anthropic.com/v1/messages';
  let index = 0;
  return async (input, init) => {
    if (input !== endpoint || typeof init?.body !== 'string' || index >= samples.length) {
      throw new Error('请求不符合本地协议样本范围；未发送网络请求。');
    }
    // 只观察正文，不打印含 API Key 的请求头。这个入口使用占位密钥。
    console.log(`本地请求正文 ${index + 1}：`, init.body);
    const sample: unknown = samples[index++];
    console.log(`本地原始响应 ${index}：`, JSON.stringify(sample));
    return new Response(JSON.stringify(sample), { headers: { 'Content-Type': 'application/json' } });
  };
}

index 是这个本地传输保存的样本位置，不是 Runtime 的模型调用次数。Response 由本地函数创建，供适配器继续执行 response.json()。日志只打印请求正文和固定响应，不打印请求头；本入口也只提供占位密钥。这个观察工具不属于框架能力，不进入正常 start 接线。

printRun 是停止后遍历历史，所以“模型响应 1”可能出现在两次本地请求日志之后。它不是又调用了一遍模型。同一请求在原始样本、转换后历史与结果关联中多次出现，也不代表多次工具执行。

切到 DeepSeek 本地命令，项目消息角色与 Runtime 行为不变；第二次 HTTP 正文变为 role: 'tool'、tool_call_id，结果中的成功/失败状态编码进文本。应比较同一份项目记录如何转换，不要求两家原始 JSON 相同。

可逆故障：未知响应不能当作回答 ​

import { isRecord } from './validation';

/** 应用提供固定文件位置；返回 ID 到非空文本的映射，不向模型开放文件路径。 */
export async function loadRecords(file: URL): Promise<ReadonlyMap<string, string>> {
  const value: unknown = JSON.parse(await readFile(file, 'utf8'));
  if (!isRecord(value)) {
    throw new Error('记录材料必须是 ID 到文本的对象。');
  }
  const records = new Map<string, string>();
  for (const [id, record] of Object.entries(value)) {
    if (!id.trim() || typeof record !== 'string' || !record.trim()) {
      throw new Error('记录 ID 和内容必须是非空文本。');
    }
    records.set(id, record);
  }
  if (records.size === 0) throw new Error('记录材料不能为空。');
  return records;
}

/** 在实际成功结果中查找指定查询，不把模型自述或失败结果当作证据。 */
function hasQuery(messages: readonly Message[], toolName: string, id: string): boolean {
  return messages.some((message) => {
    if (message.role !== 'toolResult' || message.toolName !== toolName || message.isError) return false;
    try {
      const value: unknown = JSON.parse(message.content);
      return isRecord(value) && value.id === id
        && typeof value.record === 'string' && value.record.trim().length > 0;
    } catch {
      return false;
    }
  });
}

import type { RunResult } from '@ai-harness/runtime';

/** 只展示允许的异常标识；原异常留在 result.error 中供本地断点查看。 */
function describeFailure(error: unknown): string {
  if (!(error instanceof Error)) return '未识别的异常';
  if (/^模型服务请求失败（HTTP \d{3}）。$/.test(error.message)) return error.message;
  const names = new Set(['Error', 'TypeError', 'SyntaxError', 'TimeoutError', 'AbortError']);
  const name = names.has(error.name) ? error.name : 'Error';
  const cause = error.cause;
  const code = cause instanceof Error && 'code' in cause ? cause.code : undefined;
  const codes = new Set(['ECONNRESET', 'ECONNREFUSED', 'ENOTFOUND', 'ETIMEDOUT', 'UND_ERR_CONNECT_TIMEOUT', 'UND_ERR_SOCKET']);
  return typeof code === 'string' && codes.has(code) ? `${name} / ${code}` : name;
}

/** 应用在运行停止后调用；只打印已有记录和受控诊断，不执行模型或工具。 */
export function printRun(result: RunResult): void {
  let responseNumber = 0;
  for (const message of result.messages) {
    if (message.role === 'assistant') {
      responseNumber += 1;
      console.log(`模型响应 ${responseNumber}：`, JSON.stringify(message));
    } else if (message.role === 'toolResult') {
      console.log('本地工具结果：', JSON.stringify(message));
    }
  }
  console.log('运行停止：', result.status, '模型调用次数：', result.modelCalls);
  if (result.status === 'failed') {
    console.error('异常阶段：', result.phase, '异常标识：', describeFailure(result.error));
  }
}

// 受配置清单限制的实际文件读取工具。
import { open } from 'node:fs/promises';
import { ToolExecutionError, type ExecutableTool } from '@ai-harness/runtime';
import type { ReadFileOptions } from './types/read-file';

const MAX_BYTES = 16 * 1024;
const KNOWN_IO_ERRORS = new Set(['ENOENT', 'EACCES', 'EPERM', 'ENOTDIR', 'EISDIR']);

/** 工具内部读取普通文件，最多接收 16 KiB，始终关闭文件句柄。 */
async function readAllowedFile(target: string): Promise<string> {
  try {
    const file = await open(target, 'r');
    try {
      if (!(await file.stat()).isFile()) throw new ToolExecutionError('只允许读取普通文件。');
      const buffer = Buffer.alloc(MAX_BYTES + 1);
      let total = 0;
      while (total < buffer.length) {
        const { bytesRead } = await file.read(buffer, total, buffer.length - total, null);
        if (bytesRead === 0) break;
        total += bytesRead;
      }
      if (total > MAX_BYTES) throw new ToolExecutionError('文件超过 16 KiB，本次未返回内容。');
      return buffer.subarray(0, total).toString('utf8');
    } finally {
      await file.close();
    }
  } catch (error) {
    const code = error instanceof Error && 'code' in error ? error.code : undefined;
    if (typeof code === 'string' && KNOWN_IO_ERRORS.has(code)) {
      throw new ToolExecutionError(`无法读取已配置文件（${code}）。`);
    }
    throw error;
  }
}

/** 应用创建工具；模型只收到说明，Runtime 才能调用 execute。 */
export function createReadFileTool(options: ReadFileOptions): ExecutableTool {
  const files = new Map(Object.entries(options.files));
  return {
    name: 'read_file',
    description: `读取一个已允许的 UTF-8 源码文件。可用路径：${[...files.keys()].join('、')}。`,
    parameters: {
      type: 'object',
      properties: { path: { type: 'string', description: '从可用路径中选择一项。' } },
      required: ['path'],
      additionalProperties: false,
    },
    async execute(value: unknown): Promise<string> {
      if (typeof value !== 'object' || value === null || Array.isArray(value)
        || !('path' in value) || typeof value.path !== 'string'
        || Object.keys(value).length !== 1) {
        throw new ToolExecutionError('参数必须是只包含字符串 path 的对象。');
      }
      const target = files.get(value.path);
      if (target === undefined) throw new ToolExecutionError('该路径不在应用允许的文件清单中。');
      const source = await readAllowedFile(target);
      return `${value.path}\n${source}`;
    },
  };
}

// 【新增文件】把项目历史转换为 Anthropic 的消息块。
import type { Message } from '../types/messages';
import type { AnthropicMessage, AnthropicTextBlock, AnthropicToolUseBlock } from '../types/anthropic';
import { isRecord } from '../validation';

/** completeAnthropic 调用；创建发送用数组，原记录仍由 Runtime 保存。 */
export function encodeAnthropicMessages(messages: readonly Message[]): AnthropicMessage[] {
  const encoded: AnthropicMessage[] = [];
  let previousRole: Message['role'] | undefined;
  for (const message of messages) {
    const followsResult = previousRole === 'toolResult';
    previousRole = message.role;
    if (message.role === 'user') {
      encoded.push({ role: 'user', content: [{ type: 'text', text: message.content }] });
      continue;
    }
    if (message.role === 'toolResult') {
      const block = {
        type: 'tool_result' as const,
        tool_use_id: message.toolCallId,
        content: message.content,
        is_error: message.isError,
      };
      const previous = encoded.at(-1);

      // 同一批连续结果合并到一个 user 消息，紧接原 assistant 请求。
      if (previous?.role === 'user' && followsResult) {
        previous.content.push(block);
      } else {
        encoded.push({ role: 'user', content: [block] });
      }
      continue;
    }
    const content: (AnthropicTextBlock | AnthropicToolUseBlock)[] = [];
    if (message.content) content.push({ type: 'text', text: message.content });
    for (const call of message.toolCalls) {
      const input: unknown = JSON.parse(call.arguments);
      if (!isRecord(input)) throw new Error('Anthropic 历史工具参数必须是 JSON 对象。');
      content.push({ type: 'tool_use', id: call.id, name: call.name, input });
    }
    encoded.push({ role: 'assistant', content });
  }
  return encoded;
}

import type { AssistantMessage } from '../types/messages';
import type { ToolCall } from '../types/tools';
import { isRecord } from '../validation';

/** completeAnthropic 传入 response.json() 的未知值；不执行或保存请求。 */
export function decodeAnthropicMessage(value: unknown): AssistantMessage {
  if (!isRecord(value) || value.role !== 'assistant' || !Array.isArray(value.content)) {
    throw new Error('Anthropic 响应缺少可识别的 assistant 内容。');
  }
  const reason = value.stop_reason;
  if (reason !== 'end_turn' && reason !== 'max_tokens' && reason !== 'tool_use') {
    throw new Error('Anthropic 返回了尚不支持的停止原因。');
  }
  const texts: string[] = [];
  const toolCalls: ToolCall[] = [];
  const ids = new Set<string>();
  for (const block of value.content) {
    if (!isRecord(block)) throw new Error('Anthropic 内容块格式错误。');
    if (block.type === 'text' && typeof block.text === 'string') {
      texts.push(block.text);
    } else if (block.type === 'tool_use' && typeof block.id === 'string' && block.id.trim() &&
               typeof block.name === 'string' && block.name.trim() && isRecord(block.input)) {
      if (ids.has(block.id)) throw new Error('同一消息中的工具请求 ID 重复。');
      ids.add(block.id);
      toolCalls.push({ id: block.id, name: block.name, arguments: JSON.stringify(block.input) });
    } else {
      // 不把无法保存、无法正确反馈的内容悄悄丢掉。
      throw new Error('Anthropic 内容块不在当前文本与工具支持范围内。');
    }
  }
  if ((reason === 'tool_use' && toolCalls.length === 0) ||
      (reason === 'end_turn' && toolCalls.length > 0)) {
    throw new Error('Anthropic 停止原因与工具请求不一致。');
  }
  return {
    role: 'assistant',
    content: texts.join('\n'),
    stopReason: reason === 'tool_use' ? 'toolUse' : reason === 'max_tokens' ? 'length' : 'stop',
    toolCalls,
  };
}

ts
// 执行一条模型消息内的工具请求，不请求模型、不修改历史。
import type { AssistantMessage, ToolResultMessage } from '@ai-harness/model';
import type { ExecutableTool } from './types/tools';
import { ToolExecutionError } from './tool-error';

/** 应用调用；整批按顺序完成后返回结果，应用再保存并请求模型。 */
export async function executeTools(
  message: AssistantMessage,
  tools: readonly ExecutableTool[],
): Promise<ToolResultMessage[]> {
  if (message.stopReason !== 'toolUse' || message.toolCalls.length === 0) {
    throw new Error('只执行完整的 toolUse 消息。');
  }

  // 在任何执行之前检查歧义；不会执行前几项才发现后面 ID 重复。
  const registry = new Map(tools.map((tool) => [tool.name, tool]));
  if (registry.size !== tools.length) throw new Error('本地工具名称不能重复。');
  const ids = message.toolCalls.map((call) => call.id);
  if (ids.some((id) => !id.trim()) || new Set(ids).size !== ids.length) {
    throw new Error('本批请求 ID 为空或重复。');
  }

  const results: ToolResultMessage[] = [];
  for (const call of message.toolCalls) {
    let content: string;
    let isError = false;
    try {
      const tool = registry.get(call.name);
      if (!tool) throw new ToolExecutionError('没有注册该工具。');

      let argumentsValue: unknown;
      try {
        argumentsValue = JSON.parse(call.arguments);
      } catch {
        throw new ToolExecutionError('工具参数不是合法 JSON，请重新生成。');
      }
      content = await tool.execute(argumentsValue);
      if (typeof content !== 'string') throw new Error('工具没有返回文本。');
    } catch (error) {
      // 只反馈明确归类的失败，避免把程序缺陷或敏感异常正文发送给模型。
      if (!(error instanceof ToolExecutionError)) throw error;
      content = error.message;
      isError = true;
    }
    results.push({
      role: 'toolResult', toolCallId: call.id, toolName: call.name, content, isError,
    });
  }
  return results;
}

// Runtime 持有本次历史，自动衔接模型决定与工具反馈。
import type { AssistantMessage } from '@ai-harness/model';
import type { RunAgentOptions, RunResult } from './types/run';
import { executeTools } from './execute-tools';

/** 应用调用一次；返回明确的停止结果，不把模型停止等同于任务验收通过。 */
export async function runAgent(options: RunAgentOptions): Promise<RunResult> {
  if (!Number.isSafeInteger(options.maxModelCalls) || options.maxModelCalls < 1) {
    throw new Error('maxModelCalls 必须为正安全整数。');
  }
  if (options.messages.length === 0) throw new Error('初始消息不能为空。');

  // 复制数组，由 Runtime 独占本次追加权；不深拷贝或冻结消息对象。
  const messages = [...options.messages];
  const definitions = options.tools.map(({ name, description, parameters }) => ({
    name, description, parameters,
  }));
  let modelCalls = 0;

  while (modelCalls < options.maxModelCalls) {
    modelCalls += 1;
    let message: AssistantMessage;
    try {
      // 每次使用最新记录；给调用方单独的数组，不暴露工具执行函数。
      message = await options.callModel({
        systemPrompt: options.systemPrompt,
        messages: [...messages],
        tools: definitions,
      });
    } catch (error) {
      return { status: 'failed', phase: 'model', error, messages, modelCalls };
    }
    messages.push(message);

    // 截断的动作参数不能执行；空文本也不能当作有效回答。
    if (message.stopReason === 'length') {
      return { status: 'truncated', messages, modelCalls };
    }
    if (message.stopReason === 'stop') {
      if (!message.content.trim()) return { status: 'emptyAnswer', messages, modelCalls };
      return { status: 'answered', answer: message, messages, modelCalls };
    }

    // 最后一次仍请求动作：记录请求，但不执行无法再反馈给模型的批次。
    if (modelCalls === options.maxModelCalls) {
      return { status: 'callLimit', messages, modelCalls };
    }
    try {
      const results = await executeTools(message, options.tools);
      messages.push(...results);
    } catch (error) {
      return { status: 'failed', phase: 'tools', error, messages, modelCalls };
    }
    // 不需要手写第二次调用；回到循环顶部，再带着完整反馈请求模型。
  }
  throw new Error('运行计数异常。');
}
