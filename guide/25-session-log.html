25 让 Coding Agent 退出后仍能查到会话 ​

第 23 篇能在同一个 CLI 进程里接续追问。关掉进程后，完整消息和停止原因就只能靠终端输出回查。本篇给同一个 CLI 加一个可选的会话日志，先保存已经发生的事实，为下一步恢复执行打基础。

本篇在 Agent 的什么位置 ​

第五阶段「可靠执行与恢复」从会话记录开始。每段 Agent 循环结束，Runtime 返回结果，CLI 在接续追问或生成交付报告之前写盘。

本篇技术方案 ​

实施前，先走完一次具体过程 ​

  1. 用户提交路径修复任务和一条追问，并用 --session-log 指定一个新文件。CLI 准备副本后，把版本和副本路径写入首行。
  2. 第一段修复并验收，Runtime 返回 11 条历史。CLI 把这 11 条连同运行 ID、停止状态一起写入第二行，再开始追问。
  3. 追问结束，Runtime 返回 13 条累计历史。前 11 条已经保存，CLI 只追加用户追问和模型回答。退出后，用另一个进程读取这三行。

实现架构图 ​

每行各自是一份 JSON，这种格式叫 JSONL。验收时找三个数字：版本 1、首段新增 11 条、追问段新增 2 条。交付仍看实际验收。日志含任务和工具反馈原文，选择本地私有目录保存。本篇只在运行段返回后写盘，段内突然退出时，磁盘上只有此前已写的记录。

安装项目依赖后，在仓库根目录运行。它只写一个临时文件，使用人工记录，不启动模型。

本篇核心代码在哪 ​

看 apps/coding-cli/src/main.ts 的 runCli。首段传 0，第二段传 first.messages.length。再看 apps/coding-cli/src/session/session-log.ts 的 appendRun，其中 result.messages.slice(start) 取出尚未保存的那段历史。这两处决定什么时候写，以及写哪几条。

第一步：一行保存一段运行 ​

新建 apps/coding-cli/src/session/session-log.ts。它负责两件事：任务开始时创建日志，Runtime 每返回一段结果时追加一条记录。先展开完整实现一次写入，再跟着三个小节读代码。

完整实现 session/session-log.ts
ts
// 【新增文件】由 CLI 保存已返回的运行结果。
import { constants } from 'node:fs';
import { appendFile, writeFile } from 'node:fs/promises';
import { resolve } from 'node:path';
import type { RunResult } from '@ai-harness/runtime';

/** 写入首行并返回绝对路径。已有文件由 wx 拒绝覆盖。 */
export async function createSessionLog(file: string, workspace: string): Promise<string> {
  const path = resolve(file);
  const header = { type: 'session', version: 1, workspace };
  await writeFile(path, JSON.stringify(header) + '\n', { flag: 'wx', mode: 0o600 });
  return path;
}

/**
 * 写入一段已结束的运行。
 * @param start 已记录的历史条数。首段为 0，追问段从首段历史末尾开始。
 */
export async function appendRun(path: string, result: RunResult, start: number): Promise<void> {
  const entry = {
    type: 'run',
    runId: result.runId,
    status: result.status,
    modelCalls: result.modelCalls,
    toolCalls: result.toolCalls,
    messages: result.messages.slice(start),
  };
  await appendFile(path, JSON.stringify(entry) + '\n', { flag: constants.O_WRONLY | constants.O_APPEND });
}

1.1 首行记录这是谁的会话 ​

在这个文件的 createSessionLog 中，file 来自终端的 --session-log，workspace 来自 CLI 已准备好的工作副本。假设传入 ./session.jsonl，resolve(file) 会把它转成相对终端当前目录的绝对路径。

ts
  const path = resolve(file);
  const header = { type: 'session', version: 1, workspace };
  await writeFile(path, JSON.stringify(header) + '\n', { flag: 'wx', mode: 0o600 });
  return path;

header 描述整个日志。type: 'session' 让读取方知道这一行是头部，version: 1 标记文件格式，workspace 指向这次使用的副本。JSON.stringify(header) 把对象变成一行文本，加上的 '\n' 让下一条记录从新的一行开始。等待写入成功后，CLI 接住返回的 path，后面的两段都用它追加。

wx 要求目标是新文件，同名文件已存在就报错。初始权限用 0o600，因为记录会包含任务和工具反馈原文。

1.2 一段运行变成一条记录 ​

在同一文件的 appendRun 中，result 是 Runtime 返回给 CLI 的一段完整结果，start 由调用方传入，表示日志里已经写过几条历史消息。先看函数怎样挑出要落盘的字段。

ts
  const entry = {
    type: 'run',
    runId: result.runId,
    status: result.status,
    modelCalls: result.modelCalls,
    toolCalls: result.toolCalls,
    messages: result.messages.slice(start),
  };

entry 的运行 ID、停止状态和调用计数都属于当前这一段。只有 messages 要按下标截取，因为 Runtime 返回的历史会累积。以本篇固定示例为例：

哪一段刚结束Runtime 返回的 result.messagesCLI 传的 start本行实际保存
首段修复共 11 条，包含任务、工具请求和反馈、首段回答0下标 0 到 10，共 11 条
追问段共 13 条，前 11 条与首段一致first.messages.length，也就是 11下标 11 的用户追问和下标 12 的模型回答

slice(11) 从下标 11 开始复制到数组末尾。它只改变写进日志的那份数组，Runtime 返回的 13 条历史仍然完整。比如首段的 check_complete 工具反馈仍可在文件的首段记录中查到。

1.3 把这一条追加到文件末尾 ​

appendRun 组装完 entry 后，最后一行把对象转成 JSON 文本，并补一个换行。

ts
  await appendFile(path, JSON.stringify(entry) + '\n', { flag: constants.O_WRONLY | constants.O_APPEND });

O_WRONLY 以只写方式打开，O_APPEND 让本次写入从文件末尾开始。这里没有创建标志，日志如果被移走，追加会失败，CLI 就能知道原会话文件已经不在了。两段都写完后，文件依次是「会话头 → 首段记录 → 追问段记录」。第四步的读取脚本会逐行解析这三条记录。

读到这里可以先停一下。 如果追问段改成传 start = 0，第二条运行记录会写入 13 条消息，其中前 11 条会重复。这就是第三步传入首段长度的原因。

完整文件 config/args.ts
ts
// 只处理终端参数，不读取环境或启动任务。
import type { CliOptions } from '../types/task';

export const helpText = `用法：ai-harness --task <任务.json> [--plan] [--follow-up <问题>] [--session-log <文件>]
任务路径相对当前终端目录；配置内路径相对任务文件目录。
--plan 开启实验性计划；--follow-up 在首次回答后追加一条问题。
--session-log 保存本次会话到一个新文件。
--help 只显示帮助。
退出码：0已接受，1未接受，2参数/准备/报告失败，130主动取消。`;

/** main传入argv，不接受未知、重复或缺值选项。 */
export function parseArgs(args: readonly string[]): CliOptions {
  if (args.length === 1 && args[0] === '--help') {
    return { help: true };
  }
  let taskFile: string | undefined;
  let planning = false;
  let followUp: string | undefined;
  let sessionLog: string | undefined;
  for (let i = 0; i < args.length; i += 1) {
    const arg = args[i];
    if (arg === '--plan' && !planning) {
      planning = true;
    } else if (arg === '--follow-up' && followUp === undefined) {
      // 读取一条用户追问。引号由终端处理。
      const value = args[++i]?.trim();
      if (!value || value.startsWith('--')) {
        throw new Error('追问内容缺失。');
      }
      followUp = value;
    } else if (arg === '--session-log' && sessionLog === undefined) {
      // 【新增】文件路径相对启动 CLI 时的工作目录。
      const value = args[++i];
      if (!value?.trim() || value.startsWith('--')) {
        throw new Error('会话记录路径缺失。');
      }
      sessionLog = value;
    } else if (arg === '--task' && taskFile === undefined) {
      const value = args[++i];
      if (!value?.trim() || value.startsWith('--')) {
        throw new Error('任务路径缺失。');
      }
      taskFile = value;
    } else {
      throw new Error('参数无效。');
    }
  }
  if (!taskFile) {
    throw new Error('需要任务配置。');
  }
  return {
    help: false,
    taskFile,
    planning,
    ...(followUp ? { followUp } : {}),
    ...(sessionLog ? { sessionLog } : {}),
  };
}

在 runCli 的追问分支里，first.messages 有 11 条。先展开它，再追加追问，nextInput.messages 变成 12 条。第二次 runSession 完成回答后，result.messages 变成 13 条。调用 appendRun 时仍传入首段长度 11，因此日志最后一行仅包含下标 11、12。若首段 appendRun 抛错，执行会在进入追问分支前跳到 catch，第二次 runSession 尚未开始。

完整文件 main.ts
ts
// 应用生命周期：参数→配置→副本→运行→报告→释放监听。
import type { RunInputOptions } from './types/task';
import type { ModelCall, RunEventListener } from '@ai-harness/runtime';
import { parseArgs, helpText } from './config/args';
import { loadTask } from './config/task';
import { createModelCall } from './model';
import { prepareSession } from './session/prepare';
import { appendRun, createSessionLog } from './session/session-log';
import { runSession } from './session/run';
import { reportSession } from './report/report';
import { printProgress, printBlock } from './report/terminal';
import type { CliSession } from './types/session';

/** CLI 接收退出码。观察入口可注入模型，并开启全量历史对照。 */
export async function runCli(
  args: readonly string[],
  createCallModel: () => ModelCall = createModelCall,
  fullHistory = false,
): Promise<number> {
  const controller = new AbortController();
  const onInterrupt = () => {
    if (!controller.signal.aborted) {
      console.log('请求取消，等待当前协作操作退出。');
      controller.abort();
    }
  };
  let session: CliSession | undefined;
  let phase = '参数';
  process.on('SIGINT', onInterrupt);

  try {
    const options = parseArgs(args);
    if (options.help) {
      console.log(helpText);
      return 0;
    }

    phase = '任务配置';
    const task = await loadTask(options.taskFile, controller.signal);

    phase = '模型配置';
    const callModel = createCallModel();

    phase = '副本准备';
    session = await prepareSession(task, options.planning, controller.signal);
    printBlock('工作副本', session.root);

    // 【新增】先独占创建文件，防止两次 CLI 运行混写。
    let logPath: string | undefined;
    if (options.sessionLog) {
      phase = '会话记录';
      logPath = await createSessionLog(options.sessionLog, session.root);
    }

    phase = '运行与报告';
    const onEvent: RunEventListener = (event) => {
      printProgress(event);
      if (
        event.type === 'tool_end' &&
        event.toolName === 'update_plan' &&
        !event.isError &&
        session?.plan
      ) {
        printBlock('任务计划（模型声明）', session.plan.read());
      }
    };

    const first = await runSession(task, session, callModel, controller.signal, onEvent, { fullHistory });
    // 【新增】首段落盘之后才启动追问。
    if (logPath) {
      phase = '会话记录';
      await appendRun(logPath, first, 0);
      phase = '运行与报告';
    }
    let result = first;

    // 沿用已经准备的副本和工具，只给 Runtime 一个新的历史起点。
    if (options.followUp && first.status === 'answered' && !controller.signal.aborted) {
      printBlock('首段停止', {
        status: first.status,
        modelCalls: first.modelCalls,
        toolCalls: first.toolCalls,
        runId: first.runId,
      });
      const nextInput: RunInputOptions = {
        messages: [...first.messages, { role: 'user', content: options.followUp }],
        fullHistory,
      };
      result = await runSession(task, session, callModel, controller.signal, onEvent, nextInput);
      if (logPath) {
        phase = '会话记录';
        await appendRun(logPath, result, first.messages.length);
        phase = '运行与报告';
      }
    }

    return await reportSession(task, session, result);
  } catch {
    if (controller.signal.aborted) {
      return 130;
    }

    // 原异常留在调试器，不打印凭据、响应正文或整个请求。
    console.error(`${phase}失败；请检查配置或在对应函数断点查看原异常。`);
    return 2;
  } finally {
    process.off('SIGINT', onInterrupt);
    if (session) {
      console.log('工作副本保留在：', session.root);
    }
  }
}

// 【新增文件】固定模型执行路径修复和追问，退出后可查看日志。
import { runCli } from '../../apps/coding-cli/src/main';
import { createSample } from '../input-budget/sample-model';

const file = process.argv[2];
if (!file) {
  throw new Error('请提供会话日志文件路径。');
}
const question = '最后一次实际验收结果是什么？';

process.exitCode = await runCli(
  ['--task', 'fixtures/code-tasks/route.json', '--follow-up', question, '--session-log', file],
  () => {
    const sample = createSample();
    return (context, onDelta, signal) => {
      if (!context.messages.some((message) => message.role === 'user' && message.content === question)) {
        return sample(context, onDelta, signal);
      }

      const check = context.messages.find((message) =>
        message.role === 'toolResult' && message.toolCallId === 'check_complete',
      );
      if (!check || JSON.parse(check.content).status !== 'passed') {
        throw new Error('追问缺少实际验收反馈。');
      }
      return Promise.resolve({
        role: 'assistant',
        content: '最后一次验收通过，依据是 check_complete。',
        stopReason: 'stop',
        toolCalls: [],
      });
    };
  },

// 【新增文件】在另一个进程里查看每行记录的概要。
import { readFile } from 'node:fs/promises';

const path = process.argv[2];
if (!path) {
  throw new Error('请提供会话日志文件路径。');
}

const lines = (await readFile(path, 'utf8')).trimEnd().split('\n');
for (const line of lines) {
  const entry = JSON.parse(line);
  if (entry.type === 'session') {
    console.log('会话版本', entry.version);
  } else if (entry.type === 'run') {
    console.log('运行', entry.status, '新增消息', entry.messages.length);
  }
}
