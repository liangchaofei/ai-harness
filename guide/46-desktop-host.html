第 46 篇：让桌面窗口运行和取消同一个代码任务 ​

第 45 篇让两个宿主共享 createCodeTaskRunner。本篇加上可打开的 Electron 窗口。点击「运行任务」会修改临时副本中的总价函数、执行实际验收，并把运行进度和交付结果显示在窗口里。点击「取消」或关闭窗口，也会走同一条任务取消链路。

第一次阅读，先追一遍「运行任务」，再看第二步的 task:start 和第三步的 runner.run。若已检出本篇，可从仓库根目录执行 npm run desktop:start。图解可点开看原图。

本篇技术方案 ​

Electron 的主进程可以使用 Node API，负责准备任务、调用 Harness 和清理副本。渲染进程负责页面显示。两者用 IPC，也就是进程间消息来通信。preload 是窗口加载页面前执行的桥接脚本，它只公开这个页面需要的三个操作。

实施前，先走完一次具体过程 ​

  1. 用户在窗口点击「运行任务」。renderer.js 调用 window.task.start()。preload 把它转成固定的 task:start 请求。
  2. 主进程检查请求是否来自本地页面的顶层帧，也检查当前没有运行中的任务。它创建取消控制器和临时 total.mjs，再用与 CLI 共用的 createCodeTaskRunner 执行。
  3. 固定模型先提交真实替换，将加法改成乘法。主进程从 Runtime 事件里选出阶段和序号，推送到窗口。下一轮执行可信验收，最后用共享 runner 核对当前副本，页面显示 total.mjs、验收通过和「已接受」。
  4. 若在「修改文件完成」后点击取消，preload 调用固定的 task:cancel。主进程退出等待并审阅已有改动，页面显示「已取消」和改动文件，验收栏为「无」。关窗时，主进程也先发出取消，等任务清理后退出。

本篇关键位置在 apps/desktop/src/main.ts 的两个 IPC 处理器，以及 apps/desktop/src/run-total-task.ts 的 runner.run。 前一处确认谁能开始或取消，后一处产生真正的执行和验收证据。

本章使用固定模型响应和真实文件操作来验证桌面接线。任务路径、验收文件和模型入口由主进程决定。界面不能提交任意程序、目录或模型参数。真实模型配置、用户选择任务、交互式批准和历史会话留待后续接入。 Electron 进程间通信 · Electron 渲染器沙箱 · Electron IPC 发送方校验

Pi 的 RPC 模式订阅会话事件并交给外部宿主。本篇同样将运行放在有执行能力的一侧，再让界面通过受限的请求和事件消费它。 Pi 固定版本的 RPC 模式

第二步：让窗口只能申请固定的操作 ​

新建 apps/desktop/src/main.ts。主进程持有当前窗口及运行中的任务。它接收开始和取消请求，将阶段摘要送回发起调用的窗口，并在退出前等待活动任务完成清理。

ts
// 【新增文件】创建窗口，在主进程持有任务与取消控制器。
import { app, BrowserWindow, ipcMain, type IpcMainInvokeEvent } from 'electron';
import { fileURLToPath } from 'node:url';
import { runTotalTask } from './run-total-task';
import type { DesktopTaskResult } from './types/task';

const page = new URL('../ui/index.html', import.meta.url);
let window: BrowserWindow | undefined;
let active: { controller: AbortController; completed: Promise<DesktopTaskResult> } | undefined;
let waitingToQuit = false;

/** 只接受当前窗口中可信本地页面的顶层帧。 */
function verifySender(event: IpcMainInvokeEvent): void {
  if (!window || event.sender !== window.webContents ||
      event.senderFrame !== window.webContents.mainFrame || event.senderFrame.url !== page.href) {
    throw new Error('请求来源无效。');
  }
}

ipcMain.handle('task:start', async (event) => {
  verifySender(event);
  if (active) {
    throw new Error('已有任务在运行。');
  }

  const sender = event.sender;
  const controller = new AbortController();
  const completed = runTotalTask(controller.signal, (update) => {
    if (!sender.isDestroyed()) {
      sender.send('task:progress', update);
    }
  });
  active = { controller, completed };
  try {
    return await completed;
  } catch (error) {
    console.error(error);
    throw new Error(controller.signal.aborted ? '任务准备已取消。' : '任务运行失败，请查看主进程日志。');
  } finally {
    active = undefined;
  }
});

ipcMain.handle('task:cancel', (event) => {
  verifySender(event);
  active?.controller.abort();
});

app.on('before-quit', (event) => {
  if (!active) {
    return;
  }
  event.preventDefault();
  if (!waitingToQuit) {
    waitingToQuit = true;
    active.controller.abort();
    void active.completed.then(() => app.quit(), () => app.quit());
  }
});

app.on('window-all-closed', () => app.quit());

void app.whenReady().then(async () => {
  window = new BrowserWindow({
    width: 900,
    height: 680,
    minWidth: 360,
    minHeight: 540,
    title: 'AI Harness',
    webPreferences: {
      preload: fileURLToPath(new URL('../preload.cjs', import.meta.url)),
      contextIsolation: true,
      nodeIntegration: false,
      sandbox: true,
    },
  });
  window.on('closed', () => {
    window = undefined;
  });
  window.webContents.on('will-navigate', (event) => event.preventDefault());
  window.webContents.setWindowOpenHandler(() => ({ action: 'deny' }));
  await window.loadFile(fileURLToPath(page));
}).catch((error) => {
  console.error(error);
  app.quit();
});

当已有运行时，主进程直接拒绝再次调用。这项限制在主进程实现，即使有人绕开按钮禁用，也不能并发开始。取消处理器只调用当前控制器的 abort()。应用退出时先触发相同信号，等待活动任务完成清理后才发起下一次退出。

新建 apps/desktop/preload.cjs。它定义页面的 window.task，将两个操作映射到固定通道，并支持订阅、取消订阅进度。

cjs
// 【新增文件】给页面公开固定操作，并省略 IPC 事件对象。
const { contextBridge, ipcRenderer } = require('electron');

contextBridge.exposeInMainWorld('task', {
  start: () => ipcRenderer.invoke('task:start'),
  cancel: () => ipcRenderer.invoke('task:cancel'),
  onProgress(callback) {
    const listener = (_event, update) => callback(update);
    ipcRenderer.on('task:progress', listener);
    return () => ipcRenderer.removeListener('task:progress', listener);
  },
});

在 onProgress 中，只把 update 给页面，IPC 的事件对象留在桥接侧。这样页面可以展示数据，同时不会取得发送方或通用 IPC 能力。 Electron contextBridge

第三步：由主进程运行并投影证据 ​

新建 apps/desktop/src/types/task.ts。它定义可以跨边界发送的阶段摘要和最终业务结果。不会携带整个 Runtime 消息或工作副本的绝对路径。

ts
// 【新增文件】主进程允许传给桌面视图的数据。
import type { RunResult } from '@ai-harness/harness';

/** 每次运行返回的简短结果，由主进程从验收证据提取。 */
export interface DesktopTaskResult {
  /** Runtime 停止原因，例如 answered 或 cancelled。 */
  status: RunResult['status'];
  /** 当前副本的匹配验收标记。 */
  checkMatchesCurrent: boolean;
  /** 是否有当前内容上的成功验收退出码。 */
  checkPassed: boolean;
  /** 与 Coding CLI 共用的交付判定。 */
  accepted: boolean;
  /** 仅展示相对文件名。 */
  changedFiles: string[];
}

/** 实时事件只保留阶段与顺序，不发送 Runtime 消息。 */
export interface DesktopTaskEvent {
  /** 同一运行内的顺序，可跨过未投影事件。 */
  sequence: number;
  /** 可以展示的阶段摘要。 */
  label: string;
}

新建 apps/desktop/src/run-total-task.ts。它负责准备可信的固定任务，从 npm 启动环境取得用于验收的 Node 程序，并用上一章的公开 runner 运行、观察、审阅和清理。

ts
// 【新增文件】主进程执行一份可信的总价修复任务。
import { mkdtemp, rm, writeFile } from 'node:fs/promises';
import { tmpdir } from 'node:os';
import { isAbsolute, join } from 'node:path';
import { setTimeout as delay } from 'node:timers/promises';
import { fileURLToPath } from 'node:url';
import { createCodeTaskRunner, createCodeTaskSession, type ModelCall } from '@ai-harness/harness';
import type { DesktopTaskEvent, DesktopTaskResult } from './types/task';

const checkScript = fileURLToPath(new URL('../check-total.mjs', import.meta.url));

/** 运行器使用真实编辑和验收。固定模型让页面交互可以稳定复现。 */
export async function runTotalTask(
  signal: AbortSignal,
  publish: (event: DesktopTaskEvent) => void,
): Promise<DesktopTaskResult> {
  const node = process.env.npm_node_execpath;
  if (!node || !isAbsolute(node)) {
    throw new Error('请通过 npm run desktop:start 启动应用。');
  }

  const root = await mkdtemp(join(tmpdir(), 'ai-harness-desktop-'));
  const writablePaths = ['total.mjs'];
  try {
    await writeFile(join(root, 'total.mjs'), 'export const total = (price, count) => price + count;\n');
    const session = await createCodeTaskSession({
      root,
      writablePaths,
      extensions: ['.mjs'],
      check: { executable: node, args: [checkScript, root] },
    }, signal);
    const runner = createCodeTaskRunner(session, writablePaths);
    let turn = 0;
    const callModel: ModelCall = async (_context, _delta, modelSignal) => {
      turn += 1;
      if (turn === 1) {
        return request('edit-total', 'replace_text', {
          path: 'total.mjs', oldText: 'price + count', newText: 'price * count',
        });
      }
      if (turn === 2) {
        // 固定响应留出可操作的取消窗口，不延迟真实模型。
        await delay(1_200, undefined, { signal: modelSignal });
        return request('check-total', 'run_check', {});
      }
      return { role: 'assistant', content: '请查看验收结果。', stopReason: 'stop', toolCalls: [] };
    };

    const result = await runner.run({
      messages: [{ role: 'user', content: '将总价修复为单价乘以数量。' }],
      callModel,
      signal,
      maxModelCalls: 4,
      maxToolCalls: 3,
      timeoutMs: 10_000,
      onEvent(event) {
        if (event.type === 'model_start') {
          publish({ sequence: event.sequence, label: `模型调用 ${event.modelCall}` });
        } else if (event.type === 'tool_end') {
          const verb = event.toolName === 'replace_text' ? '修改文件' : '执行验收';
          publish({ sequence: event.sequence, label: `${verb}${event.isError ? '失败' : '完成'}` });
        }
      },
    });
    // 运行取消后，仍可独立审阅已经完成的文件副作用。
    const { review, accepted } = await runner.review(result);
    return {
      status: result.status,
      checkMatchesCurrent: review.checkMatchesCurrent,
      checkPassed: review.checkMatchesCurrent && review.lastCheck?.status === 'passed' &&
        review.lastCheck.exitCode === 0,
      accepted,
      changedFiles: review.changes.map(({ path }) => path),
    };
  } finally {
    await rm(root, { recursive: true, force: true });
  }
}

/** 使用与真实模型相同的工具请求契约。 */
function request(id: string, name: string, args: Record<string, unknown>) {
  return {
    role: 'assistant',
    content: '',
    stopReason: 'toolUse',
    toolCalls: [{ id, name, arguments: JSON.stringify(args) }],
  } as const;
}

例如工具结束事件会被转换成「修改文件完成」或「执行验收完成」。这是相应工具调用已经写回结果的进度，最终是否交付还要等 runner.review。返回给页面的结果区分「是否有匹配当前内容的验收」和「该验收是否成功」。取消发生在修改后时，仍进行一次独立审阅，所以页面能看到已经修改的文件。

js
// 【新增文件】渲染层只展示通过 preload 收到的任务数据。
const start = document.querySelector('#start');
const cancel = document.querySelector('#cancel');
const progress = document.querySelector('#progress');
const status = document.querySelector('#status');
const changes = document.querySelector('#changes');
const check = document.querySelector('#check');

const unsubscribe = window.task.onProgress(({ sequence, label }) => {
  const row = document.createElement('li');
  row.textContent = `#${sequence} ${label}`;
  progress.append(row);
});
window.addEventListener('pagehide', unsubscribe, { once: true });

start.addEventListener('click', async () => {
  start.disabled = true;
  cancel.disabled = false;
  progress.replaceChildren();
  status.textContent = '运行中';
  changes.textContent = '—';
  check.textContent = '—';
  try {
    const result = await window.task.start();
    status.textContent = result.status === 'cancelled'
      ? '已取消'
      : result.accepted ? '已接受' : '未接受';
    changes.textContent = result.changedFiles.join('、') || '无改动';
    check.textContent = !result.checkMatchesCurrent ? '无' : result.checkPassed ? '通过' : '失败';
  } catch (error) {
    status.textContent = error.message;
  } finally {
    start.disabled = false;
    cancel.disabled = true;
  }
});

cancel.addEventListener('click', async () => {
  cancel.disabled = true;
  status.textContent = '正在取消';
  try {
    await window.task.cancel();
  } catch (error) {
    status.textContent = error.message;
  }
});

在 renderer.js，点击运行后清空上一轮状态并等待 window.task.start()。进度来自独立订阅，可在最终结果返回前显示。取消按钮先显示「正在取消」，收到主进程的结果后才显示「已取消」。用户关闭窗口时页面取消订阅，任务清理仍由主进程完成。

运行与验收 ​

在仓库根目录执行。窗口以固定模型运行，使用真实编辑和验收工具，无需配置模型密钥。

bash
npm install
npm run desktop:start
操作应观察到的证据
运行任务并等待结束进度出现「修改文件完成」和「执行验收完成」，结果为「已接受」，文件为 total.mjs。
修改后立即点击取消结果为「已取消」，仍有 total.mjs，验收为「无」。
修改后直接关闭窗口应用取消活动任务、清理临时副本后退出。
从页面尝试连续调用两次开始第一项继续运行，主进程拒绝第二项。

调试时，先在主进程 verifySender 查看窗口、顶层帧和 URL，再到 runTotalTask 的 onEvent 与 runner.review 检查数据怎样改变。修改过的文件属于本次临时副本，结束时会被清理。若窗口启动时看到 Electron 模块的动态 require 错误，检查桌面构建命令是否保留了 --external electron。
