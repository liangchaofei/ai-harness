从零建设 Agent 系统从原理走向可复用框架

用 TypeScript 亲手实现 Agent Runtime 与 Harness，再让命令行和桌面 Coding Agent 使用同一个底座。

开始第01篇
了解学习方式

理解系统

用具体任务、数据和图解说明每项机制的位置，以及它为什么需要存在。

逐步实现

分步讲解关键代码，观察运行与故障，再用不同任务检验复用。

建设框架

分离通用内核、能力接入与应用，逐步建立恢复、安全、观察和评估能力。

课程面向具备 TypeScript、Node.js 和一般应用开发经验的 Agent 初学者。

基础闭环只是起点。最终工程目标是可独立消费的框架包，以及通过公开接口使用它的命令行与桌面 Coding Agent。学习过程中会区分当前已实现的能力、实验策略与后续建设内容。

已提供第01篇：从包入口发起一次模型调用、第02篇：让模型提出工具请求和第03篇：执行工具，把结果交回模型。第04篇：让 Runtime 自动继续与停止进一步建立带调用上限的自动循环，应用通过函数注入模型接入。第05篇：换任务，检验同一个运行内核接入第二个独立任务，收敛第一阶段内容。第06篇：模型适配，换服务并保留同一个 Runtime进入第二阶段，提供无需第二家 Key 的本地协议观察；随后继续建设实时事件、流式输出和运行控制。

第07篇：工具准入与可判断的失败把声明的参数规则接到实际执行之前，区分可反馈的工具失败与必须停止的异常，保留此前已经完成的结果。

第08篇：运行事件与实时进度让应用在模型等待与工具处理时接收进度通知，保留 Runtime 的消息写入与任务推进职责。

第09篇：流式模型与完整消息接入两种服务的原生流式响应，让文字逐片可见；完整请求检查通过后才执行工具，提前结束不交付半条消息。

第10篇：主动取消一次运行让应用把停止请求传给模型与工具，保留先前结果、拒绝迟到返回，并在两个原有任务中接入 Ctrl+C。

第11篇：整次时限与运行预算给同一次运行设置累计期限与工具处理额度，区分到期、额度不足、主动取消和单次请求失败，保留此前已完成的结果。

第12篇：阶段联调，可观察地控制同一内核用双文件审查与共享依赖调查，检查累计机制在新材料上协作；把三个包放到仓库外使用，并区分停止、材料证据与结论正确性。

第13篇：让 Agent 调查有限工作区进入第三阶段。应用选择根目录，模型通过路径查找、内容搜索和全文读取取得证据；沿用同一 Runtime，为后续实际修改与验证反馈准备。

第14篇：修改代码，让真实验收反馈进入下一轮把只读调查接到独立副本的实际修改和限定命令验收。失败输出保存进入下一轮，原材料保留，候选供操作者审阅。

第15篇：用当前变更和匹配的验收证据交付以实际内容关联验收，展示基线差异，拒绝通过后再次修改却没有重验的交付。

第16篇：让 Agent 记录计划，并根据反馈修订进度增加可关闭的显式计划，用实际失败更新步骤，展示进度并比较开销；计划声明不替代当前变更与匹配验收。

第17篇：让 Coding CLI 使用同一个 Agent 内核建立独立终端应用，通过可信任务配置接入不同材料；复用原循环、代码工具和验收来源，展示实际变化并返回交付退出码。

第18篇：第三阶段实践验收：用现有 CLI 完成新任务以页面路径修复收拢第三阶段；保留同一个CLI和核心包，检查实际反馈、当前验收与真实迁移证据。

第19篇：完整运行记录与本轮模型输入进入第四阶段：每次模型调用前准备独立消息副本，默认保留全量，临时输入不改写执行记录。

第 20 篇：在有限输入中保留任务依据用同一修复任务比较全量与有限输入。

第 21 篇：把被省略的验收证据带回本轮输入区分历史验收与当前交付证据。

第 22 篇：从旧任务取回一条有用的线索按主题把外部笔记带进当前任务。

第 23 篇：在同一个任务里继续追问在同一副本上接续用户问题，对照全量输入和自动策略。

第 24 篇：把已验收的经验留给下一个任务从当前验收提取线索，下次任务从磁盘取回。

第 25 篇：让 Coding Agent 退出后仍能查到会话逐段保存会话记录。

第 26 篇：退出后继续追问上一场任务从会话日志重建输入。

第 27 篇：改完文件后，重启接着验收用检查点接续实际验收。

第 28 篇：验收中断后，先确认结果再决定是否重跑用完成回执处理重复提交。

第 29 篇：验收进程中断后，怎样核对现场观察进程中断与磁盘证据。

第 30 篇：在正式 CLI 里检查恢复证据用只读诊断收拢第五阶段。

第 31 篇：让 Coding Agent 在只读模式下调查代码在工具执行前落实操作者选择的权限。

第 32 篇：在修改和验收前逐次询问操作者在实际动作之前请求一次批准。

第 33 篇：让验收等待跨进程批准保存对一次具体验收的决定，另起进程继续。

第 34 篇：给 Coding Agent 接入双文件调查工具用发票任务验证可选工具、工作区约束和现有交付流程。

第 35 篇：用 MCP 接入进程外的发票规则接通真实 stdio 服务，沿用现有工具执行与交付验收。

第 36 篇：限制验收进程写文件和使用网络用同一份脚本对照 macOS 验收子进程的写入和网络能力。

第 37 篇：用结构化轨迹定位工具为什么没执行用同一任务对照预算耗尽与完成交付。

第 38 篇：离线诊断一份 Agent 运行轨迹读取旧轨迹并区分停止证据、截断和计数不一致。

第 39 篇：建立一组可重复运行的代码任务批量运行真实 CLI 任务，保存每项交付和运行证据。

第 40 篇：比较两次评估，定位哪项任务退化了按用例对齐报告，区分交付退化、改善和证据不足。

第 41 篇：把入口调查委派给一个只读子运行验证有限委派、权限和父子结果汇合。

第 42 篇：用同一任务对照直接调查与只读委派保留父子工作量，核对固定路径的实际交付。

第 43 篇：让多项只读调查限量并发，再按顺序汇合核对并发峰值、实际完成顺序与取消证据。

第 44 篇：让仓库外的应用安装并使用 Harness用本地打包产物验证公开入口以及两种宿主的代码交付。

第 45 篇：让 CLI 和独立宿主共用任务运行器通过同一接口运行、观察、取消与审阅。

第 46 篇：让桌面窗口运行和取消同一个代码任务用原生窗口验证共享运行器与进程间通信。

第 47 篇：在桌面选择任务，并接入已配置的模型由主进程校验任务与模型选择，验证真实验收。

第 48 篇：保存桌面运行历史，重开后审阅改动查看本地保存的进度、源码前后与验收。

第 49 篇：在桌面逐次批准修改和验收验证执行前人工批准与退出清理，完成八阶段主线。
