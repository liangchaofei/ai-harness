# 12 阶段联调：设计与实施计划

阶段二收尾，目标是迁移/接入/观察/控制协作，不靠继续新增Runtime模块证明进展。实际11分支跟踪远程且干净，源码已含11；没有11独立迁移/真实任务新证据，掌握未知。

能力契约：代码审查与发布调查均能注入新的任务材料而不修改model/runtime/coding-tools；同一runAgent串起两协议流式、schema已知失败反馈、观察异常隔离、取消/期限/额度，停止与证据检查分开；构建产物在仓库外消费。新增仅examples与fixtures候选，核心除清旧教材标签无语义变化。

范围选择：沿用两个领域，不引入第三个业务或通用评测平台。抽取两个应用的任务创建函数，返回共享ExampleTask（input与任务自己的report），原main仍采用原默认任务。工具工厂支持新材料但保留reviewTools与createReleaseTools()兼容；review报告支持单路径或路径列表。阶段入口消费相同任务工厂，避免复制循环或把新材料写进Runtime。

新材料：invoice.ts重复应用折扣，pricing.ts定义满10件10%折扣；100×10应900、当前810。release-57变更quote-api/checkout-api，两服务直接依赖pricing-core；要求负责人、直接依赖与共享依赖，不推断传播方向。任务验收只查成功材料证据，语义结论人工核对。

联调装置：examples/stage-check的固定消息计划与原生SSE响应生成置于配套折叠参考；normal/recover/cutoff/cancel/deadline/budget，加自愿live。recover先坏参数再预写纠正请求，且首条预览观察抛错；cutoff最终响应缺服务终止标记，已有工具事实保留、预览不交付。取消/期限在最终尾帧等待中触发；额度跨轮。固定行为不声称模型自主修正。live模式从原有配置接模型，作者不自动调用。

验证顺序：保护学习文件哈希，复制11候选清标签；创建材料与任务工厂、更新兼容工具/报告/两个入口；先运行静态材料组装；SSE装置与阶段入口；临时check、两任务×两协议×六模式、实际旧入口回归、作者新任务/失败语义、核心AST对比、包外三包消费、候选全文同源、Waza、网站和图渲染。提供可逆漏证据实验与新材料自主迁移，不安排单测教学。

有限策略：60秒/6模型/8工具沿用但不称为最优默认；本地模式使用有限短期限复现机制。阶段报告把内容提供、作者固定机制、真实服务质量、学习者独立解释/迁移分别登记，阶段三可继续但缺口不自动变成掌握。
