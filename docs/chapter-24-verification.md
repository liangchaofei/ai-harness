# 第 24 篇：方案与验证

实际起点为第 23 篇，增量候选放在 `site/snippets/24-memory-writeback`。任务配置通过可选的 `memory.captureCase` 明确启用写入。CLI 在交付接受后，从匹配当前副本的验收报告提取单个通过用例，按主题保存。报告层独立展示记忆写入状态。第 22 篇的读入口在下一次任务重新加载磁盘记录，历史线索和当前验收继续各自取证。

Pi 固定提交 `8efd314fa3d3232ce197d8d7a6a5660530b9d83e`：`AgentSession` 将实际消息交给 `SessionManager.appendMessage` 持久化，`appendCustomEntry` 创建有 ID、父条目和时间的独立会话条目。课程借鉴应用层保存记录的职责安排。本章的验收门槛、按主题更新和 JSON 笔记格式是课程设计。

在第 23 篇的临时副本覆盖候选，离线安装并通过 `npm run check`。观察脚本用人工报告验证新增、重复跳过和新证据更新。端到端固定模型通过真实工具修改及本地验收，两次调用各创建一个副本。第一次首轮无记忆，验收后 `saved`；第二次首轮命中，结束后 `unchanged`，笔记始终只有一条。另验证停用与验收不匹配都保留文件原样，停用后读取不命中。

并发写入同一笔记文件不在当前范围。验证未调用模型服务，也未测量模型使用线索后的效果。
