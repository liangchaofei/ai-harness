# 15学习卡

问题：通过后又改代码，旧检查为何仍能被当成通过？

链路：启动基线→模型动作→验收前采集→真实进程→验收后采集→私有lastCheck与反馈→停止后inspect重采集→原文差异+来源匹配→应用接受。

区分：Runtime answered / 检查status passed / stable / checkMatchesCurrent / accepted。匹配失败会拒绝；匹配成功但业务失败仍拒绝。返回对象不是保存，lastCheck赋值才写入内存；Runtime另保存反馈。

反例：通过A→加注释成B→回答：不接受；重新检查B→通过→接受。额外规则变化即使重验也拒绝。恢复A可匹配，采用内容而非最后操作。

范围：有限文本、受控串行；无原子快照/锁/OS隔离/恢复/自动回写。作者固定轨迹不证明模型自主任务能力。延迟复用见review-queue，不按章节或提交提升掌握。
