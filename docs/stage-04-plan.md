# 第四阶段：长任务的信息管理（计划）

目标：同一Runtime/Harness能明确区分真实历史与本轮可见输入，在长材料与多轮任务中选择、摘要和检索信息，保持可追溯依据，并通过同CLI比较质量与代价。不是为了压缩字节而默认丢证据。

19（正文/候选已提供）：完整记录与本轮输入分离；可选prepareMessages默认全量，临时输入不写回历史，准备失败单独归类。尚不选择或裁剪信息，实际学习源码仍以检查为准。
20（正文/候选已提供）：Agent 应用层自动判断本地 UTF-8 字节目标，保留任务与近期完整批次；同一固定任务对照与旧证据缺失反例。真实策略效果待验证。
21：带来源的任务摘要，保存目标/证据/失败/未完成，验证陈旧信息修订。
22：按需检索任务记忆，区分运行状态、外部材料、跨任务记录；不将持久记忆等同于可恢复执行。
23：同任务多轮CLI组合检验质量与相关输入/调用开销，独立迁移与延迟复用取证。

章节范围以完整能力为准；设计前读固定Pi对应实现与当前源码，具体API未冻结。源/策略/材料职责分开，策略可关闭，必要动作不能只靠固定脚本证明效果。无付费授权时只做机制验证，不编造真实质量/token/费用。

沿用现有monorepo，不推倒原包、不提前创建通用记忆平台。CLI持续用apps/coding-cli，后续会话保存/恢复在第五阶段、批准/权限/扩展在第六阶段。第八阶段收敛框架和桌面接入。学习者独立证据与内容提供分开。
