本页内容

阶段路线 ​

整门课程的目标是能够独立设计、实现、调试、扩展和评估 Agent 系统，逐步形成可独立使用的 TypeScript Runtime/Harness，并接入命令行与桌面 Coding Agent。

第一阶段建立基础闭环，后续阶段持续建设同一个系统。章节数量不作为掌握程度或工程成熟度的依据。

阶段要建立的能力阶段成果
一：基础原理与首个运行内核模型消息、工具请求、实际执行、结果反馈、循环与停止示例通过本地包入口完成任务，更换工具不改循环
二：可接入、可观察、可控制的内核模型接入、工具契约、失败分类、事件、流式输出、取消与预算不同任务复用内核，应用能观察和控制运行
三：实际代码任务与交付工作区调查、修改、执行验证、反馈调整与完成判断命令行 Coding Agent 提供实际修改及验证结果
四：长任务的信息管理上下文组装、信息选择、摘要、检索和记忆比较长任务中的质量与代价，追踪信息来源
五：可靠执行与恢复持久化、检查点、恢复、重试、副作用与资源清理可复现中断并有依据地继续运行
六：扩展、安全与人工介入工具扩展、MCP、Skill、权限、审批和隔离接入外部能力，执行前检查权限，暂停后可继续
七：评估、调试与任务编排追踪、回放、任务集、回归、委派及并发限制能定位失败、比较改动，并验证多 Agent 的适用性
八：框架收敛与桌面应用包接口、外部安装、进程通信、会话与凭据归属CLI 和桌面应用使用同一个框架

能力从早期开始交织 ​

运行验证从第一阶段出现，后续才形成系统评估；基础事件早期出现，后续才完善追踪。进入修改和执行之前先设置必要的工作范围，不等到安全专题才考虑边界。

采用 monorepo 与 workspace 分包，逐步分离模型接入、运行内核、Harness 组合层和 Coding 工具。应用、示例与任务材料独立；不在第一篇创建所有未来模块。

核心能力之后继续学习后端服务化、身份与租户、存储和队列、部署与运行观测，连接 AI 全栈工程需求。

怎样确定章节 ​

总路线约束能力覆盖，阶段大纲确定可运行成果，具体章节再细化实现。03在首次实际读取时建立coding-tools最小包；第三阶段继续扩展完整工作区、修改、验证与CLI。每篇写清新增行为、系统位置与验证依据；阶段末回到整个系统，用不同任务检查复用和缺口。

作者在设计前核对固定版本的 Pi 对应源码；正文提供必要的局部对照，不要求读者先阅读整个仓库。

第一阶段：逐篇大纲 ​

本阶段的成果是：应用通过公开包入口启动一次运行，模型提出工具动作，本地实际执行，结果进入下一轮，模型根据新信息继续或回答；换一个任务和工具时，不复制执行循环。

这是整个 Runtime/Harness 的基础闭环，不代表八个阶段的最终目标已完成。下面五篇是当前教学安排，不是强制篇数；如果具体实现的理解负担过大，先调整章节拆分，不删减阶段成果。

单元主要学习内容实现产物验证依据
01 从包入口发起模型调用模型消息与角色、上下文和token的基本含义；请求、响应、文本生成结束与任务完成的区别模型接入包＋代码审查示例，经公开构建入口调用解释两条消息和返回值的归属；正常、缺配置、截断与服务失败；修改任务输入
02 让模型提出工具请求工具名称、用途和参数说明如何进入模型输入；文本与工具请求的区别；请求ID和参数JSON模型包能够表达工具请求，应用提供工具说明从真实响应找到名称、ID和参数；未执行时没有实际结果；不假设服务只会返回一项请求
03 执行工具，把结果交回模型工具契约、名称分发、本地参数检查；实际执行结果怎样关联请求并写入消息；模型为什么能利用新结果Runtime执行器＋独立coding-tools只读工具；应用保存结果并再次调用模型对齐assistant请求、tool结果和ID；查看真实执行结果及下一次输入；错误参数不执行动作
04 让 Runtime 自动继续与停止将显式多次调用变成循环；消息状态归属；每轮的决定、结果更新、文本返回与请求上限Runtime循环与公开运行入口，应用注入模型调用，任务内容不进入循环实现观察不同任务的实际轮数；删除反馈后不能当作已知结果；达到上限明确退出，不伪造完成
05 换任务，检验同一个运行内核同一模型/Runtime接入新任务与工具；区分核心机制、工具能力、应用配置和材料第二个独立示例与阶段回顾通过公开包入口接入，不修改或复制循环；不把示例路径、任务名写进内核；解释迁移中的失败

目前01–05已提供正文与候选，第一阶段内容已覆盖两任务接入同一内核；独立迁移、真实任务质量和延迟复用仍需取证。已提供内容也不等于已经掌握。

本阶段怎样判断覆盖完整 ​

阶段末需要回到整条运行过程，检查以下关系，而不是只统计五篇是否写完：

  1. 输入与决策：能指出模型本轮实际收到哪些消息和工具说明，区分模型生成的文字与结构化动作请求。
  2. 动作与执行：能从请求ID追到本地执行的具体函数和结果，说明模型没有直接替程序运行函数。
  3. 反馈与状态：能指出哪条消息保存结果、谁持有消息记录，以及下一轮为何获得新信息；不混淆内存记录与持久化。
  4. 继续与停止：能解释循环为什么继续、为什么返回文本、为什么达到上限失败，以及服务停止不等于任务正确完成。
  5. 分层与复用：能在新任务中保留模型包和循环，只替换工具、任务和材料，并定位一次接入错误。

作者使用固定响应复现程序分支，学习者的实际模型轨迹用于观察动作选择；两种证据分开记录，不用预写的动作序列证明自主能力。真实服务调用由操作者自行执行和管理费用。

哪些能力还要在后续阶段学习 ​

第一阶段就要有参数检查、有限执行范围、基本失败退出和请求上限；不先放开任意命令，再等以后补约束。但这些基础不能代替第二阶段完整的失败分类、运行事件、流式输出、取消和预算管理。

长任务上下文、跨会话记忆、检查点恢复、系统级隔离、人工批准、完整评估和多Agent编排，仍按后续阶段建设。显式计划在实际任务需要时引入，不把维护计划列表规定为每次模型调用的前置。

第03篇同时包含执行与反馈，编写时重点检查是否能通过连续小步骤讲清。如果需要拆分，会同步这里的编号、前置和产物，后续章节顺延；不为了守住五篇而塞进难以跟做的大段代码，也不把一个辅助函数独立凑成一篇。

第二阶段：逐篇大纲 ​

本阶段让同一内核接入不同模型，提供可判断的工具与失败契约，让应用实时观察、接收增量，并能主动停止运行。最后把接入、观察和控制放在同一个任务上检验。

单元新增或检验的能力主要观察依据
06 模型适配：换服务，保留同一个 RuntimeDeepSeek / Anthropic 各自编解码与统一调用，应用选择接入同一工具与循环完成协议往返；无 Key 可用固定响应观察，真实服务另验
07 工具准入与可判断的失败工具 schema 与本地校验接线、注册检查、可反馈失败和停止异常坏数据不产生 I/O；失败能修正或明确停止
08 运行事件与实时进度动作发生时提供有顺序、有关联的运行事件应用能在等待、执行和停止时观察，不接管 Runtime 状态
09 流式模型与完整消息增量输出与完整结果协作文本分片可见；半截参数不执行；中断不会伪装为正常完成
10 主动取消一次运行应用、模型等待与工具执行协作退出取消后不再开始下一动作，迟到结果不推进循环
11 整次时限与运行预算区分单次 HTTP、整次期限和调用次数限制一次请求未超时而整次到期时，仍能有依据地停止
12 阶段联调：可观察地控制同一内核用新材料和组合故障检验累计机制及包外消费两任务复用、定位失败、解释停止与状态证据

06–12 已提供正文与候选；12使用新材料联调，并核对仓库外包消费。实现细节按理解负担调整，保留整阶段成果；不按辅助函数、日志和目录机械拆章。第一阶段的独立迁移与延迟复用继续取证，不因进入新阶段就认定已经掌握。

模型选择属于应用，协议属于 model，循环与运行状态属于 Runtime。本阶段不建设完整模型目录、自动跨服务降级或持久化恢复。没有第二家 Key 不阻塞学习：本地固定响应能检查协议机制，不能证明线上兼容和模型自主任务质量。

第三阶段：逐篇大纲 ​

本阶段从只读调查进入真实代码任务：在可重置、受限的工作区调查、修改、执行验证，根据反馈继续或交付。复用同一模型与Runtime，具体文件和接口在章节设计时确定；下面是能力安排，不是已实现功能。

单元要完成的能力主要验收依据
13 让 Agent 调查有限工作区根据任务查找、搜索和读取相关源码，建立实际修改前的证据换材料不再手工逐文件配置；调查结果足以支持下一步
14 修改代码，让真实验收反馈进入下一轮在临时副本改代码，执行预先限定的验收程序，用真实反馈继续调整实际差异、实际失败输出和后续修正；验收程序完整提供
15 用当前变更和匹配的验收证据交付让验证结果对应当前代码，拒绝修改后未经重验的交付可审阅差异及匹配版本的验证记录
16 让 Agent 记录计划，并根据反馈修订进度多步任务表达计划，按新证据更新，比较直接循环与计划策略同任务与约束下观察质量和代价；无证据不强设默认

写入和执行前就限制范围并保留清理；操作系统隔离、持久化恢复与复杂审批按后续阶段继续建设。材料与验收程序属于配套，学习主线是Agent如何取得证据、采取动作、使用反馈和判断交付。

第四阶段：长任务的信息管理（能力安排） ​

本阶段让 Agent 在任务增长时，有依据地决定本轮向模型提供什么信息。短期记忆（19–21）保留当前任务的历史和证据，由 Runtime 持有历史，应用负责组织输入。长期记忆（22、24）保存跨任务可复用的线索，由应用层负责读写。第 19 至 24 篇已提供正文与候选。

单元要建立的能力主要观察依据

20 在有限输入中保留任务依据观察输入规模，在长材料中选择信息并保留必要工具关系同材料比较策略开关，拒绝丢失关键反馈后仍声称已知

这里的记忆存储不等于进程检查点恢复。第五阶段继续研究崩溃后怎样恢复执行、副作用与清理；第四阶段先处理信息如何影响决策，不提前承诺可靠恢复。估算字节、token和真实服务使用量会明确区分，不用字符下降替代任务质量。

第五阶段：可靠执行与恢复 ​

第 25 篇：让 Coding Agent 退出后仍能查到会话在每段返回后保存消息和停止状态。后续再实现可继续执行的检查点、恢复和副作用处理。

第 26 篇：退出后继续追问上一场任务验证并读取已完成的会话，再追加一条只读追问。

第 27 篇：改完文件后，重启接着验收从受控交接点恢复一次真实验收。

第 28 篇：验收中断后，先确认结果再决定是否重跑区分待验收、结果不明和有完成证据。

第 29 篇：验收进程中断后，怎样核对现场观察进程中断与磁盘证据。

第 30 篇：在正式 CLI 里检查恢复证据用只读诊断收拢第五阶段。

第六阶段：扩展、安全与人工介入 ​

第 31 篇：让 Coding Agent 在只读模式下调查代码先实现本地工具权限，再进入具体动作的人工批准和外部工具接入。

第 32 篇：在修改和验收前逐次询问操作者完成进程内逐次确认。

第 33 篇：让验收等待跨进程批准将对一次具体验收的批准或拒绝保存在检查点旁，恢复前核对。

第 34 篇：给 Coding Agent 接入双文件调查工具用发票任务验证可选工具、工作区约束和现有交付流程。

第 35 篇：用 MCP 接入进程外的发票规则接通真实 stdio 服务，沿用现有工具执行与交付验收。

第 36 篇：限制验收进程写文件和使用网络用同一份脚本对照 macOS 验收子进程的写入和网络能力。

第七阶段：评估、调试与任务编排 ​

第 37 篇：用结构化轨迹定位工具为什么没执行用同一任务对照预算耗尽与完成交付。

第 38 篇：离线诊断一份 Agent 运行轨迹读取旧轨迹并区分停止证据、截断和计数不一致。

第 39 篇：建立一组可重复运行的代码任务批量运行真实 CLI 任务，保存每项交付和运行证据。

第 40 篇：比较两次评估，定位哪项任务退化了按用例对齐报告，区分交付退化、改善和证据不足。

第 41 篇：把入口调查委派给一个只读子运行验证有限委派、权限和父子结果汇合。

第 42 篇：用同一任务对照直接调查与只读委派保留父子工作量，核对固定路径的实际交付。

第 43 篇：让多项只读调查限量并发，再按顺序汇合核对并发峰值、实际完成顺序与取消证据。

第八阶段：框架收敛与桌面应用 ​

第 44 篇：让仓库外的应用安装并使用 Harness用本地打包产物验证公开入口以及两种宿主的代码交付。

第 45 篇：让 CLI 和独立宿主共用任务运行器通过同一接口运行、观察、取消与审阅。

第 46 篇：让桌面窗口运行和取消同一个代码任务用原生窗口验证共享运行器与进程间通信。

第 47 篇：在桌面选择任务，并接入已配置的模型由主进程校验任务与模型选择，验证真实验收。

第 48 篇：保存桌面运行历史，重开后审阅改动查看本地保存的进度、源码前后与验收。

第 49 篇：在桌面逐次批准修改和验收验证执行前人工批准与退出清理，完成八阶段主线。

CLI会持续演进 ​

17创建的是自己实现的单次任务CLI，后续保留apps/coding-cli：第四阶段接同任务的多轮输入和信息管理，第五阶段接会话保存与恢复，第六阶段接权限/批准及外部能力，之后接调试评估和桌面复用。不另起一套终端内核，也不要求从零重写输入排版库；核心机制先讲清，再接到应用。
