课程面向具备 TypeScript、Node.js 和一般应用开发经验的 Agent 初学者。

基础闭环只是起点。最终工程目标是可独立消费的框架包，以及通过公开接口使用它的命令行与桌面 Coding Agent。学习过程中会区分当前已实现的能力、实验策略与后续建设内容。

已提供[第01篇：从包入口发起一次模型调用](/guide/01-model-call)、[第02篇：让模型提出工具请求](/guide/02-tool-requests)和[第03篇：执行工具，把结果交回模型](/guide/03-tool-feedback)。[第04篇：让 Runtime 自动继续与停止](/guide/04-agent-loop)进一步建立带调用上限的自动循环，应用通过函数注入模型接入。[第05篇：换任务，检验同一个运行内核](/guide/05-runtime-reuse)接入第二个独立任务，收敛第一阶段内容。[第06篇：模型适配，换服务并保留同一个 Runtime](/guide/06-model-providers)进入第二阶段，提供无需第二家 Key 的本地协议观察；随后继续建设实时事件、流式输出和运行控制。

[第07篇：工具准入与可判断的失败](/guide/07-tool-contracts)把声明的参数规则接到实际执行之前，区分可反馈的工具失败与必须停止的异常，保留此前已经完成的结果。

[第08篇：运行事件与实时进度](/guide/08-runtime-events)让应用在模型等待与工具处理时接收进度通知，保留 Runtime 的消息写入与任务推进职责。

[第09篇：流式模型与完整消息](/guide/09-model-streaming)接入两种服务的原生流式响应，让文字逐片可见；完整请求检查通过后才执行工具，提前结束不交付半条消息。

[第10篇：主动取消一次运行](/guide/10-run-cancellation)让应用把停止请求传给模型与工具，保留先前结果、拒绝迟到返回，并在两个原有任务中接入 Ctrl+C。

[第11篇：整次时限与运行预算](/guide/11-run-budgets)给同一次运行设置累计期限与工具处理额度，区分到期、额度不足、主动取消和单次请求失败，保留此前已完成的结果。

[第12篇：阶段联调，可观察地控制同一内核](/guide/12-stage-integration)用双文件审查与共享依赖调查，检查累计机制在新材料上协作；把三个包放到仓库外使用，并区分停止、材料证据与结论正确性。

[第13篇：让 Agent 调查有限工作区](/guide/13-workspace-investigation)进入第三阶段。应用选择根目录，模型通过路径查找、内容搜索和全文读取取得证据；沿用同一 Runtime，为后续实际修改与验证反馈准备。

[第14篇：修改代码，让真实验收反馈进入下一轮](/guide/14-edit-check-feedback)把只读调查接到独立副本的实际修改和限定命令验收。失败输出保存进入下一轮，原材料保留，候选供操作者审阅。

[第15篇：用当前变更和匹配的验收证据交付](/guide/15-evidence-delivery)以实际内容关联验收，展示基线差异，拒绝通过后再次修改却没有重验的交付。

[第16篇：让 Agent 记录计划，并根据反馈修订进度](/guide/16-task-plan)增加可关闭的显式计划，用实际失败更新步骤，展示进度并比较开销；计划声明不替代当前变更与匹配验收。

[第17篇：让 Coding CLI 使用同一个 Agent 内核](/guide/17-coding-cli)建立独立终端应用，通过可信任务配置接入不同材料；复用原循环、代码工具和验收来源，展示实际变化并返回交付退出码。

[第18篇：第三阶段实践验收：用现有 CLI 完成新任务](/guide/18-stage-delivery)以页面路径修复收拢第三阶段；保留同一个CLI和核心包，检查实际反馈、当前验收与真实迁移证据。

[第19篇：完整运行记录与本轮模型输入](/guide/19-model-input)进入第四阶段：每次模型调用前准备独立消息副本，默认保留全量，临时输入不改写执行记录。

[第 20 篇：在有限输入中保留任务依据](/guide/20-input-budget)用同一修复任务比较全量与有限输入。

[第 21 篇：把被省略的验收证据带回本轮输入](/guide/21-evidence-summary)区分历史验收与当前交付证据。

[第 22 篇：从旧任务取回一条有用的线索](/guide/22-task-memory)按主题把外部笔记带进当前任务。
