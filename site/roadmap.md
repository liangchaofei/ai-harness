# 阶段路线

整门课程的目标是能够独立设计、实现、调试、扩展和评估 Agent 系统，逐步形成可独立使用的 TypeScript Runtime/Harness，并接入命令行与桌面 Coding Agent。

第一阶段建立基础闭环，后续阶段持续建设同一个系统。章节数量不作为掌握程度或工程成熟度的依据。

| 阶段 | 要建立的能力 | 阶段成果 |
|---|---|---|
| 一：基础原理与首个运行内核 | 模型消息、工具请求、实际执行、结果反馈、循环与停止 | 示例通过本地包入口完成任务，更换工具不改循环 |
| 二：可接入、可观察、可控制的内核 | 模型接入、工具契约、失败分类、事件、流式输出、取消与预算 | 不同任务复用内核，应用能观察和控制运行 |
| 三：实际代码任务与交付 | 工作区调查、修改、执行验证、反馈调整与完成判断 | 命令行 Coding Agent 提供实际修改及验证结果 |
| 四：长任务的信息管理 | 上下文组装、信息选择、摘要、检索和记忆 | 比较长任务中的质量与代价，追踪信息来源 |
| 五：可靠执行与恢复 | 持久化、检查点、恢复、重试、副作用与资源清理 | 可复现中断并有依据地继续运行 |
| 六：扩展、安全与人工介入 | 工具扩展、MCP、Skill、权限、审批和隔离 | 接入外部能力，执行前检查权限，暂停后可继续 |
| 七：评估、调试与任务编排 | 追踪、回放、任务集、回归、委派及并发限制 | 能定位失败、比较改动，并验证多 Agent 的适用性 |
| 八：框架收敛与桌面应用 | 包接口、外部安装、进程通信、会话与凭据归属 | CLI 和桌面应用使用同一个框架 |

## 能力从早期开始交织

运行验证从第一阶段出现，后续才形成系统评估；基础事件早期出现，后续才完善追踪。进入修改和执行之前先设置必要的工作范围，不等到安全专题才考虑边界。

采用 monorepo 与 workspace 分包，逐步分离模型接入、运行内核、Harness 组合层和 Coding 工具。应用、示例与任务材料独立；不在第一篇创建所有未来模块。

核心能力之后继续学习后端服务化、身份与租户、存储和队列、部署与运行观测，连接 AI 全栈工程需求。

## 怎样确定章节

总路线约束能力覆盖，阶段大纲确定可运行成果，具体章节再细化实现。03在首次实际读取时建立coding-tools最小包；第三阶段继续扩展完整工作区、修改、验证与CLI。每篇写清新增行为、系统位置与验证依据；阶段末回到整个系统，用不同任务检查复用和缺口。

作者在设计前核对固定版本的 Pi 对应源码；正文提供必要的局部对照，不要求读者先阅读整个仓库。


## 第一阶段：逐篇大纲

本阶段的成果是：应用通过公开包入口启动一次运行，模型提出工具动作，本地实际执行，结果进入下一轮，模型根据新信息继续或回答；换一个任务和工具时，不复制执行循环。

这是整个 Runtime/Harness 的基础闭环，不代表八个阶段的最终目标已完成。下面五篇是当前教学安排，不是强制篇数；如果具体实现的理解负担过大，先调整章节拆分，不删减阶段成果。

| 单元 | 主要学习内容 | 实现产物 | 验证依据 |
|---|---|---|---|
| [01 从包入口发起模型调用](/guide/01-model-call) | 模型消息与角色、上下文和token的基本含义；请求、响应、文本生成结束与任务完成的区别 | 模型接入包＋代码审查示例，经公开构建入口调用 | 解释两条消息和返回值的归属；正常、缺配置、截断与服务失败；修改任务输入 |
| [02 让模型提出工具请求](/guide/02-tool-requests) | 工具名称、用途和参数说明如何进入模型输入；文本与工具请求的区别；请求ID和参数JSON | 模型包能够表达工具请求，应用提供工具说明 | 从真实响应找到名称、ID和参数；未执行时没有实际结果；不假设服务只会返回一项请求 |
| [03 执行工具，把结果交回模型](/guide/03-tool-feedback) | 工具契约、名称分发、本地参数检查；实际执行结果怎样关联请求并写入消息；模型为什么能利用新结果 | Runtime执行器＋独立coding-tools只读工具；应用保存结果并再次调用模型 | 对齐assistant请求、tool结果和ID；查看真实执行结果及下一次输入；错误参数不执行动作 |
| [04 让 Runtime 自动继续与停止](/guide/04-agent-loop) | 将显式多次调用变成循环；消息状态归属；每轮的决定、结果更新、文本返回与请求上限 | Runtime循环与公开运行入口，应用注入模型调用，任务内容不进入循环实现 | 观察不同任务的实际轮数；删除反馈后不能当作已知结果；达到上限明确退出，不伪造完成 |
| 05 换任务检验内核 | 同一模型/Runtime接入新任务与工具；区分核心机制、工具能力、应用配置和材料 | 第二个独立示例与阶段回顾 | 通过公开包入口接入，不修改或复制循环；不把示例路径、任务名写进内核；解释迁移中的失败 |

目前01–04已提供正文与候选，05仍为大纲，接口将在实现前核对。已提供内容也不等于已经掌握。

### 本阶段怎样判断覆盖完整

阶段末需要回到整条运行过程，检查以下关系，而不是只统计五篇是否写完：

1. **输入与决策**：能指出模型本轮实际收到哪些消息和工具说明，区分模型生成的文字与结构化动作请求。
2. **动作与执行**：能从请求ID追到本地执行的具体函数和结果，说明模型没有直接替程序运行函数。
3. **反馈与状态**：能指出哪条消息保存结果、谁持有消息记录，以及下一轮为何获得新信息；不混淆内存记录与持久化。
4. **继续与停止**：能解释循环为什么继续、为什么返回文本、为什么达到上限失败，以及服务停止不等于任务正确完成。
5. **分层与复用**：能在新任务中保留模型包和循环，只替换工具、任务和材料，并定位一次接入错误。

作者使用固定响应复现程序分支，学习者的实际模型轨迹用于观察动作选择；两种证据分开记录，不用预写的动作序列证明自主能力。真实服务调用由操作者自行执行和管理费用。

### 哪些能力还要在后续阶段学习

第一阶段就要有参数检查、有限执行范围、基本失败退出和请求上限；不先放开任意命令，再等以后补约束。但这些基础不能代替第二阶段完整的失败分类、运行事件、流式输出、取消和预算管理。

长任务上下文、跨会话记忆、检查点恢复、系统级隔离、人工批准、完整评估和多Agent编排，仍按后续阶段建设。显式计划在实际任务需要时引入，不把维护计划列表规定为每次模型调用的前置。

第03篇同时包含执行与反馈，编写时重点检查是否能通过连续小步骤讲清。如果需要拆分，会同步这里的编号、前置和产物，后续章节顺延；不为了守住五篇而塞进难以跟做的大段代码，也不把一个辅助函数独立凑成一篇。

## 第二阶段：已确定的模型接入任务

在模型包中接入第二家模型服务，让应用可以选择不同接入，同时复用同一个 Runtime 循环和工具。学习内容包括请求与响应转换、凭据和模型配置、工具调用与停止原因，以及服务能力差异的处理。具体章节将在进入第二阶段前细化。

第一阶段04先让 Runtime 接收应用传入的模型调用函数，避免循环直接绑定 DeepSeek。第二阶段再通过第二家实际适配验证这个边界，不在当前阶段提前建设完整注册系统。

验收时，切换提供商不应修改 Runtime 核心或代码工具；需要检查文本、工具请求、结果反馈和失败路径，不能只把新增适配文件或替换请求地址当作完成。当前仍只支持 DeepSeek，这项能力尚待实现。
